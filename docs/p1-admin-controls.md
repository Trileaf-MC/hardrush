## 权限与操作入口

玩家 join、ready、status、history、leaderboard、book 入口继续按原规则工作。管理默认用原版 OP 级别，预览和确认时都检查权限。

| 权限 | 命令 | 范围 |
| --- | --- | --- |
| OP 2 | `/hardrush admin status`、`rules`、`audit <all\|current\|轮次> [页]` | 只读诊断、完整当轮／下轮规则、每页最多 20 条审计 |
| OP 2 | `/hardrush verify <轮次>` | 原有只读证据核对，不修订 |
| OP 3 | `/hardrush admin next-mode <normal\|hardcore> <原因>` | 改下轮模式，不改当前规则或清除故障 |
| OP 3 | `/hardrush admin start <原因>` | 提前开始已 READY 的普通 WAITING／COUNTDOWN，仅接纳在线就绪者 |
| OP 3 | `/hardrush admin abort <原因>` | 中止已 READY 的 WAITING／COUNTDOWN／RUNNING，立即停表并在提交后回大厅 |
| OP 3 | `/hardrush admin grant-revival <玩家名或UUID> <次数> <原因>` | 极限挑战／救场中为本轮参赛者累加复生次数，直接生效并标记本轮待核验 |
| OP 3 | `/hardrush admin retry-world <原因>` | OPEN 会话的 PREPARING 世界准备失败，只重试原轮／原种子 |
| OP 4 | `/hardrush admin correct <轮次> <耗时毫秒> <胜者UUID或none> <原因>` | 已通关历史的成绩投影修订，书版递增并转待核验 |
| OP 4 | `/hardrush admin validate <轮次> <原因>` | 依据原始可信首龙胜者核验，成功后可恢复正常榜资格 |
| 对应操作级别 | `/hardrush admin confirm <票据UUID>` | 在 120 秒内确认本人申请的具体操作 |

表内简写子命令都使用 `/hardrush admin` 前缀。轮次支持正整数序号或 UUID；审计另支持 `current` 查询尚未结算轮、`all` 查询全局。旧 `/hardrush config next-mode <模式> <原因>` 与 `/hardrush retry-world <原因>` 转入同一确认流程，不能绕过权限或审计。旧的无原因配置命令已替换，自动服务端命令夹具已同步升级。

世界仍由运行时自动分片准备；管理重试不能制造 READY。默认极限轮不会因管理员 start 绕过 P2：需把下轮设为普通，再在已就绪的等待轮中止、安全轮换。PREPARING 半完成世界保留原身份重试；当前不提供数据库／档案故障清除、录像保存跳过、归档或删除入口，这些在 P3 实现。

## 确认与提交边界

票据保存不可变的操作者标识、动作、具体 roundId、原因和影响。身份使用命令源实体 UUID 或控制台标识；昵称只作展示。每服最多 128 张，原因最长 512 个码点；拒绝控制／双向／格式字符及非法 Unicode。单调时钟计 120 秒，成功确认先消费票据，再提交；重启不恢复票据。另一操作者、降权、重复确认或过期票据不能写库。

当前轮票据绑定阶段、规则、终局与参与者 UUID／角色／在线／就绪／生命序号的语义指纹，普通计时检查点不会使其瞬间过期。历史票据绑定书版，事务再按 edition CAS；先确认同一版的一项后，其他旧版票据失效。实际运行写入继续使用当前 snapshot.version CAS，避免确认窗口覆盖新状态。

开始和中止仍走 RoundEngine proposal → 独立 SQLite worker → accept，管理快照与完整审计在同一事务提交，成功回执及玩家转换只在事务成功后发生。世界／档案未核验、未就绪玩家、状态写入繁忙及已捕获首龙终局都不能被管理命令绕过。

提前开赛先保存参与资格，档案适配器实际放行后才记在线时间。管理开始把本轮 timingUncertain 置为 true，不自动进入正常榜。中止受理时捕获单调时间并关闭新竞技行为，数据库等待不增加成绩；提交 ABORTED 后立即关容器／撤离受管玩家，直接进入 ROTATING，随后沿用档案、回放和世界真实关闭门槛才建下轮。中止保存原因、不发布通关庆祝，也不制造首龙证据。

世界重试先持久化 `RETRY_WORLD` 意图，再调用原 bundle 的 retry；回执表示重试已申请，实际完成仍以 READY 核验为准。适配器拒绝执行时保留意图和诊断；不能将它记成世界准备成功。Session FAILED 不经此入口恢复。

## schema 5 与历史版本

SQLite schema 5 新增 `admin_audits`、`history_originals`、`history_revisions`，历史投影增加 edition。升级 DDL、版本及原历史捕获同事务提交；旧记录保留原始摘要，不伪造首龙来源。所有成功管理写入保存 operationId、UTC 日期、操作者、动作、原因、前后值和具体轮次，快照／下轮规则／修订各自与审计原子提交。相同操作重复内容幂等，不同内容冲突拒绝；查询有界并核对摘要。

CORRECT 只改变历史投影，增加书版并撤下正常榜；原始 SETTLING 快照、首龙致死证据、活动轮次快照和已发书册均保留。胜者必须是该轮实际进入过人类生命的参与者；失败／中止不能经此玩家入口修成通关。新领书读取当前投影和 edition，自动待领按新书版去重；旧书物品继续保持发放时内容。

VALIDATE 保存显式核验原因，并根据原始首龙证据恢复归因信任及确定计时。原始可信胜者必须与当前修订胜者相符；改为其他 UUID、none、未知归因或无首龙证据旧记录均不能凭此成为正常榜。管理员可显式核验修正耗时，原始停止时间仍可追溯。每轮最多 1000 次追加修订，现版读取从原始记录重建并核对连续书版、审计拥有关系及前后摘要，缺失／篡改拒读。参与者、规则、种子和原始证据不随修订改写。

不合法管理请求拒绝并保持 Session 可写；数据库事务或审计失败则停止变更、保留脏标记。正常停止等待已受理管理写入，不依赖主线程回调完成排空；停止边界后拒绝新的连接事件。首次 adapterFailure 另捕获展示停表边界，故障后 TAB 的有效挑战时间不会持续增长。

## 2026-10-21：管理员发放复生次数

OP 3 或更高权限、服务端控制台可执行：

```text
/hardrush admin grant-revival Steve 3 测试补偿
```

执行后直接发放，不需要 `/hardrush admin confirm`；数据库提交成功后回执显示目标 UUID、发放次数和剩余次数。支持本轮参赛者名字（不区分大小写，重名时改用 UUID）或完整 UUID；在线／离线的人类和怪物均可领取，纯大厅访客不能领取。次数是正整数，累计最多 2147483647 次；仅限正常开放且世界／档案适配器就绪的极限挑战或未到期救场。发放不会立即改变身份，不延长救场，不恢复已经结算或恢复隔离的轮次。

管理员次数可以累加。怪物在大厅执行 `/hardrush revive` 或到祭坛确认，每次消耗一次并空装返回本轮主世界出生点；剩余次数跨人类死亡、怪物返厅／换角／出场、重连和正常停服重启保留，本轮通关／失败／中止时失效。原有击杀奖励仍只在余额为零时提供一次，不额外叠加。菜单、祭坛和行动栏显示剩余次数。

发放时读取并校验当前轮次、目标身份、生命和余额；提交中的并发请求会被拒绝，完成后再次执行会继续累加次数。快照和 `GRANT_REVIVAL` 审计在同一 SQLite 事务提交，审计包含目标 UUID 和前后余额，写入失败不会发放或报告成功。发放次数不计入已完成复生统计，本轮标记待核验，不自动进入正常榜。可通过 `/hardrush admin audit current` 查询记录。

快照格式升级为 v6，v1～v5 的布尔资格自动读取为 0／1 次。真实客户端操作及画面检查见 [人工测试清单](人工客户端测试/管理员发放复生次数.md)。
