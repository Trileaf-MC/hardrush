# HardRush 验收与开发顺序

需求评审完成后，按以下阶段实施。优先验证原版客户端、自身第三人称怪物外观、动态世界和依赖组合，避免完整玩法完成后才发现基础路线不满足要求。本文件定义通过标准；实际执行结果单独记录在 [P0 验证记录](p0-validation.md)，没有结果记录的项目仍未验收。

## 开发阶段与退出条件

| 阶段 | 范围与产出 | 通过条件 |
| --- | --- | --- |
| P0 技术原型 | 26.3 的最小 Fabric 服务端；三种怪物 self-view；动态三维度；依赖清单 | 两个原版客户端完整观察及操控变身；三维度与首次龙战斗可用；无必须客户端安装的依赖 |
| P0b 版本验证 | 将上述最小原型带到 26.1.2、26.2，选择回放与防作弊构建 | 三版本均明确可行或有具体服务器适配任务；正式功能开发前消除会推翻路线的问题 |
| P1 轮次与记录 | 世界准备、开局、计时、最后一击、正常重启、SQLite、TAB、基本历史书 | 同服连续 10 次轮换；成绩和离线玩家状态不串轮；关键事件可恢复 |
| P2 完整玩法 | 普通／极限、保护区、大厅、投票、安全出场、三种怪物、召唤、复生 | 击杀→资格→回大厅→复生闭环，全部死亡与救场竞态通过 |
| P3 故障与集成 | 崩溃、磁盘／数据库错误、归档、录像、防矿透、防作弊、后台管理 | 故障保留资料且不误发奖励；录像能打开；动态维度确实被保护 |
| P4 多版本发布 | 全回归、20 人负载、使用说明、配置、升级备份与许可证 | 三个独立构建完成同一关键验收，签署对应兼容记录后发布 |

P0 可以用命令触发变身、世界创建和临时交互，不必先制作完整大厅美术。P0 失败必须说明具体是哪项约束未满足；只允许修复或更换纯服务端路线，不将“自己的模型还是玩家”或“安装客户端模组即可”当作通过。

每项证据至少记录构建 commit（未建 Git 仓库时记录源码及制品 SHA-256）、MC／依赖版本、配置指纹、客户端版本、操作步骤、实际结果和日志；视觉、录像及碰撞项目附截图或短录像。自动化测试可覆盖状态机与故障注入，但不能替代真实原版 Minecraft 客户端验证。用户已明确授权本轮 P0 的隔离本地服务端和两个原版游戏客户端测试。

## 原版客户端与伪装

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| C01 | 对应版本的干净原版客户端加入 | 不安装客户端模组、不强制资源包即可完成全流程 |
| C02 | 两个客户端观察三种怪物，切 F5 前后视角 | 本人与对方都看到完整所选怪物；没有普通玩家叠影、缩小替身或隐形受伤实体 |
| C03 | 第一人称向下看、瞄准、攻击、使用技能 | 没有替身遮挡、错误选取、相机锁死或无法操作 |
| C04 | 行走、疾跑、蹲下、跳跃、台阶、门洞、游泳 | 视觉与已评审的移动／攻击尺寸一致；无穿墙、无频繁拉回 |
| C05 | 变身、死亡、复生、重连、跨维度各循环 20 次 | 不残留伪装、属性、队伍、权限、隐身或重复实体 |
| C06 | 击打替身不同部位与边缘，近战及远程 | 只命中一个权威目标，伤害不重复；模型、判定和距离限制符合锁定规格 |
| C07 | 开启防作弊与三类录制再重复 C02～C06 | 正常操作不触发持续误判；本人、旁人和区域录像无重复或消失身体 |

## 世界与轮次

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| W01 | 主世界／下界双向传送、末地进入和返回 | 始终属于同一轮，没有回大厅基础世界或上一轮的错误路由 |
| W02 | 新轮末影龙、死亡动画、出口门、再次召龙 | 首次龙正常存在；只结算一次；后续龙不覆盖成绩 |
| W03 | 不同维度的床、锚、末影珍珠、载具和重连 | 重生及跨维度遵守本轮身份和保护规则 |
| W04 | 等待、倒计时、挑战、救场、庆祝、轮换各正常停服 | 原阶段或可解释的恢复阶段继续，种子与轮次 ID 不变 |
| W05 | 世界生成慢于庆祝结束，或其中一维度失败 | 全体安全进入大厅，失败可重试，不能进入半成品世界 |
| W06 | 玩家离线跨过至少 3 轮再上线 | 旧物品、末影箱、坐标、效果和资格不带入新轮；旧记录仍可查 |
| W07 | 连续 10 轮并覆盖上述情况 | 无旧世界文件被误删、无持续增长的世界／区块／录制器引用 |
| W08 | 清理路径指向大厅、根存档、活动世界或目录外链接 | 拒绝操作并记录原因 |

## 计时与最后一击

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| T01 | 最后一名人类离线，仅怪物或大厅玩家在线 | 停表；离线人类资格不丢失、不团灭 |
| T02 | 人类上线、晚加入、复生及再次死亡 | 计时区间准确切换；排行榜仍用本轮时间，个人时长另记 |
| T03 | 人类仍在保护区、普通模式死亡画面 | 前者正常计时；后者不当活人计时，但不触发极限团灭 |
| T04 | 低 TPS、正常停服、系统墙钟变更 | 不用 tick/20 算成绩，不计停服时间，墙钟跳动不跳变比赛耗时 |
| T05 | 近战、弓箭、床、锚、TNT、水晶链对龙尾刀 | 实际因果归属正确；无法归因时待核验，不猜最近玩家 |
| T06 | 龙死亡动画、重复伤害回调、同 tick 多次命中 | 只保存一份终局，停在不可逆死亡事件而非动画结束 |
| T07 | 人类与龙在同一爆炸批次死亡 | 有效人类致死攻击仍可获胜，通关优先于团灭 |
| T08 | 模式／规则／版本不同、同耗时、管理员改成绩 | 正确分榜；同耗时同名次；修正有审计且旧书保持快照 |

## 怪物与复生

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| M01 | 同时大量玩家怪物、长时间外出、局部聚集 | 不触发人数、时长或局部数量限制 |
| M02 | 人类首次死亡、怪物被杀、主动回大厅、重连 | 30 秒出场冷却符合规则；5 秒引导可正确取消 |
| M03 | 怪物攻击每一类合法／非法目标 | 只有合法在赛人类受伤及受击退；龙、水晶、怪物、宠物、大厅及保护区均被阻止 |
| M04 | 骷髅普通箭与连射、盾牌和无敌帧 | 不叠加普通射击，不绕过原版防护；已发箭保留归属 |
| M05 | 普通苦力怕与玩家苦力怕在相同条件下爆炸 | 各难度、距离、遮挡、护甲、附魔和盾牌的伤害与原版参考一致；方块不破坏、不点火 |
| M06 | 自爆预警中被击败、自爆多杀且自身死亡 | 提前被杀不爆；多杀只一份资格；自爆死亡不抹去奖励 |
| M07 | 主人死、回大厅、离线、换角色或复生 | 已召唤实体不因这些操作移除；正常自然消失；主人复生后不被其攻击 |
| M08 | 召唤物主人在大厅／离线／已复生时击杀 | 前两者获一份资格，已复生者不获；没有延迟重复奖励 |
| M09 | 人类发箭后死亡，怪物发箭后复生，旧轮箭迟到 | 来源身份不被重写；不借身份变化刷复生、伤龙或跨轮伤害 |
| M10 | 无人类但有资格、无资格、还有离线人类 | 分别开启救场、团灭、等待离线人类，不能混淆 |
| M11 | 救场第 59 秒、截止瞬间、到期后消费资格 | 接收顺序确定；有效待提交复生不被提前团灭；过期请求拒绝 |
| M12 | 救场期间新玩家加入、持有者离线、再次全灭 | 新人成功加入可救场；离线不延长 60 秒；再次全灭可重新开窗口 |
| M13 | 连续获得资格、重复点击、背包满、复生后再死 | 资格不叠加不重复消费；空装安全复生；可再次通过击杀获资格 |

苦力怕对照必须使用同一 MC 版本、同一难度及配置、相同站位和防护条件的普通原版苦力怕作为基线；不能用网上伤害表代替实际回归。

## 保护与出场

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| S01 | 保护边缘的近战、箭、爆炸、流体、击退、珍珠、传送门 | 不可双向跨边界攻击或绕过重入规则 |
| S02 | 普通重生、极限复生、已离开者返回 | 前两者获得新生命的保护资格；其他重入被安全阻止 |
| S03 | 三维度投票，平票、无票、换维度、离线、目标死亡 | 每 UUID 一票，15 秒更新；出发再次验证，不信旧 GUI |
| S04 | 目标在洞穴、海面、悬崖、岩浆附近、末地孤岛 | 安全点遵守距离和地形规则；失败留大厅不扣资格、不贴脸兜底 |
| S05 | 连续点击出场、技能、GUI，伪造／拖动角色物品 | 只有一次权威操作，不越权、不重复召唤、不带走角色装备 |

## 数据与故障

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| D01 | 资格发放、消费、末影龙结算的每个持久化边界强制终止 | 重启后不重复奖励或消费；不确定状态留大厅恢复 |
| D02 | SQLite 不可写、磁盘不足、归档失败、录像失败 | 没有成功假象，没有静默删档；错误有具体恢复动作 |
| D03 | 领取书时背包满、退出、重启、跨多轮离线 | 待领状态可恢复，不覆盖物品，不一次塞入多轮书籍 |
| D04 | 重复进末地、重复获得进度、名字改变和恶意文本 | UUID 去重，排除配方；显示安全，不生成任意命令 |
| D05 | 超长参赛名单与大量历史轮次 | 成书按平台限制分卷；数据库完整；单次查询有界 |
| D06 | 从一致性备份恢复并升级数据库 schema | 轮次、身份、资格、成绩与文件清单一致；失败保留旧备份 |

## 集成与负载

必须证明每一轮的新维度在第一份区块包发送时已经应用 AntiXray；至少两轮不同维度 ID，检查重启前后和开采露出后的更新。Grim 使用锁定构建，覆盖正常速度变化、击退、传送、三种伪装、末影龙分部命中及网络延迟，记录误报和实际拦截范围。不能只凭日志“模组已加载”验收。

回放至少包括本人视角、旁人视角、区域录制三种证据；覆盖变身、跨维度、重连后片段、苦力怕爆炸、击龙及轮换保存。使用所选格式对应的查看器实际打开，验证录像不是空文件或不可读文件。

在记录的部署硬件上，建议 20 人测试分别运行 30 分钟，采集 TPS、MSPT p50／p95／p99、CPU、堆和 GC、磁盘空间、录像写入及网络流量。基线目标：正常战斗期间 MSPT p95 小于 50 毫秒、无持续积压；世界准备和轮换峰值单独记录。此目标需在选定硬件上达成，当前没有性能保证。

召唤物负载至少取 50、200、500 个活跃实体并说明测试中它们的区块分布、目标数及寻路状况。达到容量边界时报告可支持范围与瓶颈，优化计算及运维参数；不得借此新增用户明确取消的怪物数量、局部人数或出场时长限制。

## 首发交付清单

- 三个精确版本 JAR、校验值、对应服务端依赖和许可证。
- 中文安装、配置、普通／极限玩法、管理员命令、备份与恢复说明。
- 默认配置和校验规则；每轮规则指纹及保护／回放状态可查。
- 测试记录、已知限制、依赖兼容矩阵和故障恢复演练结果。
- 没有必须客户端安装的内容，没有外部常驻轮换程序，没有未说明的实验依赖。

任何硬性项目未通过，对应版本不能标记为正式支持；不能仅因另一个版本通过而复制验收结论。
