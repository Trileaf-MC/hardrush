## 管理入口

| 命令 | 权限 | 行为 |
| --- | --- | --- |
| `/hardrush admin status`、`audit current` | OP 2 | 查看状态、原始错误、轮次与恢复审计 |
| `/hardrush admin recheck-storage <原因>` | OP 3 | 对已有轮次的 FAILED 会话直接重新核验原数据库；成功仍保持恢复隔离 |
| `/hardrush admin close-recovery <原因>` | OP 4 | 直接结束当前 RECOVERY_REQUIRED 轮次；先保存决策，再经过原有安全释放门槛创建下轮 |

重新核验与结束原轮是两次独立操作。OP 3 无法执行 OP 4 的结束恢复轮次命令。每次命令按执行时的会话与轮次状态校验，数据库版本与完整性检查仍在事务路径中执行。

## 修复后的执行流程

1. 保留数据库、WAL／SHM、世界清单、档案 journal、世界和录像，先按完整错误修复容量、权限、只读挂载或写锁。不要在两个服务端进程中打开同一存档。
2. 已有轮次的 Session 为 FAILED 时，由 OP 3 执行 `recheck-storage <原因>`，直接开始重新核验。尚未打开任何轮次的启动失败不支持在线重核，需保留诊断并修复后重启。重核过程中比赛继续关闭。
3. 重核会等已受理 IO／回调排空，再在 IO worker 关闭并重新打开原 SQLite；核对 quick_check、外键、最新快照、原轮 ID／序号／种子／规则／版本、可信终局与历史修订，以及下轮规则。原数据库缺失、退回旧版本或最新轮次不同均拒绝，不创建空库替代。只有恢复快照与审计原子写入成功才报告核验成功。
4. 成功后为 `OPEN + RECOVERY_REQUIRED`：OPEN 仅表示可处理数据库请求；玩家仍在大厅，无法继续比赛、消费资格或重复应用原生效果。原生档案或世界故障仍需单独修复。
5. 决定结束原轮时，由 OP 4 执行 `close-recovery <原因>`，直接提交结束决策。没有已提交终局时记录 `ABORTED` 和原因，计时保持最近确定的持久量并标待核验；已有终局保留原胜者、停表时间和结果，不改成中止。已完成并冻结的可信首龙历史、原始证据、书版和正常榜资格不因终局之后的故障改变。
6. 结束决策进入 ROTATING，仍需全员回厅、档案封存、已安装回放可信保存和世界安全释放。结束决策本身不会立即创建新轮。原生档案或录像／世界核验失败继续停止，不能用重核数据库清除这些错误，也不能借此跳过录像。
7. 旧世界仍在当前进程时沿用原生保存／注销／关闭链。故障世界已由上一进程关闭时，只读核验原清单、身份与精确所有权路径，拒绝链接、路径逃逸和无清单的既存世界；不为结束故障轮重新生成或模拟旧世界。不删除、移动或归档旧文件。世界创建前崩溃且清单／三维度文件均不存在时，允许结束该空准备轮次。

写入失败时快照、历史索引与成功审计一起回滚，玩家继续隔离。核验中的正常停止会在关闭数据库前排空恢复事务；重启仍为恢复隔离。若已提交决策后再次脏退出，保留原结果并重新核对当前恢复轮，不重复消费或发放资格。

## 自动验证

```sh
scripts/p0-gradle.sh checkP3 :platforms:mc263:runGameTest -PhardrushP1=true --console=plain
scripts/p0-gradle.sh checkP3 :platforms:mc263:runGameTest -PhardrushP1=true -PhardrushP3Recovery=true --console=plain
python3 scripts/p1-server-restart.py --phase ROTATING
```

独立恢复 GameTest 使用新的随机隔离存档，不能与十轮／P2 身份／P2 大厅／容量故障专场合并。它在正式运行时注入真实 SQLite 事务失败，验证故障未修复时重核失败，修复后留在恢复隔离，随后结束原轮、关闭实际三维度并准备新轮；第二轮先真实关闭维度，再通过测试接缝移除已关闭 bundle，验证只读核验与轮换，始终不重新加载旧维度。全程无图形客户端、浏览器或 computer use。第二条不是整台服务端被强杀后的跨进程联合恢复证据。

本批新增10项 Session／SQLite 测试及3项关闭世界路径测试，覆盖资格／生命不重放、原始可信终局不变、审计中途失败原子回滚、延迟回调后的最新持久状态、数据库缺失／轮次变更／引用损坏拒绝、重核中停服及重复重开。另以原生 Brigadier 验证故障上下文变化、OP 降权、单次确认及分权。全部342项 JUnit 和101项常规必需无图形 GameTest（含5个未启用专场门禁）通过；独立恢复专场1项通过，正常ROTATING轮换的两个独立专用服务端JVM均正常退出／恢复，原终局、历史书ACK及仅一次下轮通过。结果、PID与指纹见E26清单。

初次独立恢复夹具在已有检查点尚未排空时直接替换测试引擎，产生 CAS 过期，未作为通过证据。夹具已改用正式 recheck-storage 事务进入隔离，排空后关闭世界，再验证只读核验路径；修正前后的日志分别保留在 E26。
