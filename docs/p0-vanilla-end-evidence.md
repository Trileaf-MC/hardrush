## 输入问题与已停止的自动尝试

Computer Use 最初的捕获错误在用户解锁后解除。键盘菜单、移动和右键拉弓可用，但鼠标拖动未改变原版视角。用户明确授权后，使用仅发往 HRProbeA 进程的 macOS CGEvent 鼠标事件；服务端读到相对移动使 yaw 从 `9.299561` 变为 `24.299652`，pitch 从 `9.7500215` 变为 `2.2500215`。这只发送输入，没有安装模组、附加 JVM 调试器或注入游戏逻辑。原生鼠标脚本保存在 [输入脚本](evidence/vanilla-end-20261013/input-mouse.swift)。

官方客户端使用 SDL 3.4.14。曾尝试 `SDL_MAC_USE_GCMOUSE=0`，没有改善输入；[SDL 官方文档](https://wiki.libsdl.org/SDL3/SDL_HINT_MAC_USE_GCMOUSE) 明确该开关从 3.6.0 才提供，因此不能宣称当前客户端已切换输入后端。

Computer Use 的多非修饰键组合会拒绝 `w+space`，并行发出的两个持续按键实际顺序完成。分步操作及观测间隔导致战斗操作不连续。后两次使用普通镐开路、普通弓射击及真实珍珠传送；第三次已到原生出口台附近，但被末影人击杀。没有完成床爆炸击龙。三次失败均保留；最后采用的低血量集成验证范围另行明确记录，不把这些失败记为通过。

用户选择接手击龙和返回，未授权扩展到原生键盘输入；代理已停止客户端操作。之后高频战斗、依赖手感或明显适合人工完成的测试直接交给用户，代理负责环境准备、验收步骤、日志和故障定位。
