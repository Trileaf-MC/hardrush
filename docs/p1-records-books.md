## 记录与冻结

SQLite schema 4 在同一迁移事务中新增历史、参赛者、进度观察、去重进度、统计集合及书册待领表。每次已提交的轮次快照同步更新参赛者索引；首次真正加入人类生命时保存 UUID、当时名字和加入时间，后续改名不会改写旧名。普通死亡、重生、人类在线参与时间及最终身份随已提交状态更新，单纯大厅登录不加入参赛名单。第一次终局事务冻结结果与参赛者统计，庆祝／离线／轮换检查点不能修改旧成绩和名单。

原版 `award` 成功且所有必需 criterion 已完成后才采集进度；部分 criterion、配方、无展示进度及根节点不计入。统计使用本轮 UUID 与进度 ID 联合唯一；集合按可展示 ID 排序后计算 SHA-256，数据包重载后保留新旧集合指纹，已获得 ID 不因移除／恢复／复生而倒扣。单轮最多保留 64 个统计集合指纹，超出时停止受影响写入并保留已有资料。记录详情展示指纹，集合改变不能被悄悄隐藏。

原版维度触发结束后观察本轮人类是否进入语义末地；每 UUID 只保存一次挑战时间偏移。同轮真实死亡替身和同 UUID 登录夹具不重复累计，跨轮 tracker 清空，数据库仍保存旧轮事实。隔离中、死亡画面、非人类、非本轮世界及结算冻结后的动作不产生新统计。进度恢复通过只读访问同步，不重新授予奖励。当前终局后的原版延迟进度不会补进已经冻结的统计。

统计写入使用现有独立 SQLite worker，与 FINISH 按受理顺序排队。先受理的进度即使回调尚未执行，也会先于终局事务保存。数据库失败立即停止比赛变更；worker 记录失败状态，正常停服屏障无需等待主线程回调即可拒绝 clean 标记。旧轮的异步回调核对 roundId 后才能改变当前 TAB 人数。

## 分榜与查询

榜单使用完整不可变 `RulesConfig` 指纹；模式、难度、Minecraft 版本、生成规则及战斗数值不同均不会混榜。按累计有效挑战毫秒排序，使用竞争排名，例如 `1、1、3`。失败、中止、无原始可信首龙证据、胜者待核验或计时不确定的记录完整保留，但不进入正常榜。活动轮次不经历史 API 公开种子。

读取核对快照和索引摘要；有原始终局时进一步核对致死证据与首龙关联，包括胜者待核验的原始终局。旧库迁移只回填已有数据，不伪造首龙因果、旧进度或首次末地时间。现代快照提交同时拒绝修改同轮种子、顺序号和规则。SQLite 连接显式使用 JDBC 驱动，避免 Fabric 类加载器下 SPI 初始化顺序导致的偶发“找不到驱动”。

| 玩家入口 | 行为 |
| --- | --- |
| `/hardrush history`、`/hardrush history page <页>` | 已结算历史，每页最多 20 轮 |
| `/hardrush history <序号或UUID>` | 原成绩、种子、规则、版本、集合指纹和异常说明 |
| `/hardrush leaderboard [完整规则指纹]` | 默认当轮规则榜，最多 10 条；同毫秒同名次 |
| `/hardrush participants <序号或UUID> [页]` | UUID、首次名字、人类时长、死亡／复生、进度、首次末地及最终身份，每页 20 人 |
| `/hardrush verify <序号或UUID>` | 管理员只读核验摘要与可信归因标记，不修正成绩 |
| `/hardrush book <序号或UUID> [卷]` | 手工领取历史成书，同 UUID 间隔 5 秒 |
| `/hardrush read-book [格号]` | 读取背包内已生成的历史书；格号 1～36，不指定则寻找已有书 |

单次数据库查询有界，平台异步查询并发最多 32；自动发书最多同时处理 4 人。成绩修正、开局／中止确认、完整管理分权与审计仍属于 P1-16。本批不能当作 T08 中管理员修正成绩的验收。

## TAB 与书册

TAB 只发送原版页头／页脚包，保留在线玩家列表。按实际单调时间每秒刷新，状态提交和末地人数变化立即刷新；相同文本不重复发送，新连接收到首包。显示轮次、模式、状态、暂停原因、累计有效时间、人类在线／离线、怪物人数、进入过末地人数、尾刀及开局／庆祝／救场剩余秒数；倒计时从纳秒向上取整，不提前显示零。极限怪物和救场完整运行仍待 P2。

下一轮档案转换完成后，在线大厅玩家自动获得最新上一轮主册；跨多轮离线也只补最新主册，不批量塞旧书。自动键为玩家 UUID、源轮、书版及卷号，已领不再次自动发放。背包满保留持久待领并提示，空出格位后重试，已有物品不覆盖、不丢弃。手工副本可重复领取，限速 5 秒，旧书仍是原快照；本批书版为 1，成绩修正及最新版流程待管理任务实现。

主册包含上一轮结果、当轮规则榜前 10、源轮参赛名单和受控查询入口。每卷最多 40 名参赛者，最多 80 页，每页最多 768 UTF-16 字符，按保守中文宽度换行；完整名单留在数据库，按需分页分卷。页内入口是固定命令文本，没有把玩家名解析成 JSON、选择器或点击命令。格式控制字符、双向控制字符及超长文本均受控处理。

实际物品为 `Items.WRITTEN_BOOK`，带受控来源／书版／卷号及发放 operationId。同库存重试识别相同操作，先重试保存再确认，不插入第二本。原版单玩家存档会吞 IO 异常，因此发放后回读最多 8 MiB 的 NBT，对比完整 Inventory 与轮次代数；核对成功才提交 SQLite 已领状态。此原版存档／回读是主线程不可抢占 IO 边界，不能宣称完全没有 tick 峰值。

档案就绪的大厅只放行生成历史书的读取和切换快捷栏，容器搬运、普通物品使用与竞技动作继续受隔离保护。`read-book` 为书不在快捷栏时提供入口：把书与当前手持物交换位置，同步后调用原版阅读界面，物品数量和身份保持。图形翻页、字体、客户端阅读及背包画面须由用户检查。书已发放但 SQLite ACK 尚未提交时的强制终止、物品转移及恶意伪造仍需 P3 故障回归；本批不宣称跨世界存档与数据库天然恰好一次。
