# 人工检查：管理命令与成绩修订

更新：2026-10-23。全部项目待用户手动复验。本页由用户在独立 Fabric / Minecraft 26.3 测试实例执行，记录真实聊天提示、TAB、容器、历史书和重连行为。开发自动回归不代表本页通过；本批未自行运行真实客户端、截图或 computer use。

## 准备与命令

保留日常服务器的数据，使用独立测试实例及 Java 25。首次全新数据库使用普通模式：

```bash
java -Dhardrush.competition.enabled=true -Dhardrush.round.initialMode=normal --enable-native-access=ALL-UNNAMED -jar fabric-server-launch.jar nogui
```

启动文件名按实例实际名称替换。已有数据库不会被 `initialMode` 改写。比赛模式默认关闭；不要删除日常库来制造可开赛条件。仓库开发启动脚本使用已有 `.local/server`，不会自动创建隔离实例。

预先准备普通玩家 A、B，以及非 OP、权限等级 2 的管理员、权限等级 3 的管理员、权限等级 4 的管理员测试身份。记录各 UUID、昵称、权限、JAR SHA-256、轮次 ID、规则指纹、服务端日志。以下尖括号是需要替换的参数，不是命令的一部分；原因使用清楚的测试说明。

| 权限 | 命令与用途 |
| --- | --- |
| 权限等级 2 的管理员| `/hardrush admin status`、`/hardrush admin rules`；`/hardrush admin audit <all\|current\|轮次> [页]` 只读诊断／规则／审计 |
| 权限等级 3 的管理员| `/hardrush admin start <原因>`、`abort <原因>`、`retry-world <原因>`、`next-mode <normal\|hardcore> <原因>`；输入后直接提交 |
| 权限等级 4 的管理员| `/hardrush admin correct <轮次序号或UUID> <耗时毫秒> <胜者UUID或none> <原因>`；`validate <轮次> <原因>`，直接提交历史修订或核验 |

表中省略前缀的子命令均放在 `/hardrush admin` 下。旧 `/hardrush config next-mode` 和 `/hardrush retry-world` 也直接执行并保留原因、权限与审计。普通玩家开赛前通过集结区准备／离开取消，挑战中通过中途门加入；history、leaderboard、book 继续按各自规则使用。

## 分权与直接执行

| 操作步骤 | 预期与记录 |
| --- | --- |
| 非 OP 尝试 `admin status`；权限等级 2 的管理员查看 status、rules、audit，随后尝试 start、abort、next-mode、correct、validate | 非 OP 不能使用管理入口；权限等级 2 的管理员可读诊断但不能控制或修订。失败操作不改变轮次、规则、历史或审计前后值 |
| 权限等级 3 的管理员执行 next-mode；权限等级 3 的管理员尝试 correct、validate、close-recovery | 下轮规则直接提交；权限等级 4 的管理员操作被权限拒绝 |
| 对每个下述命令只输入一次原命令，观察聊天回执和 `/hardrush admin audit` | 无确认哈希、票据、120 秒等待或再次执行 confirm 的提示；成功回执只在持久化后出现，审计保留操作者、原因、轮次及前后值 |
| 权限等级 4 的管理员查看命令补全，并尝试 `/hardrush admin confirm <任意UUID>` | confirm 不再注册，也不能执行任何旧票据 |
| 输入缺失原因、空白或非法文本的管理命令 | 继续拒绝，无状态变更或成功审计 |
| 在可复现写入延迟的独立夹具中并发执行管理命令 | 提交中请求被拒绝，不覆盖正在写入的状态。提交完成后重新输入命令属于新的管理操作，应按最新状态重新校验 |

## 开赛、规则与立即中止

| 操作步骤 | 预期与记录 |
| --- | --- |
| 世界 READY 后，A、B 留在集结区外，均未准备时执行 start | 无已就绪在线参与者时不允许开赛；管理员不能把未就绪玩家强行转为比赛人类 |
| A 站入集结区准备，在 COUNTDOWN 内由权限等级 3 的管理员执行 start | 可提前开始已就绪在线玩家；SQLite 接受及档案入场核验后才开放实际比赛。B 未准备仍在大厅；不因数据库等待增加人类参与时间 |
| 检查开赛后的 status／TAB，完成该轮后查看 history 和 leaderboard | 管理员提前开赛的轮次标记待核验，不自动混入正常榜；审计包含操作者、原因、前后阶段／计时／规则 |
| 在另一轮 RUNNING 中执行 `next-mode hardcore <原因>` | 回执在持久化后出现；本轮模式与规则指纹保持，只有下一轮使用新规则；比赛当前进度及个人物资保持 |
| A 在比赛中打开容器、骑乘载具，权限等级 3 的管理员执行 abort | 命令受理立即冻结新竞技伤害；成绩停在受理边界，持久化完成后全员关闭容器／退出载具并回长期大厅。没有“通关”或 600 秒庆祝提示 |
| 中止后尝试用旧菜单搬动物品、伤害旧世界实体；连续查看 status／TAB；等待下轮准备 | 不继续竞技、不重复中止、计时不增加；等待旧档案封存、回放门槛、旧三维度真关闭后才创建下轮。旧文件保留 |
| 查看 `/hardrush history <中止轮次>`、对应规则 leaderboard、`admin audit <中止轮次>` | 保存 ABORTED、原因及实际审计前后值；中止轮次不进入通关榜；不能由中止伪造合法首龙 |
| 默认极限 WAITING 轮先执行 `next-mode normal <原因>`，等待提交成功后再执行 abort | 只在世界已经 READY 且阶段可中止时受理；安全轮换后下一轮普通可通过集结区准备并正常开赛。start 继续检查当前轮次的开赛与档案门槛 |

当前中止仅开放已 READY 的 WAITING、COUNTDOWN、RUNNING，且没有未完成写入／排队事件／已捕获首龙终局。PREPARING 失败使用同轮世界重试；SETTLING、CELEBRATING、ROTATING 及 RECOVERY_REQUIRED 不由本入口改写。稳定复现“状态繁忙”需要独立提交延迟夹具时，标记夹具；普通客户端无法复现时写未测试。

旧 `/hardrush config next-mode <模式> <原因>` 别名应执行一次即提交下轮规则，无 confirm 提示；`/hardrush retry-world <原因>` 别名按下节相同条件验证。`grant-revival` 的直接执行回归见[专用清单](管理员发放复生次数.md)，存储恢复两条命令见[恢复清单](恢复决策与存储重试.md)。

## 同轮世界重试与故障保留

| 操作步骤 | 预期与记录 |
| --- | --- |
| 在独立测试实例出现 OPEN 会话 + PREPARING + 世界准备 FAILED，先记录 status、原轮 UUID、种子、清单、已创建目录及失败日志 | 未完成世界不能加入或开赛。失败清单与部分文件保留，不新建轮次或替换种子 |
| 管理员按该故障说明恢复测试实例的具体外部条件，再执行 `retry-world <原因>` | 先保存重试意图审计，再重新准备原轮次／原种子。命令回执不能冒充世界已 READY；仍需等待三维度及出生点核验 |
| 完成后核对清单和 status，再由 A 进入集结区准备 | 身份、种子及原规则保持；不会覆盖已经保存的建筑／物品，READY 后才允许正常入口 |
| 在正常准备中、已经 READY、Session FAILED、RECOVERY_REQUIRED 或世界 CLOSE_FAILED 时尝试 retry-world | 拒绝不适用目标；不会清除数据库／档案／回放故障或跳过关闭门槛 |
| 正常 stop 后重启失败实例，核对日志及保留文件 | 正常停服／重启按真实保存结果核验；失败不能被伪装成 clean 或可信完整成绩。需要人工恢复的原始文件仍在 |

人工只在明确可恢复的独立测试夹具中制造故障。没有此条件时填写“自动夹具覆盖，人工未测”，不编辑日常 SQLite、不移除生产所有权清单、不强行杀进程。录像保存失败重试／管理员跳过与旧世界归档／删除属于后续故障恢复范围。

## 成绩修订、核验与旧书

先准备一轮有真实首龙因果且已经通关的历史记录。保存其原 UUID、胜者 UUID、耗时、规则指纹、书版、history／leaderboard 输出，并由 A 领取主册，放入专门格位作为旧书。

| 操作步骤 | 预期与记录 |
| --- | --- |
| 权限等级 4 的管理员执行 `correct <历史轮次> <修订耗时毫秒> <原胜者UUID> <原因>`，随后查 history、leaderboard、audit，并打开原主册 | 历史修订和审计一起持久化、书版递增；CORRECT 先转待核验，从正常榜排除。原终局／因果不改写；原主册内容与书版仍保持领取时快照 |
| 等待手工领书冷却后执行 `/hardrush book <历史轮次>` 和 `/hardrush read-book <格位>` | 新领主册反映当前版修订内容；旧书继续可读，不被原地改写，不覆盖背包物品 |
| 对保持原合法胜者的通关修订执行 `validate <历史轮次> <核验原因>` | 仅当原始首龙证据可信、胜者与原合法来源相符且原记录为通关，才可核验进入对应规则正常榜；保存核验原因及前后资格，按毫秒排序 |
| 对同一历史轮次执行一次修订，等待完成后再执行另一修订 | 每次独立读取当前书版并递增，保留两笔真实审计；异步并发碰到旧版 CAS 时拒绝覆盖 |
| 另行执行把胜者设为 `none` 或另一 UUID 的修订，再尝试 validate | 修订展示为保留／待核验；不能凭管理员指定变成可信原首龙来源，不能混入正常榜。非法／未参赛 UUID 被拒绝时如实记录 |
| 对中止记录或缺首龙证据的旧记录尝试 validate | 不能虚构通关或合法尾刀；原记录、文件及审计保留 |
| 在活动轮中修订某个旧历史，再正常完成活动轮 | 只改变目标历史投影，不改活动轮规则、胜者候选、人类时长、世界或轮次身份；活动轮结算不覆盖旧轮修订 |
| 正常 stop / restart，重新查目标历史、audit，重读两版书 | 修订、书版及审计仍在；旧书保留快照，重新领书得到最新版，重启不重复应用已提交操作 |

若当前实例没有可信首龙通关，保留对应步骤未测试；低血量首龙夹具、完整生存通关及无证据旧记录分别记录。成绩核验不替代实际因果，不用 `/kill` 或开发工具制造可信比赛成绩。

## 正常停止与连续十轮

分别在 WAITING、COUNTDOWN、RUNNING、CELEBRATING、ROTATING 时正常输入 `stop`，等待保存完成后用相同制品重启；PREPARING 另测正常准备中及上述失败夹具。每次记录轮次身份、有效挑战时间、阶段剩余量、规则、玩家档案、当前／待领书版。预期保持原轮、剩余量和已提交结果，停服时间不计比赛或倒计时；重启不重放已提交管理操作。状态未达目标或保存失败时不勾选正常恢复通过。

同服十轮仍需要独立整链验收：每轮记录开局、普通首龙、历史书、两人重连、旧三维度释放和新身份；让 A 离线跨至少三轮后回来，核对新轮空装／进度隔离、旧书补领及旧档案保存。使用管理员提前开赛、短庆祝、低血量或假时钟时逐项标记，不能累计为默认规则真实客户端十轮通过。
