# 崩溃隔离与存储故障人工检查

日期：2026-10-15。此页保留早期隔离版本的历史检查，命令和恢复行为可能已变化；当前操作以恢复决策清单为准。使用独立测试实例与可丢弃的完整存档副本，记录本批源码／JAR SHA-256、规则指纹和原版客户端版本。历史实现记录及自动证据未保存在当前仓库。

本页保留第一批隔离检查。第二批新增存储重核与结束恢复轮次入口，最新构建还需执行 [恢复决策与存储重试人工检查](恢复决策与存储重试.md)。

本批恢复会停在大厅隔离，尚不能解除 RECOVERY_REQUIRED 或从强杀的活动轮继续比赛。以下仅验已实现的隔离、提示和准备重试，不视为故障恢复的完整验收。需要查看画面或真实输入的项目交由用户执行，开发代理不自行启动客户端。

- [ ] 两名原版玩家在隔离实例进入正式极限模式，分别在资格授予后、点击消费后、首龙通关后强制结束测试服务端，再以原存档重启。检查同 UUID 登录后均在大厅且不能移动出隔离、攻击、打开比赛物品交互或加入新轮；管理员状态明确显示 RECOVERY_REQUIRED，无虚假“恢复成功”。不要在日常存档执行。
- [ ] 核对强杀前后可确定的角色、资格、生命序号、死亡／复生统计与原始通关记录，无重发奖励、重复消费或同一轮重复通关。未知计时时段不补算；已提交可信终局保留原始证据。无法判断的状态继续隔离并保留日志。
- [ ] 正常跨轮重置后立即退出或重启，重连检查进度、配方、背包和末影箱没有被第二次清空，仍在档案核验完成后才可加入。人工无法精确停在 journal 边界时记录为未覆盖，不凭画面猜测持久化阶段。
- [ ] 用 `-Dhardrush.storage.minimumFreeBytes=9223372036854775807` 启动单独测试实例，检查世界准备失败时玩家留大厅，状态包含实际可用空间与最低储备，无下一轮成功提示。恢复正常配置后，按权限等级 3 的管理员的 retry-world／confirm 流程核对同轮 ID、种子和已有建筑保留。此操作模拟储备不足，不填满磁盘；配置需重启才能改变。
- [ ] 在只有世界准备故障的实例中，用低权限账号尝试 retry-world 和他人的确认票据，应拒绝；权限等级 3 的管理员查看具体轮次、原因、影响后确认成功，审计能查到操作者与原因。数据库故障时不能报告重试成功。
- [ ] 若在专门的容量受限／只读测试卷执行真实存储故障，观察失败后无继续开局、物品或奖励重复、静默删档；修复存储后不会自行解除比赛隔离。保存原始文件、完整日志和操作时间。该环境尚无自动准备脚本，未具备时保持未测试。

每项记录步骤、预期、实际结果及截图或录像。整服联合强杀、恢复决策、数据库重试、回放／防护组合与备份恢复仍需后续实现后追加；故障恢复整体验收 保持未完成。
