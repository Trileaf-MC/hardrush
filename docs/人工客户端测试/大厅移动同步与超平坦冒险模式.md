# 大厅移动同步与超平坦冒险模式

本清单交由人类使用两名 Minecraft 26.3 原版客户端执行。自动回归使用无图形服务端和模拟网络连接，不代表客户端画面或真实网络验收。

## 准备

使用启用了 `-Dhardrush.competition.enabled=true` 的隔离实例和本次构建的 `platforms/mc263/build/libs/hardrush-0.1.0-alpha+mc26.3.jar`。更换制品后正常重启；`/hardrush status` 应显示“大厅准备：已完成”。两名玩家 A、B 使用不同 UUID，先不要报名。

大厅固定使用持久维度 `hardrush:lobby`。原主世界、原比赛世界和档案应保留，不需要删除世界或修改 `server.properties` 的世界类型。

## 大厅双人同步

- [ ] A、B 均出现在同一片超平坦草地，能互相看到；F3 的维度为 `hardrush:lobby`。
- [ ] 两人交替行走、转向、跳跃、疾跑、潜行。旁人看到连续的位置和姿态变化，没有站在原地、回弹或隐身；走离出生点后仍可活动。
- [ ] 两人均为冒险模式，不能飞行、破坏或放置方块；尝试后没有长期残留的客户端假方块。彼此攻击不会造成伤害或击退。
- [ ] `/hardrush menu` 可打开、点击、关闭；已领取的历史书可正常阅读。菜单图标、书籍和物资不会因活动而复制或掉落。
- [ ] A 报名并就绪，B 留在大厅。倒计时期间两人仍可互相看到移动。取消就绪后行为相同。
- [ ] A 退出重进，核验完成后恢复大厅活动。B 看到 A 重新出现并移动，不残留旧玩家实体。

## 比赛与返厅

- [ ] 两人正式入场后均恢复生存模式，可正常进行生存活动；新轮空档案、同轮重连物资和进度遵循原有规则。
- [ ] 极限模式中一人死亡，完成怪物大厅核验后以冒险模式待命，可移动和操作角色菜单。安全出场后恢复生存模式及正确怪物身体。
- [ ] 怪物主动返回、败退或死亡返厅后仍可活动；不会携带角色技能物品或重复恢复死亡物资。
- [ ] 轮次结束、管理员正常中止或轮换时，全员返回同一个超平坦大厅。走离出生点后不会被每次检查拉回；新轮档案核验期间的短暂隔离结束后可继续活动。

## 重启与隔离

- [ ] 正常停服并使用原存档重启，两名玩家重新进入相同的 `hardrush:lobby` 超平坦大厅；原主世界、比赛建筑和档案仍保留。
- [ ] 刚登录且档案尚未核验时，尝试移动会被纠正到服务端位置；核验完成后才可活动，不能提前参赛。
- [ ] 在独立故障测试实例执行已有的 存储故障／恢复流程。FAILED、RECHECKING 和 RECOVERY_REQUIRED 期间玩家不能移动出隔离、操作比赛物资或参赛；仅重核存储成功不会解除隔离。
- [ ] 管理员完成恢复轮处置并创建健康新轮后，核验完成的玩家重新获得大厅活动能力。

## 无图形自动回归入口

双连接数据包与故障恢复整链：

```sh
./gradlew :platforms:mc263:runGameTest -PhardrushCompetition=true -PhardrushLobbyMovement=true --console=plain
```

该入口使用 `.local/lobby-movement/<UUID>` 下的独立存储。大厅地形与冒险模式的独立 JVM 重启验证：

```sh
python3 scripts/server-restart.py --phase WAITING --phase COUNTDOWN
```

两种入口均不启动真实客户端，也不替代上面的双人观察验收。
