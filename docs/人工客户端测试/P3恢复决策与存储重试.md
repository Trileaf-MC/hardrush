# P3 恢复决策与存储重试人工检查

更新：2026-10-23。状态：待用户手动测试。使用独立可丢弃测试实例和完整存档副本，记录源码／JAR SHA-256、规则指纹、原版客户端版本与具体轮次。[实现及运维流程](../recovery-controls.md)，[自动证据](../evidence/recovery-controls-20261015/manifest.json)。本清单不在日常存档注入故障。

- [ ] 两名原版玩家在活动轮中强制终止独立测试服务端，再以原存档重启。观察同 UUID 均留在大厅，无法移动出隔离、攻击、打开比赛容器、消费资格或触发技能，OP 2 状态显示具体恢复轮次。普通玩家无法执行管理恢复命令。
- [ ] 在有 FAILED 会话的测试实例中修复已知存储问题，由 OP 3 执行 `/hardrush admin recheck-storage <原因>`。命令直接开始核验，无确认票据或 confirm 提示；仅在事务提交成功后显示数据库核验成功，仍为 RECOVERY_REQUIRED，两名玩家继续隔离。未修复故障时不得显示成功。
- [ ] OP 2 不能执行 OP 3 的重核命令；OP 3 不能执行 OP 4 的结束恢复轮次命令。缺少原因或状态不适用时拒绝，审计没有未实际提交的成功操作。confirm 不再注册。
- [ ] OP 4 执行 `/hardrush admin close-recovery <原因>`，无需确认即提交结束决策；提交前不切换轮次，成功后先回厅并等待安全释放再进入新轮。检查原终局保留、未结算轮待核验中止、旧文件保留及释放门槛。重复执行时按最新状态拒绝，不生成重复轮次或审计。
- [ ] 分别在资格已发放、资格已消费、已有可信首龙终局的状态执行恢复处置。检查前两种没有补发资格／物品或再次增加生命序号，未结算轮只形成一条中止历史；可信终局的胜者、耗时、原始记录与历史书版本保持原值，不能被改成新的中止成绩。
- [ ] 结束恢复轮后重连，新轮档案隔离完成后才可加入；背包、末影箱、效果、进度和身份按既定跨轮规则处理。磁盘上旧清单、世界与档案资料仍保留，不能因为出现新轮就认为旧世界已归档或删除。
- [ ] 在世界／档案或已安装回放仍有故障时执行结束命令，检查玩家继续留厅，状态说明释放故障，没有新轮成功提示。重核数据库不应清除这些独立错误。需要修复的文件保留，不能手改 cleanShutdown 或直接删库放行。
- [ ] 在重核提交期间正常停服，重启后仍保持恢复隔离；在结束决策已经提交后再次强制退出，原终局／中止结果不被替换，核对审计后重新处置也不重复资格、历史或开两轮。
