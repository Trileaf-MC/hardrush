# 人工检查：连续十轮与正常恢复

日期：2026-10-15。**尚未执行，等待用户手动测试。** 本页覆盖 Minecraft 26.3 普通模式的同服真实客户端整链，以及正常 `stop` 后的新进程恢复。原开发计划和验收资料未保存在当前仓库。

本轮开发仅运行自动规则、SQLite 与无图形服务端夹具。即使夹具使用真实三维度、真实档案和原生首龙，也不能替代原版客户端画面、真实输入、满血生存游玩或本页十轮验收。本页不表示其他开发工具、依赖核查或比赛验收已通过。需要截图、交互和游玩判断的步骤全部由人类执行。

## 独立实例与操作入口

保留日常服务器数据，使用独立 Fabric / Minecraft 26.3 实例、Java 25、对应 Fabric API 和本轮 HardRush JAR。从该实例目录启动，首次全新比赛数据库明确使用普通模式：

```bash
java -Dhardrush.competition.enabled=true -Dhardrush.round.initialMode=normal --enable-native-access=ALL-UNNAMED -jar fabric-server-launch.jar nogui
```

`fabric-server-launch.jar` 是示例文件名，按实例实际启动文件替换。比赛模式默认关闭；已有数据库的当轮／下轮模式按已保存规则恢复，`initialMode` 不改写已有极限轮。仓库 `./gradlew :platforms:mc263:runServer -PhardrushCompetition=true -PhardrushInitialMode=normal --console=plain` 固定使用已有 `.local/server`，不会创建隔离实例。

准备两个干净原版客户端 A、B，记录 UUID、昵称和客户端版本；不安装测试模组或资源包。另准备管理员身份，记录 OP 级别。十轮期间保持同一实例目录、同一数据库／存档和同一制品，不用删除数据库、还原快照或复制新实例接续轮数；正常停止后重启仍属于同一实例，须保留停服记录。

| 入口 | 用途 |
| --- | --- |
| `/hardrush status` | 当轮身份、阶段、模式、计时／暂停原因和世界准备状态 |
| `/hardrush join`、`/hardrush ready`、`/hardrush unready` | 持久化加入／就绪，默认 30 秒自动开局；成功回执后才视为加入／就绪完成 |
| `/hardrush history <轮次>`、`/hardrush participants <轮次>` | 已结算轮次详情、实际参赛名单和个人统计；轮次支持序号或 UUID |
| `/hardrush leaderboard [完整规则指纹]` | 当前规则榜，或指定规则的历史榜 |
| `/hardrush book <轮次> [卷]`、`/hardrush read-book [格号]` | 手工补领／阅读历史成书；格号为 1～36，手工补领间隔至少 5 秒 |
| 权限等级 2 的管理员：`/hardrush admin status`、`/hardrush admin rules`、`/hardrush admin audit <all\|current\|轮次> [页]` | 只读管理诊断、完整规则和审计 |
| 服务端控制台 `stop` | 正常停止，等待实际保存、工作线程排空和进程退出后再启动 |

尖括号参数需要替换，不能原样输入。若独立测试库已处于极限 WAITING，管理员按现有 [管理操作流程](管理命令与成绩修订.md) 先执行 `/hardrush admin next-mode normal <原因>`，等待提交成功；当前世界 READY 且状态允许时，再执行 `/hardrush admin abort <原因>`，安全轮换到下一普通轮。两条命令均直接执行，无需 confirm；保存原因、回执和审计；这一中止轮不计入下面的十轮通关。PREPARING 使用原轮世界重试，其他故障不能由中止或重试绕过。

十轮主线采用默认自动开局和 90 秒现实时间庆祝。管理员提前开赛、改短规则、假时钟、低血量首龙、固定站位或物品准备均须逐项标为夹具，不累计成默认规则真实生存通过次数。管理操作的成功预览也不能当作世界已 READY 或操作已完成。

## 每轮执行的整链

先建立连续十轮记录表。开始第 1 轮前保留 status／规则输出和实例日志；十轮指十个完整通关及其十次实际轮换，**需要继续观察第 10 轮释放后第 11 轮 READY／WAITING**，才能验证第 10 次轮换和第 10 轮主册发放。

| 步骤 | 预期与记录 |
| --- | --- |
| 1. 世界准备中登录，尝试 join；准备完成后参加者 join／ready，实际等待默认 30 秒 | 准备／档案核验未完成时留大厅并拒绝入场；就绪持久化后才倒计时，开局后空装进入本轮安全出生点。记录 roundId、序号、种子／规则指纹和三维度键 |
| 2. A、B 分别沿安全出口离开；至少一轮由 B 晚加入，至少一轮取消最后就绪后重新 ready | 出口可通行；晚加入不重置全轮时间，个人时长另计；最后就绪取消／下线时原倒计时取消，再次就绪才开启新的倒计时 |
| 3. 在出生区外取得本轮可辨物品、经验与可展示进度；走原版下界门往返及末地门 | 世界与路由属于同一 roundId，不进入大厅、开发工具世界或上一轮；保留箱子／普通建筑。原版累计统计保留，本轮进度与首次末地人数按 UUID 去重 |
| 4. 每轮让在线参加者至少一次同轮下线／重连；至少一轮 A、B 同时离线一段实际时间 | 同轮恢复原维度、位置／朝向、背包、末影箱、经验、效果、床／锚和进度；所有活人离线时停表、不团灭，档案核验后恢复有效计时。离线跨轮的 A 不要求在缺席轮重连 |
| 5. 至少一轮普通死亡，在死亡画面停留后重生；分别使用有效和失效床／锚场景 | 没有其他活人在线时死亡画面不计活人时间，但普通模式不触发极限团灭；有效床／锚优先，失效回本轮出生点。死亡产生的正常掉落按原版处理，末影箱／本轮进度保持 |
| 6. 普通生存完成本轮原生首龙，记录最后一击玩家、龙 UUID、致死观察时刻及视频 | 真实人类致死来源获胜；只公布一次，成绩停在不可逆死亡捕获点。未知来源须保留“胜者待核验”，不能猜最近玩家或用管理员修订补出可信尾刀 |
| 7. 核对 TAB、history、participants、leaderboard；观察原生死亡动画和出口门 | TAB 保留在线名单，显示本轮模式／状态、停止成绩、去重末地人数、尾刀者及轮换倒计时；历史和规则榜与本轮一致。返回流程按本轮允许的庆祝交互记录，后续龙或重复伤害不创建第二成绩 |
| 8. 实际等待默认 90 秒现实时间；至少一轮庆祝期间有非胜者重连 | 成绩冻结；庆祝期间的原版战斗、死亡和物品转移不计入任何统计。重连者以空手身体回到龙池旁，庆祝不会因重连从 90 秒重算；离线本身不暂停服务器庆祝 |
| 9. 庆祝到期观察回大厅、退容器／载具、档案封存、旧三维度关闭及下轮准备 | 先完成旧档案与回放门槛、旧世界实际释放，再产生下一轮；准备未完成留大厅。未安装录制器须记录 disabled，不声称已保存录像 |
| 10. 下一轮核对身份／三维度键、空装／进度隔离、自动主册和旧历史 | roundId 更新、序号递增、新种子及当轮规则正确；旧物资、坐标、效果、经验、出生绑定和进度不带入。历史书是允许的新发物品，不是旧战斗背包泄漏；旧成绩与原世界文件保留 |

至少在两轮核对各方攻击与真实尾刀；箭／床／锚／TNT／水晶链和同批死亡的全部因果边界继续按 [终局人工清单](终局与自动轮换.md) 分别记录，不用一次近战尾刀替代 T05／T07 全覆盖。满血生存首龙与低血量首龙分开记录，不使用 `/kill` 或开发工具制造比赛成绩。

## 同轮保留与离线跨三轮隔离

每个检查点先记录物品格位／数量、末影箱、经验、效果及剩余时长、维度键／坐标／朝向、床／锚绑定、至少两个本轮进度和首次末地人数。效果在正常在线游玩中会消耗时长，不把自然到期当作恢复丢失；记录下线、停服及重连的实际时间。死亡后的正常掉落也与档案恢复分开判断。

| 场景 | 操作与必须结果 |
| --- | --- |
| 同轮重连 | 在主世界／下界／末地分散布置重连检查；回原位置和维度，物品不多发或回滚，末影箱／进度保持。再次进入末地和重复 criterion 不增加本轮数量 |
| 同轮正常 stop／新进程登录 | 原位置可能暂时无法加载时先留大厅核验；核验完成后恢复本轮位置，不能把大厅临时坐标存成比赛位置。建筑与箱子保留，累计统计不清零 |
| A 离线跨三轮 | A 在第 3 轮 RUNNING 保存上述可辨状态后下线，B 完成第 3 轮及第 4、5、6 轮；A 全程不在第 4～6 轮上线，第 7 轮 READY 后才重连。记录三轮完成和轮换时间，不能靠手动修改 roundId 代替 |
| 第 7 轮重新加入 | A 不恢复第 3 轮物资／末影箱／坐标／效果／经验／床锚／进度，不出现在旧维度；核验后在大厅，join 后从第 7 轮出生点空装进入。本轮末地统计从零开始；原版累计统计和第 3 轮历史仍在 |
| 离线书册 | A 上线补领最新上一轮主册，不能一次塞入所有缺席轮主册；第 3～6 轮历史可分别查询，旧轮书可按命令手工补领。缺席轮名单不能虚构 A 已参加 |

普通模式当前没有极限复生资格。本页不把“没有发现资格”记为资格隔离通过；资格、怪物身份和救场跨轮隔离由 完整身份回归补齐。

## TAB、书册与成绩逐轮核对

每轮保存开局、无在线活人、首龙后、轮换前及下一轮的 TAB 画面。比较 history／participants 的当轮有效耗时、个人在线时长、名单、死亡／重生次数、进度／首次末地、胜者、规则与异常标记；不能把个人时长作为排行榜总时间。十轮各有一份独立终局，旧轮输出不被新轮或重连更新覆盖。

每次轮换后亲自打开真成书，检查上一轮结果、当前规则榜、参赛名单、历史入口、书版和总卷数；中文换行和末行由用户截图判断。`read-book` 交换书与手持物时不能丢失／复制物品。已领主册在同轮重连及正常重启后不自动重复发同版；手工补领允许限速重复，记录为主动领取。

另用独立的满背包场景按 [书册人工清单](统计榜单与历史书.md) 检查待领、空出格位后的重试和正常重启。管理员准备物品须标记夹具；不要因新轮本来清空战斗背包而声称已经覆盖“自动书满包”。成绩修订、核验和两版书快照沿用 [管理清单](管理命令与成绩修订.md)，不在十轮主线用修订替代首龙。

## 正常 stop／新进程恢复矩阵

可把这些检查安排在上述十轮，或在同一独立实例额外轮次执行，记录对应轮次。每项先用 status、TAB 和服务端日志证明已到目标阶段，再在控制台输入 `stop`；保存最后状态与进程退出日志，实际离线一段时间，用相同目录、制品和参数启动新进程，记录新 PID／启动日志。仅关闭客户端不算新进程恢复，仅重开 SQLite／Session 不算整服恢复。

| 目标阶段 | 停止前准备 | 重启后必须核对 |
| --- | --- | --- |
| PREPARING | 原轮创建后、三维度未全部 READY；记录已落盘清单／部分世界 | 原 roundId、种子和规则继续准备，部分文件保留；核验完成前不能加入，不新建替代轮次 |
| WAITING | 世界 READY，记录参加／就绪状态、种子与清单 | 原身份和规则保持；在线状态按新连接重新核验。准备验证不重造地形，不自动启动无人就绪的比赛；已保存建筑的对照另在 RUNNING 停服项执行 |
| COUNTDOWN | 默认 30 秒内记录剩余量及已就绪者 UUID，及时 stop；保留一个停服前未 ready 的观察者 UUID | 重启后先等原世界 READY，原已 ready 玩家暂不登录；控制台 `hardrush status` 应仍为 COUNTDOWN 且显示等待档案核验。让未 ready 的观察者登录，用 TAB 连续观察至少 5 秒，保存剩余量不减；其他 UUID 登录不能代替恢复门槛。原 ready UUID 完成档案核验上线后，从保存剩余量继续，不扣停服／等候时间；恢复后显式 unready 或最后 ready 玩家断线仍取消，下一次 ready 才从完整 30 秒重新开始。另在暂挂期间再次 stop／重启，核对剩余量保持；不能把重新 ready 的 30 秒当成原剩余量已恢复 |
| RUNNING | A／B 在不同维度，记录完整档案、有效时间及已获进度；另测全部活人离线 | 同轮档案恢复及累计时间保持，停服不加时间；无人类在线继续停表，不把 offline 当团灭；之后正常首龙成绩仅包含实际有效区间 |
| SETTLING／终局提交中 | 捕获首龙后立即 stop，保留实际致死／受理日志 | 已受理结果与因果排空，唯一终局、胜者／待核验及停止成绩保持，不产生部分成绩或再次结算；保存等待不加成绩。人工未捕获此短阶段则填未测试，延迟提交夹具另列 |
| CELEBRATING | 真实运行庆祝若干秒，记录停止成绩 | 原胜者、历史、书版和冻结时间保持；重启后不恢复庆祝，直接安全换轮，所有人在大厅，没有庆祝物资 |
| ROTATING | 尽量在实际回大厅／封存／关闭期间 stop，记录旧轮和下轮提交边界 | 恢复到同一旧轮的可解释关闭步骤，或已原子提交的那一个下轮；根据日志和持久化身份判定。旧世界不误删，不重开旧轮比赛、不创建两个下轮、不重复发书 |
| 新轮 READY、书已领／待领 | 保存上一轮详情、已领主册数量；待领另用可复现满包夹具 | 旧成绩／待领／当前书版保持；已领同版无自动重复发放，待领不丢、不覆盖背包 |

正常停止以实际保存成功为准。若出现 dirty／RECOVERY_REQUIRED、档案失败、CLOSE_FAILED 或保存错误，保留资料并填失败／未完成，不删除标记或手改数据库将它变成 clean。PREPARING 故障重试只使用适用的原轮管理操作流程；没有具体恢复条件时停止该场景并反馈日志。救场阶段在 相关功能接通后补测，不能用普通离线停表模拟救场。

## 旧世界保留与释放证据

各轮从实例存档根下 `hardrush/round-worlds/<roundId>.json` 只读记录所有权、种子、三维度键和登记的实际存储位置；玩家封存位于 `hardrush/profiles`，历史数据库为 `hardrush/rounds.sqlite`。路径以该实例实际存档根和清单为准，不猜测维度目录、不改写清单。世界结束前后的箱子／建筑照片与清单对应，正常停服后再检查已保存文件；保留原 SQLite 和 WAL 文件。

每次轮换留存以下证据：全员在长期大厅、旧维度不再允许路由／重连、旧清单与区块文件仍在、新轮生成独立三维度身份，以及服务端的关闭／释放日志或本轮自动整链的对应记录。权限等级 2 的管理员可把清单里的**完整旧维度键**用于只读命令 `/execute in <旧维度键> run time query gametime`：轮换后旧维度应被判为未知，当前轮维度应可查询；保存完整输出。该检查只证明命令解析入口已注销，不证明所有 Java 对象或 native IO 已释放，也不允许用传送回旧世界替代检查。

“文件仍在”与“运行引用已释放”分别记录：旧文件默认保留是正确结果。旧世界、区块、IO、轮换任务或录制器引用是否持续增长，需要十轮无图形整链／专门诊断证据；TAB、目录存在、维度命令拒绝和一次 GC／内存截图均不能单独证明没有泄漏。无法观察的指标写“人工不可观察／自动证据待核对”，不要虚构管理诊断字段。

当前没有自动归档／删除及完整回放保存故障管理。不要删除旧世界来证明“释放”，也不要跳过已安装录制器的 VERIFIED 保存门槛；未安装录制器记录 disabled。录像实际播放、救场／极限闭环、强制杀进程、数据库／磁盘故障、清理路径攻击和归档恢复归极限玩法和故障恢复，后续另验。
