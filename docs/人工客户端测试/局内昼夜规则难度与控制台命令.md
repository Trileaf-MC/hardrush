# 人工检查：局内昼夜与控制台时间天气

日期：2026-11-01。由人类用户在独立开发实例、干净原版 26.3 客户端执行。本次开发没有运行真实客户端。

修复前，正式轮次的服务端昼夜判定（亡灵日晒、床能否入睡、夜间刷怪、月相、袭击巡逻等）一直停在第 0 tick 的清晨，与客户端看到的天空不一致；服务器控制台执行 `/time`、`/weather` 只改动无人使用的原版主世界。修复后两者都以本轮共享时钟和本轮天气为准。服务端 GameTest 已覆盖时钟→环境属性与控制台路由，以下只验证客户端可见结果。

| 操作 | 预期 | 记录 |
| --- | --- | --- |
| 挑战中在服务器控制台执行 `time set midnight`，再执行 `time set noon` | 局内所有维度玩家的天空立即切换；黄昏契约随入夜结束；大厅时间不变 | 控制台回执、局内与大厅截图 |
| 控制台执行 `weather rain`、`weather clear` | 只有局内主世界下雨／放晴，大厅天气不变 | 截图 |
| 局内入夜后（自然入夜或控制台调到 `midnight`），怪物玩家放出僵尸／骷髅随从，并让随从站在露天 | 随从不燃烧；调回 `noon` 后露天随从按原版规律燃烧，戴头盔时只磨损头盔 | 视频或截图 |
| 局内入夜后在露天平地等待 1–2 分钟 | 自然刷出敌对生物，与原版夜晚一致 | 截图 |
| 局内夜晚右键床 | 可以入睡；所有在线局内玩家睡下后跳到早晨；白天右键提示“只能在夜间睡觉” | 截图 |
| 停服重启后重复第一行检查 | 局内时间保留重启前进度，昼夜判定仍与天空一致 | 重启前后时间 |

每项填写通过／失败、复现步骤、JAR SHA-256、轮次 ID。客户端画面只由用户手动确认；失败时保留日志与世界清单。
