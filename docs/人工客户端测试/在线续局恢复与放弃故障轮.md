# 在线续局恢复与放弃故障轮

日期：2026-10-23。待用户手动检查。使用原版客户端，在可丢弃测试实例与存档副本中进行。[实现说明](../p3-auto-resume.md)。

- [ ] OP4 在故障隔离中输入 `/hardrush admin recovery`。聊天显示保存时间、约多久之前、轮号、回退提醒，以及可点击的 yes/no；普通玩家和 OP3 无法执行。
- [ ] 点击 no，确认所有人仍在大厅，建筑、物品和数据库没有被回退。重新执行命令获得新的提示。
- [ ] 点击 yes。等待安全释放和载入完成，在线人类自动回原局，保留保存点的身份、生命、复生次数、背包、末影箱、经验、进度、效果、维度和位置，无需重登／再次准备。
- [ ] 保存时鼠标拿物品并打开合成格，恢复后核对总数恰好一次；原版关闭菜单时物品可以回到背包。
- [ ] 在隔离副本破坏最新保存点文件。命令应自动找到较早的可用点，明确显示更早的时间。确认提示出现后再破坏该点，点击 yes 后应继续查找其他点并重新确认，不应静默扩大回退范围。
- [ ] 所有保留点损坏或缺失时，明确显示“无法自动恢复”和原因；准备区、追猎、复生入口都不能绕过故障隔离。
- [ ] 旧提示过期、申请管理员重登／降权、另一位管理员点击、重复点击，以及轮次已经改变后点击，都不能触发回退。
- [ ] 在无法恢复的故障轮输入不带参数的 `/hardrush admin close-recovery`。原轮记为中止，释放完成后新轮可正常准备；旧轮装备不进入新轮，旧世界仍保留。原轮已有终局时保持原结果。
- [ ] 正常对局中执行 recovery 或 close-recovery，均拒绝操作；新轮重启后不应恢复到已放弃的故障轮。

记录服务端 JAR、保存点时间、轮次、玩家名与服务器日志。存储只读／满盘、录像保存失败、原数据库或世界所有权无法核验时，应展示阻塞原因，修复后再重试。
