# 统计、榜单与历史书人工检查

日期：2026-10-14。尚未执行，等待用户测试。使用当前 Minecraft 26.3 构建，独立测试存档与数据库。只需原版客户端，不安装测试模组或资源包。下面的操作由人类进行，本批代理未启动真实客户端。

首次新实例使用 Java 25、对应 Fabric API，启动参数为 `-Dhardrush.competition.enabled=true -Dhardrush.round.initialMode=normal --enable-native-access=ALL-UNNAMED`；已有库以已保存规则为准。默认极限模式当前仍禁止开赛，不用开发工具或编辑当轮数据库绕过。

## 1. TAB、原版列表与计时

1. 两个玩家登录，档案核验完成后 `/hardrush join`，一人 `/hardrush ready`。按 TAB，确认原版在线名单仍在，页头包含轮次／普通／状态，30 秒开局倒计时不提前归零。
2. 开局后确认有效挑战时长每秒更新；另一人晚加入，轮次时间不重置。死亡画面停留、重生、下线／重连时对照既有计时人工清单。
3. 所有人类下线，再登录仍保留原轮；无人类在线的期间不增加有效时长。暂停原因和在线／离线数正确。
4. 状态文字、胜者名字、倒计时与末地人数无明显闪烁或错误截断。角色／救场全场景由角色与救场清单检查。

## 2. 进度和首次末地进入

1. 同轮依次取得两个可展示进度，完成重复 criterion 不增加数量；配方解锁和根节点不计入。结算后用 `/hardrush participants <轮次>` 对照。
2. 一个玩家正常走原版末地门，人数增加 1；出入末地、死亡重生、同轮下线再上线，不重复增加。另一个 UUID 进入才增加到 2。
3. 下一轮人数与进度从零开始，旧轮详情仍保存原数。数据包集合变更的指纹验证以自动测试为基础；若人工改变数据包，记录变更前后完整指纹。

## 3. 结算与分榜

1. 完成普通模式首龙尾刀，确认 TAB 显示尾刀者、停止时间及默认十分钟庆祝倒计时。低血量夹具结果须标注，不能当作满血生存验收。
2. 查询 `/hardrush history <轮次>`、`/hardrush participants <轮次>`、`/hardrush leaderboard`；记录模式、规则指纹、耗时、名单和种子只在结算后公开。
3. 正常重启后查询同轮，结果与名单保持。切换下轮规则后，默认榜使用新的完整规则指纹，旧规则通过显式指纹查询；同毫秒和异常隔离已有自动证据，不靠手改成绩模拟验收。
4. 非管理员 `/hardrush verify <轮次>` 不可执行；管理员能只读核验，但没有修正结果。管理员成绩修正与审计尚未实现。

## 4. 真成书、阅读与分卷

1. 实际等待庆祝结束、自动轮换与新档案核验，背包出现一本真正的成书。主册应含上一轮结果、当前规则榜、源轮名单、历史命令与总卷数。
2. 手持书右键翻页，确认中文换行可读、末行未消失。书不在快捷栏时运行 `/hardrush read-book`，或 `/hardrush read-book <1～36格号>`；确认打开书，原手持物只是与书交换格位，没有丢失、覆盖或复制。
3. `/hardrush book <轮次> [卷]` 领取有效卷；不存在的卷被拒绝。快速重复请求触发 5 秒限速，等待后可手工再领；数据库名单不因分卷丢失。
4. 普通大厅不能借阅读书绕过隔离去使用其他物品、搬运容器或发动攻击。单纯切快捷栏可用，未完成档案核验时阅读仍拒绝。

## 5. 满背包、离线补领与正常重启

1. 在可操作的测试场景／由管理员准备满背包，记录每格物品与数量。下一轮自动书领取失败时有待领提示，没有覆盖已有物品或丢书到地上。
2. 空出一个格位，等待自动重试；只有一本自动主册。若书位于主背包，使用 `read-book` 验证可读。
3. 玩家离线跨三轮后登录，档案核验后只补最新上一轮主册，不一次塞入三轮书；旧轮仍可手工领取。
4. 背包满且待领时正常停服重启，待领保留；已经领取后正常重启，不再自动重复发同版主册。
5. 故障注入、强制结束进程或 SQLite ACK 前物品转移不在此次人工清单的正常流程内，留待故障专项验证。
