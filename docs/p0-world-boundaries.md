## 修复内容

原版跨维度进度使用 `minecraft:overworld`、`minecraft:the_nether`、`minecraft:the_end`，不会直接匹配本轮 `hardrush:p0_…/…` 注册键。新增受控映射：

- 仅在本轮拥有的两个世界之间转换时，为原版维度转换进度提供语义键，并保留下界进入坐标供 `nether/fast_travel` 使用。
- 原版位置谓词检查标准三维度时使用语义键；明确指定真实自定义维度键的数据包条件仍按真实键匹配。
- 不替换存储、网络包或玩家位置中的真实维度键；普通原版世界的进度、床／锚与末地出口另有回归断言。

Fantasy 0.8.4+26.3 的默认运行时时钟独立于大厅，但只存在于内存。现在三个本轮维度共用一套持久昼夜时钟，保存于本轮主世界的 `data/hardrush/p0_clocks.dat`，只由本轮主世界推进一次。原版模拟用的 `gameTime` 仍沿用 Fantasy 的全服 tick，不用这个值计算未来比赛成绩。

26.3 的 `ServerLevel.getWeatherData()` 默认读取全服天气，构造时也从服务器复制初始雨量。现在本轮维度使用自己的 `data/minecraft/weather.dat`；构造时读取该文件，原版 `weather` 命令按命令来源修改本轮天气。Fantasy 已有按维度发送天气包的适配，本项目复用它。大厅中的命令继续使用原版全服天气入口。

旧原型没有保存运行时时钟，无法找回过去已经丢失的昼夜值。首次使用本实现时创建本轮时钟，此后的正常保存／重启保留时钟及天气。损坏数据、强制终止与跨轮状态隔离仍属于后续任务。

## 正常停服重启

使用没有玩家在线的受管 `.local/debug/server`，Minecraft 26.3、Loader 0.19.5、API 0.162.0+26.3、Fantasy 0.8.4+26.3。该服务端包含 MCPFabric 调试工具，未连接客户端。操作为：备份本轮时钟／天气文件 → 在本轮设置时间及雷雨 → 等原版雨量过渡完成 → `save-all flush` → 正常 `stop` → 重新启动 → 核对轮次清单、时钟推进和雷雨 → 停服后恢复原文件并启动。

结构化结果：[restart-results.json](evidence/world-boundaries-20261013/restart-results.json)。复现脚本：[verify-restart.py](evidence/world-boundaries-20261013/verify-restart.py)，从仓库根目录运行；只允许已有受管调试服且无玩家在线，不接受新 EULA。脚本使用本地鉴权配置，输出不包含凭据。

结果：轮次／种子／三个维度清单保持一致；重启没有把本轮时间重置，昼夜增量与模拟 tick 增量相符；本轮雷雨恢复，大厅雨天保持自己的状态。测试后恢复原本的本轮时钟／晴天资料。仅证明正常停服路径，不宣称崩溃恢复或 P0 阶段通过。
