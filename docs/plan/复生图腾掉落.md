# 复生图腾掉落与原地复生

2026-11-19 与需求方讨论定稿。状态：方案已定，待对抗性评审后实现。

## 背景

人类击杀人类后可以得到复生图腾，但这个机制几乎没人注意到：

- 奖励只记在快照里。人类活着时背包里没有图腾，击杀后只在动作栏闪过一句「获得 1 个复生图腾 · 可在营地祭坛复生」。对一个还没死过的人来说，"营地祭坛"是什么他都不知道。
- 事先也没有任何告知。日落时的标题只写「极限追猎开始」，规则书把这句话放在"复生"那一页，读起来像是怪物的规则。
- 奖励兑现得太晚，要等自己阵亡才用得上。

结果人类入场后倾向于合作，偏离了本模组"人类之间也有竞争"的设计。

改为：复生图腾成为世界里看得见、捡得到、用得上的东西。

- 人类被人类击杀时，尸体旁会掉一个复生图腾，捡到就是缴获。
- 人类背包里一直带着那叠图腾，和阵亡后在营地看到的是同一叠。
- 拿在手上阵亡时，按原版机制弹出图腾，原地救回。

复生次数因此有了两种用法：

- **原地复生**：保留装备和位置；
- **祭坛复生**：空手出发，落在远处荒野。

只在**极限模式**生效，普通模式没有复生图腾，所有行为不变。

## 1. 规则

### 1.1 掉落

- **触发条件**：日落后，一名本轮在场的人类阵亡，而且死亡的击杀归属是"以人类身份发起的直接攻击"。
  - 击杀归属沿用现有的 `RoundDeath.killCredit()`，按原版"最近 5 秒内伤害过你的玩家"计算。所以被打落悬崖、被打进岩浆、挨打后被怪补刀，都算。
  - 攻击种类沿用现有的 `directHumanAttack`：近战、箭、床、重生锚、TNT、末地水晶。
  - 自杀不算。
- **数量**：每名阵亡者掉 **1 个**，与他持有多少图腾无关。一次爆炸炸死多人，就每人掉一个。
- **不再要求击杀者此刻仍是人类**。掉落物不归任何人，谁捡到算谁的，所以只要攻击发起的那一刻对方是人类就行（`CombatOrigin.actor().identity()` 记录的是攻击发起时的身份）。这样一来：
  - 互相同归于尽的，照样掉落；
  - 击杀者已经阵亡、箭还在飞，照样掉落。
- **击杀者不再自动 +1**。这是和现状最大的区别：奖励从"记到账上"变成"掉在地上"。
- **怪物玩家击杀人类保持不变**：直接 +1、召回祭坛前，不掉落。掉落只属于人类之间的 PvP。
- **阵亡者自己持有的图腾不会掉出**，原样带回营地。他在营地看到的还是那叠图腾，前后连贯。

### 1.2 地上的掉落物

| 属性 | 规则 | 依据（26.3） |
| --- | --- | --- |
| 位置 | 阵亡者死亡时的位置和维度，与原版死亡掉落同处 | — |
| 拾取延迟 | 生成后约 2 秒内不能拾取，与原版死亡掉落相近 | — |
| 防火 | 带 `damage_resistant`（`minecraft:is_fire`）组件：不会烧毁，在岩浆里能浮起来 | `ItemEntity.fireImmune()` 取 `!getItem().canBeHurtBy(inFire)` |
| 防爆、防仙人掌 | 实体设为无敌（`setInvulnerable`）。虚空仍会把它删掉，因为那条路径是 `onBelowWorld → discard`，不经过伤害 | `ItemEntity.hurtServer` 先判 `isInvulnerableToBase` |
| 寿命 | 与原版一样 5 分钟（`LIFETIME = 6000`），到时消失 | `ItemEntity.tick` |
| 醒目程度 | 金色发光轮廓；头顶始终显示金色名字「复生图腾」 | 自定义名字设为可见时，`EntityRenderer.shouldShowName` 对掉落物也成立 |
| 本轮结束 | 全部清除 | — |

### 1.3 拾取

- **谁能捡**：只有本轮在场、在线的人类。
- **谁捡不走**：怪物玩家、原版生物、悦灵、漏斗、漏斗矿车。
- **背包规则**：和原版一致。已经有图腾就能并进那一叠（上限 99）；没有图腾又没有空位，就捡不起来。
- **捡到时**：
  - 播放原版拾取动画和音效；
  - 本轮第一次捡到时，动作栏显示「获得复生图腾 · 拿在手上阵亡时原地复生」；
  - 之后再捡不再出字，数量变化本身就看得见。

### 1.4 持有与外观

人类和营地怪物持有的是**同一件物品**，数量就是复生次数，快照仍然是唯一的余额。

它和原版不死图腾的区别：

- **能堆叠，还显示数量**：原版不死图腾不能堆叠，这是最直观的区别；
- **金色名字**「复生图腾」，非斜体；
- **附魔光效**；
- **描述**按持有者的身份改写：

| 持有者 | 描述（第一行即手持时动作栏的那句用法） |
| --- | --- |
| 人类 | 拿在手上阵亡时原地复生，消耗 **1** 个 ／ 没拿在手上就阵亡，可到营地祭坛复生 ／ 阵亡不掉落 · 不能丢弃或转赠 |
| 营地怪物 | 站上营地北侧祭坛的金块 **4** 秒复生 ／ 每个图腾复生一次，复生后空手出发，其余图腾随身带走 ／ 不能丢弃或转赠 · 本轮结束时清空 |

持有超过 99 个时，在第二行补「共 **{n}** 个」，与现状相同。

- 不能丢出，不能放进任何容器（含末影箱、收纳袋、物品展示框、盔甲架、饰纹陶罐），不能交给悦灵。
- 物品**永远不带** `DEATH_PROTECTION` 组件（与现状相同）。所以原版的免死逻辑永远不会认它，原地复生只能走我们自己的入口（见 1.5）。

### 1.5 原地复生

- **触发**：人类拿着复生图腾（主手或副手）阵亡，而且死因是原版图腾也能救的那一类，即不带 `bypasses_invulnerability` 标签。虚空、`/kill` 救不了。
- **手的顺序与原版一致**：先主手，后副手，取第一个"能免死的物品"。如果副手拿着原版不死图腾、主手拿着复生图腾，用的是复生图腾；反过来就用原版的。
- **效果与原版一致**：
  - 生命值设为 1；
  - 套用原版不死图腾的效果：清除所有状态效果，给予生命恢复 II 45 秒、伤害吸收 II 5 秒、抗火 40 秒；
  - 广播实体事件 35，播放全屏图腾动画、粒子和音效；
  - 记录物品使用统计，触发 `used_totem` 进度条件。
- **额外的提示**：动作栏「复生图腾生效 · 还剩 **{n}** 个」。
- 被原地救回不算阵亡：不进入死亡结算，不掉落图腾，没有击杀公告，攻击者也没有击杀奖励。
- **无法扣次数时**：如果比赛此刻处于锁定、核验或恢复隔离之类的状态，或者这名玩家的账上已经没有可用次数，就不救，按原版流程继续。另一只手里有原版不死图腾的照常生效；没有就正常阵亡，带着图腾回营地。

### 1.6 祭坛复生

流程不变，只改描述和提示里的"空手出发"：复生用掉 1 个，剩下的图腾随身回到人类背包里。

### 1.7 TAB 栏

- 用原版计分板的列表槽位（`list`），名字右侧显示金色的 `✦{n}`。
- 人类和怪物都显示；0 个的不写分数，不显示任何内容。
- 只发数据包，不写服务端计分板，所以不会存进存档，也不影响服主自己的计分板。代价是：如果服主自己也在列表槽位放了计分项，会被覆盖。
- 依据（26.3 客户端 `PlayerTabOverlay`）：没有分数的玩家显示空白；每个分数可以单独设置数字格式，可以用固定格式写成 `✦2`。

### 1.8 告知

| 时机 | 档位 | 文案 | 说明 |
| --- | --- | --- | --- |
| 黄昏契约预警（黄条） | T3 | 夜幕将至 · 日落后击杀人类可夺得复生图腾 · {mm:ss} | 只在极限模式改；普通模式维持「距猎杀开始还有」；红条不变 |

| 人类互杀后的公告 | T1 | **{击杀者}** 击杀了 **{阵亡者}** · 掉落 **1** 个复生图腾 | 每位玩家本轮第一次遇到时提示，之后不再提示。发给本轮在场、在线的人类和怪物，不包括击杀者、阵亡者、管理员旁观者和已退出本轮的人。一批多人时写成「击杀了 **{阵亡者}** 等 **{n}** 人 · 掉落 **{n}** 个复生图腾」 |

各条说明：

- 黄昏契约的 Boss 栏和标题，人类和怪物看到的是同一份，所以写「击杀人类」。这句话对两种身份都成立：人类击杀人类会掉落，怪物击杀人类直接到手。
- 公告不写"首杀"。"本轮已经提示过"的记录只在内存里，服务器重启后可能会再提示一次；不写"首杀"，重复一次也不算说错。
- 现在人类击杀者收到的「获得 1 个复生图腾 · 可在营地祭坛复生」**删除**，因为击杀者不再自动得到图腾。
- 怪物击杀人类时的提示不变。

规则书：

- 「黄昏契约」页（极限模式）补一句：*日落后，人类被人类击杀时会掉落 1 个复生图腾。*
- 「复生」页改写为：*复生图腾：人类被人类击杀会掉落 1 个，人类捡起即得；怪物击杀人类直接获得 1 个。拿在手上阵亡时原地复生，消耗 1 个；没拿在手上就阵亡，可到营地祭坛站上金块 4 秒复生，空手出发。图腾不能丢弃或转赠，阵亡时自己的图腾不会掉落。*
- 一页放不下就拆成两页。

## 2. 实现设计

### 2.1 core：快照记录地上的图腾

`RoundSnapshot` 新增 `looseTotems: Map<UUID, LooseTotem>`，其中 `LooseTotem(UUID victim, int victimLife, UUID killer)`。编码 `SCHEMA` 从 9 升到 10，并限定数量上限。旧版本快照读出来时，`looseTotems` 为空。

| 提议 | 变化 |
| --- | --- |
| `proposeDeathBatch` | 人类击杀人类的分支，由"击杀者 +1"改为"为每名阵亡者生成一个编号，登记进 `looseTotems`"。判定条件见 1.1。怪物击杀人类的分支不变 |
| `proposeLooseTotemPickup(eventId, roundId, token, playerId, life)` | 新增。拾取者必须是本轮在场、在线的人类，生命序号一致，编号还在登记里。成功后删除编号、拾取者 +1 |
| `proposeTotemSave(eventId, roundId, playerId, life)` | 新增。必须是在场人类，生命序号一致，次数至少 1。成功后次数 -1，其他不变 |
| 换轮 | 新的一轮从空表开始 |

编号登记在快照里，有三个原因：

1. 引擎能核对每一次拾取，不靠平台层自觉；
2. 服务器重启时，只要世界和快照都保存了，没人捡的图腾不会丢；
3. 任何时候都不会刷出图腾：
   - 先有提交成功，后有地上的实体，所以"实体在而编号不在"只会出现在已经被捡走、而世界还没存盘就崩溃的情况，这种实体直接删除；
   - "编号在而实体不在"只是一条空登记，本轮结束时清掉。

对照：营地的怪物币（`CampTransfers`）丢出时就扣账，地上那叠只记在内存里，重启就作废。复生图腾不同，它是凭空产出的奖励，丢了对玩家不公平，所以登记进快照。

### 2.2 platform：拆出复生图腾的独立包

`RevivalTotems` 现在放在 `lobby` 包里，只服务营地怪物。这次它要覆盖挑战世界里的人类，再放在 `lobby` 下就不合适了（Level 2 重构）。新建 `dev.hardrush.revival` 包：

| 类 | 职责 |
| --- | --- |
| `RevivalTotems` | 从 `lobby` 移过来。物品模板、按身份改写描述、把余额投影到背包。资格从"营地怪物"放宽到"营地怪物或挑战世界里在场的人类（档案已核验）"。投影数量 = 已提交的次数 − 正在提交中的原地复生次数 |
| `TotemDrops`（新） | 死亡结算提交后生成掉落物；处理拾取；每秒巡检所有世界的游离图腾（无编号、编号不在登记里、实体与登记不符的一律删除）；处理击杀公告；管理掉落物发光颜色用的队伍 |
| `TotemSave`（新） | 原地复生：同步判定、执行原版效果、把扣次数排进提交队列 |
| `TotemTab`（新） | TAB 栏的计分板数据包，每位玩家单独维护，只在变化时发 |

`CampTransfers.sweep` 里现在那段"游离复生图腾一律删除"的逻辑，移到 `TotemDrops` 统一处理。

### 2.3 死亡位置与生成时机

- 在 `AFTER_DEATH` 记录阵亡者死亡时的维度和坐标，与 `captureDeath` 放在同一处，按死亡批次暂存在平台层。
- 死亡批次提交成功后，对比提交前后 `looseTotems` 的差别，在暂存的位置生成掉落物：
  - 掉落物带编号；
  - 设为"永不可拾取"（`setNeverPickUp`）：原版生物、悦灵、猪灵的拾取路径都会先检查 `hasPickUpDelay`（见 `Mob.aiStep`），这样它们统统捡不走；
  - 玩家拾取走我们自己的入口，在 `playerTouch` 的开头接管，自己维护那约 2 秒的生成延迟；
  - 漏斗不检查拾取延迟（`HopperBlockEntity`），需要单独拦截。
- 提交失败时不生成，与死亡结算一起失败。

### 2.4 拾取路径

沿用营地怪物币"先提交、后拾取"的模式（`CampTransfers.pickup`）：

1. 在 `playerTouch` 的开头识别带编号的复生图腾。
2. 检查拾取资格，以及背包能否放下。
3. 标记"已认领"，然后请求 `proposeLooseTotemPickup`。
4. 提交成功后，播放 `player.take` 拾取动画、删除实体，由投影把背包数量补齐。
5. 提交失败就取消认领标记，图腾留在原地。

### 2.5 原地复生的同步判定

原版的免死是在伤害处理过程中同步判定的，而本模组的状态变更是异步提交的。这里沿用阵亡的处理方式：**世界里先发生，账本随后补记**。阵亡也是先在 `captureDeath` 采集、后排队提交的。

1. 在 `LivingEntity.checkTotemDeathProtection` 开头注入。只处理在场人类，并且伤害类型不带 `bypasses_invulnerability`（原版代码在 `LivingEntity` 第 1415 行起）。
2. 按主手、副手的顺序，找第一个"复生图腾，或带 `DEATH_PROTECTION` 的物品"。是原版物品就交给原版处理；是复生图腾就进入下一步。
3. 调用 `RoundSession.captureTotemSave(...)`，同步判断能不能救。条件是：比赛没有锁定；这名玩家是在场人类，生命序号一致；已提交的次数减去正在提交中的原地复生次数至少为 1。能救就把这次扣减记作"提交中"，排进提交队列。
4. 能救：手里的那叠减 1，然后按原版顺序执行：记统计、触发 `used_totem`、生命值设为 1、套用 `DeathProtection.TOTEM_OF_UNDYING` 的效果、广播实体事件 35。返回 `true`。
5. 不能救：跳过复生图腾，按原版逻辑继续检查另一只手。
6. 扣减提交失败属于存储故障，走现有的会话失败与恢复流程，不在这里单独处理。

现有 `MonsterLivingMixin.noCreeperEquipmentProtection` 也注入在同一个方法开头，只作用于苦力怕形态的怪物，和这里互不干扰，但两处的先后顺序要在实现时确认。

### 2.6 阵亡时不掉落自己的图腾

在在场人类的 `dropAllDeathLoot` 开头，从背包、合成格、光标上清掉复生图腾。这些都只是投影，余额在快照里。

### 2.7 禁止放进容器

物品只是余额的投影，本身不带免死效果，放到别处也没有任何作用：任何人拿到一个多余的副本，投影都会按他的实际次数把它收回。所以这里的拦截只是为了体验，不涉及安全：

- 现有的丢出拦截（`ProtectionNetworkMixin`、`PlayerIsolationNetworkMixin`）扩展到挑战世界里的人类；
- `Slot.mayPlace`：非玩家背包的格子不接受复生图腾；
- 收纳袋、物品展示框、盔甲架、饰纹陶罐、悦灵逐一拦截。

### 2.8 TAB 栏

`TotemTab` 给每位在线玩家维护一套只存在于数据包里的计分项：

- 计分项 `hardrush_totems`，显示在列表槽位；
- 每位在场参赛者一个分数，数字格式固定为金色的 `✦{n}`；
- 0 个时发送"重置分数"；
- 每秒最多对比一次，有变化才发。

掉落物的金色发光轮廓也用只存在于数据包里的队伍（`hardrush_totem_drop`，颜色 `GOLD`），成员是掉落物实体的 UUID。
