# 集结区统一入场

2026-11-02 与需求方讨论定稿。状态：已实现，待[人工客户端验收](../人工客户端测试/集结区统一入场.md)。

## 背景

挑战开始后，玩家走进集结区会被传送到固定落点 `WAIT_OUTSIDE`（`HumanEntry` 中 `!open` 分支）：

1. 无论从哪侧进圈都甩到同一点，最远跨十几格，像“闪现”。
2. 传送强制改朝向为 yaw 180、pitch 0，镜头被掰一下。
3. 只在聊天栏提示，容易被刷走；文案固定为“请使用中途门”，在世界准备、结算、庆祝、换轮、恢复核验时并不成立，极限怪物也会被错误地指向中途门。

梳理全部强制传送／拉回调用点后，普通玩家会碰到的“禁区弹出”只有集结区这一处。正式世界已沿用原版生存规则（`RoundRuntime` 对正式世界不返回保护区），出生保护相关逻辑已无法触发。

讨论过“关闭时立栅栏封场”“常驻栅栏加门”“只做软反馈的通用禁区框架”，最终改为：**取消中途门，集结区始终开放，按阶段决定站进圈的效果**。玩家只需记住一条规则：站进圈 = 我要参加，离开 = 不参加。

## 1. 集结区各阶段行为

任何阶段都不再把人传出圈。

| 阶段 | 有资格的大厅玩家站进圈 | 没有资格的玩家站进圈 |
| --- | --- | --- |
| 等待／倒计时 | 与现有相同：立即准备，共用开局倒计时，离开取消 | 动作栏说明原因 |
| 挑战／救场 | 站满 4 秒中途加入，离开取消（见第 2 节）；救场阶段加入即救场 | 动作栏说明原因 |
| 世界准备中 | 动作栏：世界准备中，开放后自动准备 | 动作栏说明原因 |
| 结算／庆祝／换轮／恢复核验 | 动作栏说明当前状态 | 动作栏说明原因 |

- **开放时已在圈内的玩家自动准备**：世界准备期间可以先站进圈等待，进入等待阶段后直接登记准备，不必出圈再进。这一条取代原手测清单中“开放后需主动入圈”的要求。
- 资格判定沿用现有 `eligible` 与中途门 `gateAvailable` 的条件（大厅身份、档案核验、世界就绪、未锁定比赛）。
- 没有资格的原因分开写，例如：
  - 极限怪物：你已化身怪物 · 去怪物庭院追猎，或到复生祭坛复生
  - 已退出本轮：你已退出本轮，下一轮可重新集结
  - 结算／庆祝／换轮：本轮结束中，换轮后重新开放
  - 恢复核验：恢复核验中，入口暂停
- 提示走现有 `LobbyHints` 动作栏，不发聊天消息。

## 2. 中途加入

- 仿照原版下界传送门：在圈内连续站满 80 tick（4 秒）后提交加入请求。原版等待时间由 `playersNetherPortalDefaultDelay` 规则决定（`NetherPortalBlock.getPortalTransitionTime`），默认 80 tick。
- 站立期间：
  - 向该玩家显示个人 Boss 栏，进度条表示剩余时间，文字为：`世界已运转 X 天 Y 小时 · 中途加入无出生保护 · 祝你好运`。
  - 天数和小时取本轮主世界的 `dayTime`：天 = `dayTime / 24000`，小时 = `dayTime % 24000 / 1000`。睡觉跳过的夜晚计入，与 F3 显示的天数一致。
  - 播放原版传送门音效 `block.portal.trigger`，脚下冒传送门粒子。
  - 动作栏补充：离开集结区取消引导。
- 离开圈或失去资格时取消，Boss 栏移除。
- 请求一旦提交即不可撤销；失败时按回复提示，玩家需出圈再进才会重新计时。
- 加入后的结果与原中途门相同：空装进入本轮主世界自然出生点，无出生保护。

## 3. 移除中途门

- 删除 `LobbyLayout.Facility.MIDROUND`、对应讲台、告示牌和木框架（`CampBlueprint`），以及 `LobbyContext.ENTRY` 菜单、`openGate`、`gateButtons`、`confirm` 和靠近自动开菜单的逻辑。
- 不处理已建成营地中的旧中途门方块（当前无真实用户，不做迁移）。
- 文案同步：营地状态牌（“集结关闭 · 中途门开放”改为挑战中可站入集结区中途加入）、集结区告示牌、救场 Boss 栏与动作栏（“中途门加入”改为“集结区加入”）、规则讲台、怪物资格提示等。

## 4. 管理员旁观拉回提示

管理员旁观越界被拉回时（`PlayerProfiles.rejectAdministrativeSpectatorMove` → `ProtectionRuntime.correct`），补充动作栏原因提示，并播放 `block.vault.reject_rewarded_player`，限频避免刷屏。暂不抽象通用的禁区反馈框架。

## 5. 清除出生保护遗留代码

当前无真实用户，不考虑旧存档、旧配置或旧营地的兼容与迁移。

- `ProtectionRuntime`：删除人类单向离区、怪物不得入内、区外回退站位等仅服务出生保护的逻辑。保护改为按整个世界判定（只有营地所在世界受保护），圆形边界 `ProtectionBoundary` 一并删除。保留大厅保护、交互／伤害拦截与管理员旁观移动限制。
- `Participant.hasLeftProtection`、`Participant.leaveProtection`、`RoundEngine` 对应提议、`RoundSession.leaveProtection` 及 `Access.leaveProtection`。
- `RoundSnapshotCodec` 升到 schema 9，不再写该字段。实现偏差：读取 schema 2–8 时仍跳过这一个布尔值，因为编解码器对旧 schema 的其他字段仍保持支持，不跳过会让旧布局错位；实际旧快照还会因规则里的 `protectionRadius` 键在规则解码时被拒绝。
- `RulesConfig.protectionRadius` 配置键（会改变规则指纹；旧配置文件含该键时按未知字段拒绝）。
- `RoundWorldManifest` 中恒为空的出生出口 `exits` 及其校验。
- 同步删除或改写依赖上述内容的测试。
