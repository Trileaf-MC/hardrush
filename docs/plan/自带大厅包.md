# 模组自带多个大厅包

2026-11-27 需求方确定：除默认营地外，模组再自带几个风格不同的大厅包，服主装上模组就能在包库菜单里选用。状态：已实现（2026-11-27）。

## 做法

大厅包的分发、安装、回滚、以包为起点新建草稿都已经有了（[大厅包与工坊](大厅包与工坊.md) 第 10、12 节），缺的只是“自带的包怎么到服主的包库里”。所以不新增任何机制：

- 自带的包放在 jar 里，`hardrush/lobby/bundled.txt` 逐行列出“jar 内资源 → 包库里的文件名”。
- 启动时（`LobbyWorld` 的启动 IO 任务里，清理之后）`BundledPacks.release` 把包库目录 `hardrush/lobby/packs/` 里**还没有**的自带包复制进去。从那以后它们就是普通的包库文件。
- 默认营地也在清单里。这样服主换了别的大厅之后，随时能在菜单里换回默认营地，不只依赖“回到上一个大厅”。
- 首次启动仍然安装默认营地，不加配置项：换大厅就是进菜单点一下。

## 规则

- **不覆盖**：包库里已有同名文件就跳过，不管它是什么。文件名带版本号（`<id>-v<version>.hrlobby`），模组升级带来的新版本以新文件名出现，旧版本留在包库里，已安装的大厅不受影响。
- **删了会回来**：服主从包库删掉一个自带包，下次启动会再放回去。包库只是可选项的列表，不影响正在用的大厅。
- **不开后门**：释放出来的文件和别人分享的包走同一条读包、清洗、验收路径。
- 清单里某个包复制失败只记日志并跳过，不影响大厅启动。

## 把示例包打进模组

```bash
python3 scripts/lobby-pack.py bundle <id>
```

先构建 `lobby-packs/<id>`，没有错误才继续：把产物复制到 `platforms/mc263/src/main/resources/hardrush/lobby/bundled/`，并登记到 `bundled.txt`；同一个 id 之前随模组发的旧版本会被替换。复制进去的包和清单都要提交。升级一个自带包时，先改 `lobby.json` 的 `version`，再 `bundle`。

## 测试

- `BundledPacksTest`：清单里每个包都在 jar 里，文件名与它自己 `pack.json` 的 id、版本一致；释放时只补缺失的文件，不动服主已有的同名文件，第二次启动什么都不加。
- 自带包本身的可安装性由 `bundle` 前的无头构建保证（验收无错误、能读回）。
