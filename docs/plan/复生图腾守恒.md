# 复生图腾守恒

2026-11-23 与需求方讨论定稿。状态：已实现，待人工客户端验收（见[人工客户端测试](../人工客户端测试/2026-11-17-界面挡住动作栏的提示.md)第十二段）。本文修订 [复生图腾掉落](复生图腾掉落.md) 的若干条款，冲突处以本文为准，修订清单见第 6 节。

只在**极限模式**生效。普通模式没有复生图腾，行为不变。

## 背景

复生图腾也可以理解为"参赛资格"。场上的资格总量是：

> **Q = 存活人类数 + 全部复生图腾数**（人类和营地怪物手里的，加上地上已登记的）

现有机制大体能让 Q 守恒：怪物击杀人类，怪物 +1；人类击杀人类，掉 1 个；被逼出图腾也会放出 1 个；祭坛复生用 1 个图腾换回 1 名人类。守恒让怪物不会越来越多，人类也不会越来越少。

但下面这些情况会让 Q 永久减少：

| # | 场景 | 根因 |
| --- | --- | --- |
| A | 人类自然死亡：摔死、岩浆、溺水、原版怪物、饥饿，或者挨打已超过击杀归属窗口 | 没有击杀归属，"给怪物"和"掉落"两个分支都不走 |
| B | 自杀：被自己的 TNT、床、重生锚炸死 | `TotemDrop.qualifies` 排除了 `killer == victim` |
| C | 有归属但不合格：攻击种类不在名单里、击杀者已退出或被取消资格、攻击来自过期的出击序号 | `monsterKiller` 与 `qualifies` 都返回 false |
| D | 人类被人类打进虚空 | 旧规则"虚空不生成掉落"。怪物把人打进虚空却照样 +1，两边不对称 |
| E | 环境逼出图腾：拿着图腾摔落、被岩浆烧到原地复生 | `proposeTotemSave` 只处理怪物和人类两种归属 |
| F | 地上的图腾 5 分钟没人捡就过期 | `LooseTotem.LIFETIME_NANOS` |

另有一个公平性问题：旧规则 1.5 允许被逼出者捡回自己的图腾。远程对射时，A 被射到弹出图腾，转身就能捡回来，B 永远射不死 A。拿着图腾跳崖、泡岩浆同样会变成免费无敌。

## 1. 规则

### 1.1 总能放出 1 个

**每一条人类生命的结束，以及每一次原地复生，都恰好放出 1 个复生图腾。** 去向按以下顺序判定：

1. 怪物合格击杀或逼出（现有的 `monsterKiller`）：直接给怪物 +1，有怪物币的局照常召回祭坛。**不变。**
2. 人类合格击杀或逼出（现有的 `TotemDrop.qualifies`）：掉在地上。**不变**，称为"人类掉落"。
3. **其余一切情况**：掉在地上，称为"无主掉落"。包括 A、B、C，以及 E 中的环境逼出。

规则是一个全函数：以后新增死因或攻击种类时，默认落到第 3 档，不会再出现新的缺口。

- 阵亡者自己持有的图腾仍然原样带回营地（旧 1.1 不变）。这里放出的 1 个代表"结束的那条命"，与他持有多少图腾无关。
- 日落前（黄昏契约期间）的自然死亡同样放出。它与 PvP 无关，开局摔死也应该把资格留在场上。
- 带着通关结果的死亡批次不放出，因为本轮已经结束。导致本轮失败的批次同样不放出。

### 1.2 掉落位置

- 一般情况：死亡或弹出图腾时所在的位置。原地复生掉在被逼出者脚下（旧规则不变）。
- **虚空**（死亡位置低于世界最低高度）：人类掉落和无主掉落都改为生成在**开始下落的位置**，也就是原版 `ServerPlayer.startingToFallPosition`，见 2.3。会落到那附近最近的可站立地面上（横向 2 格、向下 3 格内）；附近没有地面，就放在下落起点本身。这个值为空时，生成在该维度的落地点：末地用黑曜石平台，其他维度用本轮出生点（在本轮主世界）。
  - **悬在虚空上空时**（尸体还没掉到最低高度以下就死了，比如在末地主岛外被箭射死、被龙撞飞），同样按下落起点处理：尸体正下方一直到世界底部都没有方块或液体时，就认为它悬在虚空上空。没有下落起点时，图腾生成在尸体处，掉下去后按 1.3 送回。
  - 旧规则"虚空不生成掉落、也不发公告"作废。
- 防火、无敌、发光、头顶名字、2 秒拾取延迟，都与旧 1.2 相同。

### 1.3 不再过期

- 已登记的掉落**本轮内永不过期**，本轮结束时清除。`LooseTotem.LIFETIME_NANOS` 和按时间剔除的逻辑一并删除。
- 登记上限（1024）和"挤掉最老的一条、永不抛异常"保留，作为防御性兜底。
- 已登记（或还在等待登记）的掉落物落到世界最低高度以下时，不删除：第一次送回它生成的位置；再掉一次，说明那里本身悬空，就送到该维度的落地点（同 1.2）。落地点通常是可站立的地面；末地平台被挖掉时，图腾会在平台和虚空之间往返，不会丢失，原版有玩家进入末地时会重建平台。生成位置记在掉落物自己身上，见 2.1。
- 送到落地点时，向本轮在场的人补发一行新坐标（1.5），因为它可能离原来公告的坐标很远，甚至换了维度。

### 1.4 拾取：所有权，开放给怪物

**谁能捡**：本轮在场、在线的人类，以及**出击中**的怪物玩家。

**所有权**：每个掉落记着它的"主人"，即放出它的那条命（`victim`、`victimLife`）。

> 拾取者是主人本人、仍是在场人类、而且生命序号等于 `victimLife` 时，拒绝拾取。

- 换句话说，只禁止**同一条人类生命**捡回自己的图腾。变成怪物以后，或者复生为新的人类以后，都能捡。
- 实际受影响的只有原地复生放出的掉落（人类逼出、环境逼出）。阵亡放出的掉落，那条人类生命已经结束，主人永远不会命中这条判定。
- 拒绝时动作栏提示一次（T1，每人每轮一次），例如「这是你用掉的复生图腾，自己捡不回来」，并播放失败音效。

**仍然捡不走**：营地里的怪物（本来就够不着）、原版生物（含悦灵、猪灵、狐狸、海豚）、漏斗、漏斗矿车。这些拦截全部保留，**只撤掉"怪物玩家不能捡"这一条**。

**怪物捡到时**：与怪物击杀人类的奖励完全一致，+1，有怪物币的局按 `revivalFirst` 召回祭坛。也就是"捡到图腾就回去复生"。

- 提示沿用怪物击杀奖励的原句。
- 怪物不需要背包空位，因为余额直接记账，召回后由投影补到营地背包里。
- 人类的背包规则不变（旧 1.3）。

### 1.5 告知

| 时机 | 档位 | 文案（草稿） | 说明 |
| --- | --- | --- | --- |
| 无主掉落（阵亡、环境逼出图腾） | T5 全服聊天 | **{阵亡者}** 留下的复生图腾在 {维度} **({x}, {y}, {z})** | **每次都发**，不是"每人每轮一次"，因为坐标本身就是信息。发给本轮在场、在线的人类和怪物（含阵亡者本人）。紧跟在原版死亡消息或原地复生公告（[死亡消息](死亡消息.md)）之后，不复述发生了什么，只补位置，所以阵亡和逼出用同一句。一批多人时，每个掉落各占一行。环境逼出图腾时**有意暴露一名活着的人类的位置**，是高风险时刻，规则书写明 |

- 坐标取掉落物生成时的方块坐标。维度写「主世界」「下界」「末地」。
- 只在掉落物已经生成并登记之后才发（与旧 1.8 相同）。
- 这条广播属于新增的 T5 事件，需求方已确认，同步写进 [玩家消息分级](玩家消息分级.md) 的 T5 白名单。

### 1.6 规则书与物品描述

- 「复生图腾」页按新规则改写：
  - 人类每结束一条命、每用掉一次图腾，都会放出 1 个复生图腾。怪物击杀或逼出的直接归怪物，其余掉在原地，人类和出击中的怪物都能捡，但放出它的那条命捡不回来。
  - 没有被人击杀或逼出时，掉落会公布坐标。这句覆盖意外死亡、自杀、环境逼出、攻击种类不合格、击杀者已退出等所有无主掉落。
- 地上掉落物的描述第二行：「出击中的怪物也能捡 · 放出它的那条命捡不回来」。
- 人类持有的图腾描述，第三行从「阵亡不掉落 · 不能丢弃或转赠」改为「阵亡不掉落 · 不能丢弃或放进容器」。营地怪物那一行同样去掉"转赠"。理由见 3.2：转移已经可以通过付出一条命来实现，不再对玩家承诺"不能转赠"。
- 被拦下丢弃时的提示「复生图腾不能丢弃或转赠」同样改为「……不能丢弃」。

## 2. 实现设计

### 2.1 core

**分类器**：用一个全函数替换"`qualifies` 合格就掉，否则查 `monsterKiller`"的写法。

```java
// TotemDrop
sealed interface Release {
    record ToMonster(UUID owner) implements Release {}
    record Dropped(LooseTotem.Source source, Optional<UUID> killer) implements Release {}
}
static Optional<Release> release(RoundSnapshot before, UUID victimId, Optional<CombatOrigin> killCredit)
```

- 判定顺序：`monsterKiller`（从 `RoundEngine` 移到 `TotemDrop`）合格时返回 `ToMonster`；`TotemDrop.qualifies` 合格时返回 `Dropped(HUMAN)`；其余返回 `Dropped(UNCLAIMED)`。
- 前提是 victim 为极限模式下的在场人类，不满足就不放出。死亡和原地复生共用这个函数。
- 平台在死亡或弹出图腾那一刻用它预判，引擎提交时用同一个函数核对，与现在 `qualifies` 的用法相同。

**`LooseTotem`**：

```java
LooseTotem(UUID victim, int victimLife, Source source, Optional<UUID> killer, long droppedAtChallengeNanos)
enum Source { HUMAN, UNCLAIMED }
boolean ownedBy(Participant taker)   // 所有权判定，见 1.4
```

- `killer` 改为 `Optional`，只有 `HUMAN` 来源才有。
- `source` 决定公告用哪一句。阵亡还是逼出由平台的待登记记录区分，不进快照。
- **坐标不进快照**：core 不依赖 Minecraft 的维度和坐标。生成位置写在掉落物的物品数据里（与掉落编号放在一起），虚空送回时读取；公告坐标取自平台在生成那一刻的记录。满检查点回档会同时还原世界和快照，所以两者始终一致。
- 删除 `LIFETIME_NANOS` 和 `expiredAt`，`liveLooseTotem` 改名为 `looseTotem`。`retainedLooseTotems` 只保留终局清空和上限挤出两项。
- 快照编码 `SCHEMA` 从 11 升到 12。第 10、11 版只有人类攻击才会登记掉落，所以旧条目读为 `HUMAN`，并保留原来的击杀者。

**提议**：

| 提议 | 变化 |
| --- | --- |
| `proposeDeathBatch` | 对每个在场人类的阵亡调用 `TotemDrop.release`：`ToMonster` 走 `rewardMonsterKill`（不变）；`Dropped` 登记 `dropToken`，平台没有给出编号（比如生成失败）时不登记 |
| `proposeTotemSave` | 同样改用 `TotemDrop.release`，所以环境逼出也会登记来源为 `UNCLAIMED` 的掉落。作废分支保持全函数、不抛异常 |
| `proposeLooseTotemPickup` | 拾取者放宽为"在场在线的人类，或在线的出击中怪物（`MONSTER_DEPLOYED`，出击序号一致）"。参数增加 `expectedDeploymentSequence`。所有权判定放在引擎里（`LooseTotem.ownedBy`），平台先预判一次并给出提示，所以不需要新的 `Refusal`。怪物拾取成功后走 `rewardMonsterKill` 的同一套逻辑（+1、`revivalFirst`） |

### 2.2 platform：掉落的生成

- `TotemDrops.prepare`（死亡）和 `prepareSave`（原地复生）改为按 `TotemDrop.release` 预判。只要结果是 `Dropped` 就生成实体，不再只看 `qualifies`。
- 位置由 `TotemDrops.place` 决定：一般在尸体处；死在世界最低高度以下或悬在虚空上空时，取下落起点（2.3），不再直接返回空。
- 公告：`settle` 按登记的 `source` 分组，阵亡还是逼出看平台待登记记录里的 `save`。人类掉落沿用旧公告；无主掉落每个条目发一行 T5，坐标取自待登记记录里的生成位置。
- 巡检：删除按时间过期删实体的分支。新增 `TotemVoidMixin`，拦截 `Entity.onBelowWorld`（`ItemEntity` 没有重写它）：还在等待登记或已登记的掉落物按 1.3 送回，其余照原版删除。

### 2.3 虚空位置：复用原版的下落起点

不新增每 tick 采样。原版 `ServerPlayer` 维护 `startingToFallPosition`：玩家开始下落时记下位置，着地后清空，原本供"高处坠落"类进度触发器使用。人掉进虚空时，这个值就是他离开地面的位置。

- **已查证**（26.3 服务端源码，按 [minecraft-knowledge](../../.agents/skills/minecraft-knowledge/SKILL.md)）：
  - 字段为 `private Vec3 startingToFallPosition`；
  - `ServerPlayer.tick()` 每 tick 调用 `trackStartFallingPosition()`：`fallDistance > 0` 且字段为空时，记下当时的 `position()`；
  - `resetFallDistance()` 把它清空（着地、进水、传送等）；
  - `die()` 不会清空它，所以 `AFTER_DEATH` 里仍然能读到。
- 平台用 `TotemFallStartAccessor` 读取这个字段。记下的是刚离开地面后第一 tick 的位置，可能已经在悬崖边外一点点，所以再找附近最近的可站立地面（1.2）。
- 鞘翅滑翔等情况下，下落距离可能被清零，字段为空，就退到落地点。

### 2.4 platform：拾取

- `TotemPickupMixin` 和 `TotemDrops.touch` 的资格判定加入出击中的怪物。原版生物、漏斗、漏斗矿车的拦截不动。
- 怪物各形态的背包都不检查空位，提交成功后直接删除实体。人类仍按旧 2.4 的流程，由投影补齐。
- 所有权拒绝的提示走 `Notices.firstInRound`，并配失败音效。

## 3. 滥用盘点与取舍

### 3.1 已经堵住的

| 场景 | 处理 |
| --- | --- |
| 远程对射时被逼出图腾，转身捡回，永远射不死 | 所有权：同一条生命捡不回 |
| 拿着图腾无限抵挡摔落、岩浆 | 同上。每次都实打实少 1 个，而且全服公布坐标 |
| 自杀换位置（自然死亡后祭坛复生，落到远处荒野） | 改版后会放出 1 个图腾给别人，换位置有了代价 |

### 3.2 接受的（不额外设防）

- **人类暗盟转移**：A 故意自杀或被逼出图腾，盟友 B 捡走。
  - 总量不变，只是转移。每次转移都要真的付出一条命，还要靠近、被广播，让怪物和其他人类有机会截胡。
  - 机制上无法区分串通和真打，硬堵会误伤正常玩法。
  - 相应地，规则书和物品描述不再承诺"不能转赠"（1.6）。
- **人类与怪物暗盟**：怪物反复逼出残血盟友的图腾，或者人类故意让图腾掉在怪物盟友身边。同样守恒，同样接受。
- **人类互杀刷图腾**：旧文档推演过，每轮净收益为 0。
- **怪物截胡人类掉落**：开放怪物拾取后，人类 PvP 打出的图腾可能被附近的怪物抢走。这是"鹬蚌相争"式的有意张力。
- **死在拿不到的地方**：比如下界岩浆海。图腾防火，会浮在岩浆上，有抗火手段就能拿，算作一种悬念。
- **"跑尸"：阵亡者变成怪物后，按坐标捡回自己那条命掉的图腾**（2026-11-23 评审提出，需求方此前已确认"跨身份、跨复生可以捡"）。
  - 后果：手里没有图腾的人类意外死亡后，可以出击、按公告跑过去捡起，有怪物币的局随即被召回复生。意外死亡的代价从"失去资格"变成"丢掉装备、跑一趟、和别人抢"。
  - 接受的理由：图腾留在场上本来就是本方案的目的。坐标是公开的，人类和其他怪物都会去抢，阵亡者并没有独占权；出击只能落在追猎目标附近，不能直接落到坐标上，跑过去有路程和风险。
  - 如果实战中发现意外死亡的代价太轻，可以把所有权改成"按玩家、整轮有效"（自己放出的，本轮都捡不回），总量仍然守恒，改动只在 `LooseTotem.ownedBy` 一处。
- **合格攻击名单对"给谁"的约束变弱**：怪物用不合格的方式杀人（比如推下悬崖后过了归属窗口），图腾成为无主掉落，它自己走过去也能捡。人类之间也一样，HUMAN 和 UNCLAIMED 的区别主要只剩"发不发坐标"。
  - 接受的理由：名单现在只决定"直接到手"还是"掉在地上、2 秒后谁先捡到算谁的"。不合格的击杀拿不到直接奖励，还要冒公开坐标、被别人截胡的风险，所以合格击杀仍然更划算。总量在任何情况下都守恒。

### 3.3 不处理的

- **最后一名人类阵亡（含自然死亡、同归于尽）**：没有怪物持有图腾时直接判负，即使地上还有掉落、怪物理论上能去捡，也不为此延长比赛。需求方确认。
- **退出本轮、被取消资格**：身上的图腾随人消失。参赛人数本身变了，资格总量跟着变是合理的。
- **残血时断线逃避阵亡**：另立 Issue「战斗中断线视为阵亡」，不在本次范围内。
