# 击杀奖励与身价投入

2026-11-27 与需求方讨论定稿，需求见 [issue #106](https://github.com/Trileaf-MC/hardrush/issues/106)。状态：已实现（2026-11-27），待人工客户端验收（[2026-11-27 场次](../人工客户端测试/2026-11-27-击杀奖励.md)）。

本文是实施方案，写给没有参与讨论的实现者：规则以 issue 为准，这里写清规则在代码里落到哪里、有哪些陷阱、怎样算完成。

## 0. 规则速览

- **身价** = 基础 10 级 + 投入 + 伤害，三者相加后封顶 30 级，单位是千分之一级。
  - 投入：本次出击实际支付的怪物币，每 5 币 +1 级。
  - 计入的投入：
    - 带上出击的商店商品；
    - 本次所穿宝库装备的钥匙；
    - 苦力怕解锁费；
    - 本角色能用的永久升级（拘魂袋），按实付的 1/10 计入，每次出击都计。
  - 不计入：复生补给；按星级白送的刷怪蛋和护甲。
  - 归返暂停后恢复出击时，已计入的部分不重复计；暂停期间新买的商品补算。
- **被玩家击杀时的掉落**（前提沿用 `MonsterRoles.recentlyHurtByOtherPlayer`）：
  1. 原版掉落：按当前形态的原版战利品表、以“被玩家击杀”结算。
  2. 经验与附魔书：不变。
  3. 铁锭：⌊身价整数等级 ÷ 7⌋。
  4. 炼药材料：按身价分档，见第 2.3 节。
- 没有其他玩家参与的死亡什么都不掉，和现状一致。
- **苦力怕自己引爆**而死时什么都不掉，即使引爆前被人类打过。这和原版苦力怕爆炸后不留掉落一致。被人类用打火石或火焰弹强行点燃的，仍算人类击杀。
- 怪物玩家打死怪物玩家照常发奖励，沿用原有设计。

### 评审后的裁决（2026-11-27）

- **苦力怕自爆**：被人类打过之后自己引爆，原本会按被玩家击杀发整份奖励。光是解锁费就让身价起步 18 级，零伤害也必掉书。需求方定为不给奖励，见上一条。
- **怪物互杀**：两只怪物可以互杀给人类送铁锭，但每次都要付出出击和 45 秒冷却的代价。需求方定为照常发奖励。
- **暂停期间买的永久升级**：恢复出击时不补算，到下一次全新出击才计入，最多差约 2.6 级。永久升级不是"带上出击的东西"，所以维持第 2.2 节的写法，不为此新增字段。
- **原版掉落**：遵守原版的 `doMobLoot`（`MOB_DROPS`）游戏规则。身价奖励是比赛奖励，不受这条规则影响。

## 1. 现状（2026-11-27 核对）

- `core/.../round/MonsterWorth.java`
  - 身价 = `worth.baseLevel` × 1000 + Σ`sortieDamage.weightedMilli` × `worth.levelsPerDamage`，再以 `worth.maxLevel` 封顶。
  - `experience`、`bookLevel` 都是纯函数。
- `core/.../round/MonsterWallet.java`：怪物的钱包。
  - `bought`：价格阶梯，记的是本次出击窗口内已买的次数。
  - `order`：已付款、等待下次出击的商品。
  - `active`：本次部署冻结、带上身的商品。
  - `gear` / `activeGear`：宝库开出的装备。
  - `sortieDamage`：伤害计入，一直保留到下一次全新部署才清空。
- 部署与结算的调用点：
  - 部署：`RoundEngine.deployMonster` 调用 `wallet.deploy(rules, role)`。
  - 从未落地的出击：`RoundEngine.neverLanded` 调用 `cancelDeploy()`。
  - 归返暂停：`park(body)`。
  - 出击结束：`keepUnspent()` / `endSortie()`。
  - 开宝库：`RoundEngine.proposeVaultOpen` 调用 `openVault(key, slot, roles, item)`。
- `platforms/mc263/.../monster/mixin/MonsterLivingMixin.noRoleLoot`：拦截 `LivingEntity.dropAllDeathLoot`，并且**整个取消原版掉落**。拦截后依次执行：
  1. `MonsterRoles.dropRoleEquipment(player, source)`：身上装备按 8.5% 掉落，背包物品落地。
  2. `MonsterWorthRewards.slain(player)`：经验喷泉与署名附魔书。
- 原版模型：`MonsterRoles.nativeModel(player)` 返回一个**不在世界里**的 `Mob`，类型由 `MonsterForm` 决定（ZOMBIE、DROWNED、SKELETON、STRAY、CREEPER）。`syncNativeContext(player)` 会把位置、着火、效果、装备同步到这个模型上。
- 规则快照：`RulesConfig` 校验时，只要出现任一 `worth.*` 键，就必须包含 `WORTH_DEFAULTS` 的全部键。`withEconomyDefaults` 会给待用规则补齐缺失的默认值。
- 快照编码：`RoundSnapshotCodec.SCHEMA = 18`。钱包由 `writeWallet` / `readWallet` 读写，`GearPiece` 也在其中读写。

## 2. 核心（`core`）

### 2.1 规则参数

在 `RulesConfig` 里新增一组默认值 `SPOILS_DEFAULTS`。不要并入 `WORTH_DEFAULTS`：并入后，旧存档里进行中的对局缺这几个键，会在校验时失败。

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `worth.coinsPerLevel` | 5 | 每多少枚怪物币投入换 1 级身价 |
| `worth.permanentPermille` | 100 | 永久升级按实付的千分之几计入 |
| `worth.levelsPerIron` | 7 | 每多少级身价掉 1 个铁锭 |

- 校验规则：
  - 三个键要么全有，要么全无。
  - 出现这三个键时，`WORTH_DEFAULTS` 也必须齐全。
  - `coinsPerLevel ≥ 1`，`levelsPerIron ≥ 1`，`0 ≤ permanentPermille ≤ 1000`。
  - 已有的“`worth.*` 必须是不超过 1000000 的整数”这条校验天然覆盖这三个键。
- `withEconomyDefaults`：在判断“是否已齐全”的 `allMatch` 里加上 `SPOILS_DEFAULTS`，并对它执行 `putIfAbsent`。不需要提升 `DEFAULTS_REVISION`。
- `MonsterWorth` 增加以下内容：
  - 三个常量：`COINS_PER_LEVEL`、`PERMANENT_PERMILLE`、`LEVELS_PER_IRON`；
  - `spoilsEnabled(rules)`：等于 `enabled(rules) && containsKey(COINS_PER_LEVEL)`。旧对局没有这组键时，没有投入、铁锭和药材，行为与现在完全一致。

### 2.2 投入记账（`MonsterWallet`）

#### 新增字段

- 钱包新增分量 `long sortieInvestment`，单位是**千分之一怪物币**。用这个单位，1/10 折算可以精确表示。
  - 必须 ≥ 0。
  - 生命周期和 `sortieDamage` 完全一样：全新部署时重置；`park`、`keepUnspent`、`endSortie` 都保留它，好让死亡结算时还能读到。
  - 现有的便捷构造器补 0，私有的 `with(...)` / `withParked(...)` 等原样带上这个字段。
- `GearPiece` 新增分量 `int paid`，表示开出这件装备的钥匙实付的币数。必须 ≥ 0，旧构造器补 0。
  - `openVault` 改为 `openVault(RulesConfig rules, ShopOffer key, GearSlot slot, Set<MonsterRole> roles, String item)`，`paid = MonsterCoins.price(rules, key, 0)`。
  - 钥匙一律按固定价出售（`ShopOffer.flatPrice()` 对钥匙恒为 true），所以价格与第几把无关。在代码里注明这个前提。

#### `deploy(rules, role)`

在现有逻辑之后计算本次部署的投入：

```text
fresh  = !hasParkedBody()
frozen = Σ 本次带上的商品 offer：MonsterCoins.refund(rules, offer, wallet.bought(offer), carried(offer)) × 1000
       + Σ 本次带上的装备 piece：piece.paid × 1000
once   = fresh 时：
           (role == CREEPER && creeperTicket && MonsterCoins.creeperPaid(rules) ? creeperUnlockPrice(rules) × 1000 : 0)
         + Σ 所有满足 offer.permanent() && offer.sellableTo(role) 的永久升级：
             MonsterCoins.refund(rules, offer, bought(offer), bought(offer)) × permanentPermille
         否则为 0
investment = (fresh ? 0 : 原 sortieInvestment) + frozen + once
```

- 只有 `MonsterWorth.spoilsEnabled(rules)` 时才计算，否则保持 0。
- 用 `refund(rules, offer, bought, count)` 求实付价是对的：带上身的商品永远是该商品最后买的那几件。
  - 已经部署过的商品不再在 `order` 里。
  - 退款从最新的一件开始退。
  - `endSortie` 只给仍在等待的商品保留阶梯。
  - 测试要覆盖这几种情形：
    - 暂停期间再买一件，第二件按翻倍价计入；
    - 带电苦力怕“未用掉”退回营地后再次出击，按第一次的价格计入。
- 复生补给对任何角色都 `sellableTo == false`，不会进入 `carried`，所以天然不计入。白送的刷怪蛋和护甲不经过钱包，也天然不计入。

#### 其他方法

- `cancelDeploy()` 改为 `cancelDeploy(RulesConfig rules)`。`RoundEngine.neverLanded` 需要把规则传进来，沿调用链补参数。
  - 没有暂停中的身体：投入清 0。
  - 有暂停中的身体：从原投入里减去用同样公式算出的 `frozen`。此时 `active`、`activeGear`、`bought` 都还是部署时的样子，要在把商品还回 `order` **之前**计算。
- `becameMonster`、`credit`、`spendCoins`、`buy`、`chooseRole`、`refund`、`openVault`、`creditDamage`、`unlockCreeper`、`useCreeperTicket`：都保留投入不变。

### 2.3 身价与奖励表

`MonsterWorth.milliLevels(rules, wallet)` 改为：

```text
base + damage                                           （现有逻辑，用 long 计算）
+ (spoilsEnabled ? wallet.sortieInvestment() / coinsPerLevel : 0)
→ min(·, maxLevel × 1000)
```

`/ coinsPerLevel` 之后直接就是千分之一级：5000 千分之一币 ÷ 5 = 1000 千分之一级。全程用 `Math.addExact` / `long` 计算，防止溢出。

**职责划分（结构调整）**：现在“掉多少”分散在核心的 `MonsterWorth` 和适配层的 `MonsterWorthRewards` 两处。调整后：

- `MonsterWorth` 只回答“这具身体值多少级”：`milliLevels`、`level`、`progress`、`spoilsEnabled` 以及参数常量。
- 新的 `MonsterSpoils` 回答“这具身体留下什么”，是**唯一的奖励表**，负责经验、附魔书等级、铁锭和药材。
  - `MonsterWorth.experience` 和 `MonsterWorth.bookLevel` 原样搬到 `MonsterSpoils`，改名为 `MonsterSpoils.experience` / `MonsterSpoils.bookLevel`，从 `MonsterWorth` 删除。
  - 调用方一并改过来：
    - `MonsterWorthRewards.showWorth`，经验条的总经验；
    - `LobbyRuntimeGameTest`；
    - `MonsterWorthTest`：经验和书的用例移到 `MonsterSpoilsTest`。
- 适配层 `MonsterWorthRewards` 只负责把 `Spoils` 变成世界里的东西：经验喷泉，以及书、铁锭和药材物品。它自己不再算任何数量或门槛。

以后调数值、加材料，只改 `MonsterSpoils` 和它的单元测试。

新增 `core/.../round/MonsterSpoils.java`（纯 Java，不依赖 Minecraft）：

```java
public final class MonsterSpoils {
    public enum Material { NETHER_WART, GLASS_BOTTLE, MAGMA_CREAM, GLISTERING_MELON_SLICE, GOLDEN_CARROT,
        RABBIT_FOOT, PUFFERFISH, FERMENTED_SPIDER_EYE, GHAST_TEAR, PHANTOM_MEMBRANE, BREEZE_ROD,
        GLOWSTONE_DUST, REDSTONE }
    public static final List<Material> COMMON = List.of(MAGMA_CREAM, GLISTERING_MELON_SLICE, GOLDEN_CARROT,
        RABBIT_FOOT, PUFFERFISH, FERMENTED_SPIDER_EYE);
    public static final List<Material> RARE = List.of(GHAST_TEAR, PHANTOM_MEMBRANE, BREEZE_ROD);
    public record Spoils(int experience, int bookLevel, int ironIngots, Map<Material, Integer> brewing) {}
    /** random.applyAsInt(bound) returns a uniform value in [0, bound). */
    public static Spoils roll(RulesConfig rules, int milliLevels, IntUnaryOperator random) { ... }
}
```

`roll` 的计算方式：

- `experience = MonsterSpoils.experience(rules, milliLevels)`，`bookLevel = MonsterSpoils.bookLevel(rules, milliLevels)`，这两个函数从 `MonsterWorth` 原样搬过来，数值不变。
- `!spoilsEnabled` 时，`ironIngots = 0`，`brewing` 为空。
- `ironIngots = level / levelsPerIron`，其中 `level = MonsterWorth.level(milliLevels)`。默认 7 级一个，10 级掉 1 个，14 级掉 2 个，28 级起掉 4 个。
- 药材档位写死在本类里，与 `maxLevel` 无关，30 级以上不再加档。**随机数的抽取顺序固定**如下，便于测试：
  1. `level ≥ 12`：地狱疣 +1，玻璃瓶 +3。
  2. `level ≥ 18`：`COMMON[random(6)]` +1。
  3. `level ≥ 24`：先抽 `RARE[random(3)]` +1；再用 `random(2)` 选荧石粉（0）或红石（1），数量为 `1 + random(2)`。
  4. `level ≥ 30`：地狱疣 +1，玻璃瓶 +3，再抽一次 `COMMON[random(6)]` +1。
- `brewing` 用 `EnumMap` 合并相同材料，并包成不可变的 Map，按枚举顺序迭代。
- 在类注释里写明选材原则和禁止清单（见 issue），提醒以后加材料的人不要破坏它。

### 2.4 快照编码

- `SCHEMA` 改为 19。
- 写入：钱包最后追加 `writeLong(sortieInvestment)`；每个 `GearPiece` 在 item 之后追加 `writeInt(paid)`。
- 读取：`schema >= 19` 才读这两个值，否则补 0。注意 `GearPiece` 的读取在循环里，`schema` 要传进去。
- 已有快照用例要补一个 schema 18 的样本：解码后投入为 0、`paid` 为 0。仿照现有的旧 schema 用例写。

## 3. 适配层（`platforms/mc263`）

### 3.1 统一的击杀奖励入口

`MonsterLivingMixin.noRoleLoot` 改为依次执行：

```java
MonsterRoles.dropRoleEquipment(player, source);
MonsterWorthRewards.slain(player, source);
callback.cancel();
```

`MonsterWorthRewards.slain(ServerPlayer player, DamageSource source)`：

1. `if (!MonsterRoles.recentlyHurtByOtherPlayer(player)) return;`
2. `MonsterNativeLoot.drop(player, source)`：原版掉落，**不依赖身价是否启用**。
3. 读取身价和规则；任何一个为空就返回，和现在一样。
4. `var spoils = MonsterSpoils.roll(rules, milli, bound -> player.getRandom().nextInt(bound));`
5. 依次处理：
   - 经验喷泉，现有逻辑；
   - 署名书：`bookLevel > 0` 时生成，现有逻辑；
   - 铁锭：`ironIngots > 0` 时生成 `new ItemStack(Items.IRON_INGOT, ironIngots)`；
   - 药材：每种材料生成一叠。

   物品都用 `player.spawnAtLocation(level, stack)` 生成。

材料到物品的映射写成 `switch`，放在 `MonsterWorthRewards`，或者新建一个包内工具类。用 switch 是为了让编译器检查有没有漏掉的枚举值：

- `NETHER_WART → Items.NETHER_WART`，`GLASS_BOTTLE → Items.GLASS_BOTTLE`，`MAGMA_CREAM → Items.MAGMA_CREAM`
- `GLISTERING_MELON_SLICE → Items.GLISTERING_MELON_SLICE`，`GOLDEN_CARROT → Items.GOLDEN_CARROT`
- `RABBIT_FOOT → Items.RABBIT_FOOT`，`PUFFERFISH → Items.PUFFERFISH`，`FERMENTED_SPIDER_EYE → Items.FERMENTED_SPIDER_EYE`
- `GHAST_TEAR → Items.GHAST_TEAR`，`PHANTOM_MEMBRANE → Items.PHANTOM_MEMBRANE`，`BREEZE_ROD → Items.BREEZE_ROD`
- `GLOWSTONE_DUST → Items.GLOWSTONE_DUST`，`REDSTONE → Items.REDSTONE`

### 3.2 原版掉落（新文件 `monster/MonsterNativeLoot.java`）

- 照抄 26.3 `LivingEntity.dropFromLootTable(ServerLevel, DamageSource, boolean)` 构造 `LootParams` 的方式。实现前必须先用 minecraft-knowledge 读它的源码，确认参数集（`LootContextParamSets.ENTITY`）和每个参数名：

  ```bash
  python3 .agents/skills/minecraft-knowledge/scripts/mc-knowledge.py --format compact source LivingEntity --member dropFromLootTable
  ```

  各参数的取值：

  | 参数 | 取值 | 说明 |
  | --- | --- | --- |
  | `THIS_ENTITY` | 原版模型 `MonsterRoles.nativeModel(player)` | 原版条件要看“这只怪”本身，例如僵尸的 `is_on_fire` 会让土豆变成烤土豆。传入之前调用 `MonsterRoles.syncNativeContext(player)` |
  | `ORIGIN` | `player.position()` | 模型不在世界里，位置以玩家为准 |
  | `DAMAGE_SOURCE` | `source` | — |
  | `ATTACKING_ENTITY` / `DIRECT_ATTACKING_ENTITY` | `source.getEntity()` / `source.getDirectEntity()` | 可选参数；抢夺附魔经由它们按原版生效 |
  | `LAST_DAMAGE_PLAYER` | `player.getLastHurtByPlayer()` 指向的那名人类 | 加上运气 `withLuck(那名人类.getLuck())`。`killed_by_player` 条件靠这个参数成立 |

- 战利品表：`model.getLootTable()`，返回 `Optional<ResourceKey<LootTable>>`。为空就什么也不做。
- 战利品表的种子用 `model.getLootTableSeed()`。物品用 `player.spawnAtLocation(level, stack)` 生成，**不要**用模型生成，因为模型不在世界里。
- 方法里开一个包内可见的重载：可以传入固定种子，只返回物品列表、不生成实体。gametest 要用它做确定性断言。
- 不要再给原版掉落加身价或抢夺加成，只按原版结算。
- 唱片：苦力怕被骷髅射死才掉唱片，条件要求击杀者是原版骷髅实体。怪物玩家化身的骷髅是 `ServerPlayer`，不满足条件，所以不掉；被原版骷髅射死的苦力怕玩家照常掉。两种情况都和原版一致，不必处理。

### 3.3 其他

- `RoundEngine.proposeVaultOpen` 调用 `openVault` 时传入 `before.rules()`。
- `LobbyRuntime` 的暂存提示、`MonsterWorthRewards.showWorth`（经验条）都读 `MonsterWorth.milliLevels`，投入会自动反映出来，不用改。

## 4. 测试

### 4.1 核心单元测试（`./gradlew :core:test --offline --console=plain`）

**`MonsterWorthTest`**

- 默认规则下 `spoilsEnabled` 为真。去掉 `worth.coinsPerLevel` 等三个键的规则下为假，此时投入不计、铁锭和药材为空。
- 身价组成：
  - 投入 25 000 千分之一币 → +5 级；
  - 投入、伤害、基础三者相加后封顶 30 级；

**钱包投入（新建 `MonsterInvestmentTest`，或并入 `MonsterCoinsTest`）**
