# 管理员命令与面板

2026-11-24 与需求方讨论定稿。状态：已实现，待人工客户端验收（面板部分）。

## 背景

管理员需要在比赛中途调整细节：给某人补发复生图腾或怪物币、提前结束冷却或保护、推进阶段、暂停比赛。开发调试时也常要跳过等待，比如提前结束某人的「初入荒野」，好测试追猎。

已有的 `/hardrush admin` 只能开局、中止、给复生次数、取消资格，而且每条都必须填原因。原版 `/give` 给的图腾和绿宝石不进账本，会破坏[复生图腾守恒](复生图腾守恒.md)，所以这些调整必须走专用命令。

## 1. 原则

- **命令和面板一一对应。** 面板上的每个按钮都调用同一个操作入口，并重新检查权限。控制台和命令方块只能用命令。
- **原因可选。** 所有管理命令的原因都放在最后，可以不填；不填时审计里记为“管理员操作”。
- **成绩分级。** 可能改变胜负的操作会把本轮标成“有待管理员核实”（`timingUncertain`），也就是暂时不进排行榜，需要 4 级管理员复核（`validate`）后才转正。其他操作只写审计。
- **公开透明。** 影响胜负的调整，除了告诉当事人，还会给本轮其他在场的参赛者发一行简短提示，避免“偷偷照顾朋友”的猜疑。
- **不改规则快照。** 每轮的规则在开局时冻结，带指纹，用于排行榜分组。这次只调整“本轮正在走的计时器”，不提供修改下轮规则的命令。

## 2. 命令

全部挂在 `/hardrush admin` 下，权限为 3 级（复核成绩为 4 级）。`<目标>` 可以写本轮玩家名（会自动补全）或 UUID，也可以写分组关键字 `all-humans`、`all-monsters`、`all-players`（玩家名不能含连字符，所以不会和真名冲突）。分组只作用于其中符合条件的人；全部不符合时，整条命令拒绝。

| 命令 | 允许的时机与对象 | 标存疑 | 公告 |
|---|---|---|---|
| `give <目标> totem <n> [原因]` | 极限模式，挑战中或救场中；已参赛的人类或怪物 | 是 | 是 |
| `take <目标> totem <n> [原因]` | 同上；超过现有数量时拒绝，不会扣到 0 为止 | 是 | 是 |
| `give <目标> coins <n> [原因]` | 开了经济的极限局；只对怪物 | 是 | 是 |
| `take <目标> coins <n> [原因]` | 同上；超过现有数量时拒绝 | 是 | 是 |
| `cooldown <目标> clear [原因]` | 挑战中或救场中，对象是怪物，清零出击冷却 | 是 | 是 |
| `cooldown <目标> <秒> [原因]` | 同上，设成指定秒数 | 是 | 是 |
| `unlock <目标> all [原因]` / `unlock <目标> <人类> [原因]` | 清除怪物的击败锁定：全部，或只清对某个人类的 | 是 | 是 |
| `shelter <目标> end [原因]` | 结束初入荒野；同时清掉祭坛复生的“图腾之力”效果 | 是 | 是 |
| `timer <秒> [原因]` | 把当前阶段的剩余时间设为指定值；只对倒计时、结算或庆祝展示、救场有效 | 仅救场 | 仅救场 |
| `skip [原因]` | 倒计时中：立即开局。结算或庆祝中：立即开始下一轮。其他阶段拒绝并说明原因；挑战中会提示中止请用 `abort` | 否 | 否 |
| `start [原因]` | 已有；等待或倒计时中立即开局，只带已就绪的人 | 否（原来为“是”） | 否 |
| `pause [原因]` / `resume [原因]` | 挑战中或救场中 | 是 | 全服 |
| `pull <玩家>` | 把大厅里的人送进集结区，之后走正常的准备或中途加入流程 | 否 | 否 |
| `disqualify <玩家> [原因]` / `withdraw <玩家> [原因]` | 已有，原因改为可选 | 是 | 否 |
| `validate <轮次> [原因]` | 已有，4 级；面板上的“复核成绩”调用它 | — | 否 |

`grant-revival` 由 `give … totem` 取代。另外删掉 `/hardrush config next-mode` 和 `/hardrush retry-world` 这两个与 admin 子树重复的入口，统一用 `/hardrush admin next-mode`、`/hardrush admin retry-world`。

### 2.1 细节

- **`start` 不再标存疑。** 开局前少等几秒，不影响挑战用时。
- **`pull` 只是传送。** 把玩家放到集结区里的“恢复就绪”落点（`Landing.RESTORE_READY`），后面完全复用正常流程：开局前站进去就是准备，挑战中站满 4 秒就是中途加入（有初入荒野）。所以它不改任何状态，也不标存疑。玩家必须在线、在营地、此时集结区开放，并且本人可以参赛。
- **`take … totem`。** 扣掉的是账本里的次数，背包里的图腾由投影（`TotemProjection`）自动同步。救场中扣光所有怪物的图腾，并且已经没有人类时，本轮按失败结算，和正常走到这一步的规则一致。
- **`timer` 设到 0。** 由下一次周期结算推进阶段：倒计时 0 秒即开局，展示 0 秒即开始轮换，救场 0 秒即失败。
- **`shelter end`。** 初入荒野是按“这条命在人类状态下累计的时间”推算的，不是倒计时，所以给参赛者加一个“已解除保护”标记，只对第一条命有意义。图腾之力只清除祭坛加持的那组效果（生命恢复 II、伤害吸收 IV，以及与它们同时存在的抗火）。

### 2.2 暂停

只冻结 HardRush 自己的计时，原版世界照常运行（生物、饥饿、昼夜都不停）。

- 冻结的计时：挑战用时、救场倒计时、出击冷却、击败锁定、初入荒野。
- 不冻结的计时：怪物技能冷却（按真实时间记）、循迹和挖掘这类几秒的引导。
- 暂停期间怪物不能出击，也不能从营地追猎。其他行动照常，例如祭坛复生、中途加入、购物。
- 本轮离开挑战阶段（结算、中止）时，暂停自动解除。正常停服重启后，暂停状态会保留。
- 暂停和继续都会全服广播并显示标题。TAB 栏显示“计时暂停 · 管理员暂停”。

## 3. 面板

输入 `/hardrush admin` 不带参数，打开原版对话框（Dialog），原版客户端可以直接使用。每次点击都先重新检查权限和当前状态；操作完成后面板自动刷新，结果同时发到聊天栏。

- **主面板**：显示轮次、阶段、剩余时间、本轮模式、是否暂停、成绩是否存疑。
  - 按钮：立即开局、跳过等待、暂停或继续、设定剩余时间、玩家、复核成绩（只有 4 级可见）、刷新、关闭。
  - 不适用的按钮不显示。
- **设定剩余时间**：0–600 秒的滑块，加上可选的原因输入框。
- **玩家列表**：本轮每个参赛者一个按钮，标注身份（人类、怪物、出击中、大厅等）。
- **玩家详情**：显示身份、第几条命、复生图腾、怪物币、出击冷却、击败锁定、初入荒野剩余时间。
  - 输入：数量滑块（1–64）和原因输入框。
  - 按钮按适用情况显示：发图腾、扣图腾、发币、扣币、清出击冷却、清击败锁定、结束保护、拉入集结区、取消资格（需要再点一次确认）、返回。
- **复核成绩**：列出最近有冠军、但还没进排行榜的通关轮次。点击后执行 `validate`。冠军无法核实的轮次只能用 `correct` 命令修正，面板会说明这一点。

## 5. 审计

每条操作写一条 `AdminAudit`。动作名：`REVIVAL_ADJUST`、`COINS_ADJUST`、`DEPLOY_COOLDOWN`、`HUNT_UNLOCK`、`SHELTER_END`、`PHASE_TIMER`、`PAUSE`、`RESUME`、`START`。

- 修改前和修改后的值记录轮次、版本、阶段、是否存疑、规则指纹，以及当事人相关字段（图腾数、怪物币、冷却、锁定、保护标记）。
- `pull` 不改状态，只发给在线管理员一行提示。

## 6. 数据格式

轮次快照升到第 16 版（第 15 版是同期合入的个人追猎档位），追加两段数据：

- `adminPaused`：一个布尔值。
- 解除了初入荒野的参赛者 UUID 列表。

旧版快照读出来时视为未暂停、未解除。
