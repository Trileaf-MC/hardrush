# 遗落之地：祭坛复生后指回上次倒下的地方

2026-11-23 与需求方讨论定稿。状态：已实现，待人工客户端验收（[2026-11-17 场次](../人工客户端测试/2026-11-17-界面挡住动作栏的提示.md)第十段）。

## 背景

人类阵亡时按原版把身上的东西掉在原地。祭坛复生后，他会空手落在远方荒野，不知道自己上次倒在哪、离这里多远。原版里，掉落物只在所在区块被加载时才计时（`ItemEntity.tick` 里 `age++`，满 6000 tick 消失）。没人守着的地方，区块卸载后遗物会一直留着，所以“回去捡遗物”是一条真实可行的路线。

需求方在三个方案里选了“原版追溯指针”：

- 只在聊天栏提示一次：距离不会更新，弃用。
- 只用追溯指针：选用。
- 追溯指针再加一条聊天提示：不需要，弃用。

## 规则

- **谁有**：从祭坛复生、上一条命是在本轮正式世界里阵亡的人类（死亡已被回合捕获）。只在极限模式会发生，因为普通模式没有祭坛复生。
- **物品**：原版追溯指针，名为“遗落之地”。描述写“指向你上次倒下的地方”和“走到 **8** 格内、阵亡或丢出时消失”。
- **指针**：交给原版客户端处理。26.3 客户端 `CompassAngleState.CompassTarget.RECOVERY` 读的是持有者自己的 `lastDeathLocation`，维度不同时乱转。复生传送进正式世界之前，服务端把上一条人类命的死亡位置写回 `lastDeathLocation`；这次跨维度传送会发 `ClientboundRespawnPacket`，它的 `CommonPlayerSpawnInfo` 会带上这个值。
  - 不能直接沿用原版记录：变成怪物出击后如果再死，原版会把这个位置覆盖掉。所以人类阵亡时由我们自己记下维度和方块坐标。没有记录时写空，免得指向怪物那条命的死亡点。
- **手持提示**：沿用[手持物品提示](手持物品提示.md)，在动作栏显示：
  - 同一维度：`主世界 x y z · 距离 N 格`，距离按水平距离计算，边走边更新；
  - 不同维度：`下界 x y z · 不在当前维度`。
  - 不换算下界坐标（×8），因为下界的东西只能回下界去捡。
- **消失**：
  - 走到死亡点 8 格内（三维距离），动作栏提示“回到了遗落之地 · 追溯指针已消散”；
  - 再次阵亡时，不随尸体掉落；
  - 丢出时直接消失（`ServerPlayer.drop` 入口），不会补发；
  - 换了一条命、换了一轮，或者在其他玩家的背包里时，每 tick 收回。
  - 放进箱子不会失效：本人取回仍然可用；别人拿到手里会被收回。
  - 落地时如果已经在 8 格内，就不发放。

## 实现

- `revival.FallenCompass`：
  - `died` 在 `AFTER_DEATH` 捕获人类死亡时记下位置；
  - `target` 供 `PlayerProfiles.revive` 在传送前写入 `lastDeathLocation`；
  - `tick` 负责发放一次和收回；
  - `heldHint` 提供手持提示。
- 物品的自定义数据里存着主人、轮次、生命序号和目标位置，所以已经发出的指针在重连或重启后仍然可用。只有“阵亡到复生”之间的那条记录存在内存里：这段时间内重启，这次复生就拿不到指针。这种情况很少，可以接受，与图腾之力庇护的落地记录一致。
- 规则书不加说明：页面已经到了长度上限，物品名、描述和手持提示足够让玩家看懂。
