# 悬赏改版：威胁值、相对星级与庭院展示

2026-11-23 与需求方讨论定稿。状态：方案已定，已经过一轮对抗性评审（裁决见文末），需求方已确认评审带来的调整，已实现（2026-11-23），待人工客户端验收（[2026-11-17 场次](../人工客户端测试/2026-11-17-界面挡住动作栏的提示.md)第九段）。

## 背景

怪物玩家倾向于“柿子挑软的捏”：集中追猎弱小的人类，回避最强的人类，造成两极分化。现有悬赏有两个问题：

1. 只靠目标模型名字后面的“悬赏 ×1.75”展示，不显眼，怪物在庭院里看不出谁最值得追。
2. 倍率 = 1 + 维度加成 + 本条命存活加成（`MonsterCoins.bountyPermille`），太笼统，强者和弱者常常倍率相同。

需求方明确：**悬赏不碰复生**。击杀给复生的规则不变，不做头号悬赏额外奖励、协助分成或弱者保护（刚复生的保护由需求方在其他地方协调）。悬赏的职责是：

- 把人类之间的实力差距直接暴露给怪物；
- 打高悬赏的人类，怪物币与身价涨得更快（沿用现有“倍率乘伤害计入值”的通道）。

## 1. 威胁值

每名人类每条命一个威胁值，**死亡清零**，复生的新命从 0 开始；图腾救命不换命，威胁值保留。只在极限模式且启用怪物币的轮次（`MonsterCoins.enabled`）生效，普通模式完全不受影响（包括不撤销进度）。只计下面两类来源；存活时间、所在维度、击杀自然生成的怪物都**不计入**。

### 1.1 战斗

| 事件 | 分值 |
| --- | --- |
| 击杀一名怪物玩家 | +3 |
| 被怪物玩家从营地发起追猎 | +1 |

战斗分值刻意压低，威胁值主要由进度决定。

- **击杀**：怪物玩家出击中死亡，原版击杀归属（死亡时的 kill credit）是这名人类，且击杀者此刻仍是在场人类、未在同一死亡批次中死亡。出击已被更早的提交结算（如击杀召回）后才到达的死亡不再计分。
- **被追猎**：怪物在营地点他的目标模型、出击被核心接受（`proposePersonalHunt`）时 +1，不论结果如何。恢复暂存的出击也是从营地发起，同样计入；野外循迹（追迹罗盘）不计入。出击在真正开始前被补偿取消（`proposeMonsterDeployCancelled`，很少发生）时不退回。
  - 刷分风险：怪物可以反复出击再归返来抬高目标的星级，但每次都受出击冷却限制，每次只 +1，而进度分值动辄 4–10，影响有限，接受。

### 1.2 进度里程碑（非线性）

| 原版进度 | 分值 |
| --- | --- |
| 石器时代、获得升级、不吃这套 | 1 |
| 来硬的、整装上阵、这不是铁镐么、热腾腾的、冰桶挑战 | 2 |
| 附魔师、本地酿造厂 | 3 |
| 钻石！、阴森的要塞（下界要塞） | 4 |
| 勇往直下（进入下界） | 5 |
| 用钻石包裹我、与火共舞（烈焰棒） | 6 |
| 隔墙有眼（跟随末影之眼找到末地要塞） | 8 |
| 结束了？（进入末地） | 10 |

- 表外进度记 0。进度 ID 与中文名在实现时按 `.agents/skills/minecraft-knowledge/SKILL.md` 核实。
- 每条命独立：**人类复生时撤销该玩家带 display 的原版进度**（配方不动），新命重新达成时会再弹原版提示、在聊天栏再广播一次，并重新计分。
  - 撤销必须发生在复生快照写入之前，在线复生和离线复生（`proposeAdmissionRevival`）两条路径都要覆盖，否则重连时会从快照恢复旧进度，恢复的进度不再触发 award，新命永远拿不到这部分分。
  - 这改变了 `PlayerProfiles.revive` “复生保留本轮进度”的约定，相应 gametest 一并更新。
  - 战绩进度数已按 `INSERT OR IGNORE` 并集入库（`SqliteRecordIndex`），撤销不会缩水；只补测试，不改持久化。
- 同一条命内同一项进度只计一次（威胁状态里记录已计入的进度 ID，重启后不重复计分）。

## 2. 相对星级与倍率

- 比较范围：当前**在线**的人类（`HUMAN_ACTIVE`）。离线的人类保留自己的威胁值但不参与比较，避免一个追不了的人压低所有人的星级、或成为追不了的头号悬赏。
- 比值 r = 本人威胁值 ÷ max(最高威胁值, 10)，下限 10 让开局几分的差距不被放大。星级按阈值表：r = 1（即第一名）为 ★5，r ≥ 0.7 为 ★4，r ≥ 0.45 为 ★3，r ≥ 0.2 为 ★2，其余 ★1。
- 倍率：★1 ×1、★2 ×1.25、★3 ×1.5、★4 ×2、★5 ×2.5。
- **头号悬赏**：威胁值最高且 ≥ 10 的人类（即 5 星中的第一名）；并列最高时都算。
- 倍率在**命中那一刻**确定：适配层在记录伤害时按当时的排名算出倍率，写进 `DamageCoins`（取代现有的 `dimension` 字段），核心按它计价。这样致命一击即使在人类死亡、威胁值清零之后才落账，也按死亡前的星级算。
- 现有的 `coin.bounty.*`、`coin.survival.*` 配置删除。星级阈值、倍率和战斗分值放在新的 `bounty.` 前缀下（规则快照中的不可变数值，同步更新 `RulesConfig` 的校验）；进度分值是固定的代码表。

## 3. 怪物侧展示

### 3.1 营地庭院的目标模型（位置保持稳定，只做高亮）

- **所有可追猎目标的模型都穿上对应人类的实时装备**：头、胸、腿、脚、主手、副手，保留附魔光效。装备变化时只发装备包增量更新，不重建整页模型；比较装备时忽略耐久，更新做节流。
- **名字行**：`名字 · ★★★☆☆ · 下界 · 绯红森林`；星级颜色按档位：1–2 星白、3 星黄、4 星金、5 星红。
- **头号悬赏的模型**：头部显示不祥旗帜（代替头盔显示，袭击队长的标志），发光轮廓（原版默认白色，不为染色另发队伍包），名字金色并标注“头号悬赏”。旗帜能否在 Mannequin 头上渲染尚未核实，列入人工客户端测试；不能渲染时退回到只用发光和金色名字。
- 非可追猎状态（离线、阵亡、复生中等）的模型不显示星级，保持现状。

### 3.2 提醒

- 头号悬赏**易主**时，提醒营地里的怪物玩家：`X 成为头号悬赏`，对这些玩家播放袭击号角。同一名人类成为头号悬赏的提醒至少间隔 60 秒。
- 出击后的追猎 Boss 栏显示目标的星级。

## 4. 人类侧展示

### 4.1 TAB 栏

只显示自己的悬赏：`你的悬赏 ★★★★☆`；是头号悬赏时 `你的悬赏 ★★★★★ · 头号悬赏`。

### 4.2 关键变化提示（动作栏）

| 事件 | 提示 |
| --- | --- |
| 成为头号悬赏 | `你成为了头号悬赏，怪物会优先盯上你`，配一声不祥音效（实现时核实原版音效） |
| 失去头号悬赏 | `你不再是头号悬赏`，无音效 |
| 从低于 4 星升到 4 星或 5 星 | 每次进入都提示，如 `悬赏升至 ★★★★☆`；由自己的行为引起时带原因，如 `击杀了怪物 · 悬赏升至 ★★★★☆` |
| 升到 2 星或 3 星 | 同一档在一条命里只提示一次 |

- 星级下降不提示，只更新 TAB 栏。
- 防抖：同一档提示至少间隔 30 秒。
- 同一时刻既成为头号悬赏又升到 5 星时，只发头号悬赏那条。

## 5. 实现要点

**core**
- 新增独立的嵌套 record `HumanThreat(lifeSequence, monsterKills, huntsSurvived, milestones)`，挂在 `Participant`、随 `RoundSnapshotCodec` 持久化。`lifeSequence` 与当前命不一致就视为 0，不在各条转换路径里手动清零。
- 新增纯函数：威胁值、星级、头号悬赏判定、星级倍率，写单元测试。
- `RoundEngine`：
  - `proposeDeathBatch`：新增 `humanKiller` 归属解析（`monsterKiller` 会排除人类发起者），击杀者 +3。
  - `proposePersonalHunt`：目标人类 +1（`PersonalHuntRequest` 已校验目标与命号）。
  - 新增进度里程碑事件，带人类的 `lifeSequence` 校验，防止旧命的进度记到新命上。
  - `creditDamageCoins` 使用 `DamageCoins` 里命中时的倍率。
- `RuleBookText` 中怪物币一页的悬赏说明更新。

**platforms/mc263**
- 进度：`PlayerAdvancementIsolationMixin` 的 award 返回处上报里程碑；人类复生时撤销原版进度（`PlayerProfiles` 复生身体流程）；确认 `ProgressTracker` / 战绩持久化按并集保存，撤销后不缩水，服务器重启后也不缩水。
- `LobbyProjections` 先做结构重构，把模型的“身份”和“装饰”分开（见 5.1）。
- `LobbyRuntime.updateDisplays`：每个 tick 只算一次所有目标的身份和装饰，再对每个观察者做差异比较，不再为每个观察者重复读取装备和群系。

### 5.1 目标模型的两层结构

现状：`LobbyRuntime.updateDisplays` 只要新旧 `targets` 不相等，就调用 `LobbyProjections.show`，删掉整页模型再重建。群系换了、悬赏档位变了都会重建；如果把装备也放进去，耐久每掉一点就重建一次。

改为两层：

| 层 | 内容 | 变化时 |
| --- | --- | --- |
| 身份 | 展位顺序（目标 UUID）、命号、状态（可追猎、离线、阵亡、复生中、暂不可追猎） | 重建本页模型（和现在一样），点击判定只依赖这一层 |
| 装饰 | 名字行（星级、维度与群系、状态文字）、是否发光、是否头号悬赏、六个装备栏 | 在原模型上原地更新：名字和发光发 `SetEntityData`，装备只发变化的栏位的 `SetEquipment` |

- 每个模型记住上次发给这个连接的装饰，只发有差异的部分。新建模型（建页、翻页、身份变化）时直接带上完整装饰。
- 装备转成“展示用物品”后再比较：复制一份，数量设为 1，去掉耐久，保留附魔光效等外观。耐久变化因此不会触发更新，盔甲上的耐久条本来也不在模型上显示。
- 装饰按节流计算：名字行和星级跟随状态实时更新；装备每 10 tick 读取一次。
- 头号悬赏的头部旗帜属于装饰：头盔栏发送的是不祥旗帜而不是真实头盔。
- `LobbyRuntime.bounty` 改为读取核心星级。
- `TabListRuntime`：按玩家追加自己的悬赏行。
- `HuntBossBars`：标题加星级。
- 新增人类提示与营地怪物提示的状态跟踪（每人上次星级、上次提示时间、头号悬赏集合），只在内存中保存，重启后以当前状态为基准，不补发。

**文档**
- `docs/plan/玩家消息文案.md` 增补新文案；README 的悬赏描述更新。
- 人工客户端测试：模型装备与旗帜显示、发光、TAB 行、提示与音效，追加到最新的待测试场次。

## 评审记录（2026-11-23）

一轮独立对抗性评审，逐条裁决：

| 意见 | 裁决 |
| --- | --- |
| 致命一击落账时目标星级已清零 | 采纳：倍率在命中时确定并随伤害提交 |
| 模型页每次变化都整页重建，装备会让它每 tick 重建 | 采纳：先把 `Target` 拆成身份和装饰两层（结构重构） |
| 撑过追猎漏算、重复算、可被刷 | 需求方改为更简单的规则：被从营地发起追猎 +1，击杀怪物玩家 +3，问题随之消失 |
| 撤销进度违反现有约定并有恢复竞态 | 采纳：撤销在快照写入之前，覆盖两条复生路径，更新 gametest |
| 战绩并集已由数据库保证 | 采纳：只补测试 |
| 离线人类扭曲排名 | 采纳：只在在线人类中比较 |
| 威胁值绑定命号、做成嵌套 record | 采纳；图腾救命保留威胁值 |
| 击杀计分需要新的归属解析 | 采纳：新增 `humanKiller`；已结算出击的迟到死亡不计分 |
| 模式门控 | 采纳：仅极限模式且启用怪物币的轮次 |
| 向上取整让 4–5 星扎堆 | 采纳：改用阈值表，★5 只给第一名 |
| 分值配置前缀 | 采纳：`bounty.` 前缀加固定的进度代码表 |
| 金色发光需要队伍包 | 采纳为白色发光，不发队伍包 |
| 旗帜渲染未核实 | 列入人工测试，准备退路 |
| 进度名混淆 | 采纳：表中写明下界要塞和末地要塞 |
| 疑虑：威胁值高让人类不愿反击 | 接受：强者主动迎战本来就应该暴露为高悬赏；战斗分值已压低，影响更小 |
| 疑虑：复生后进度会在聊天栏再广播一次 | 接受：这正好提示“新的一条命重新开始” |
