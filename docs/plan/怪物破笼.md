# 怪物破笼：像空手一样挖，苦力怕炸墙

2026-11-26 与需求方讨论定稿（[#94](https://github.com/Trileaf-MC/hardrush/issues/94)）。状态：已实现，待人工客户端验收（[2026-11-17 场次](../人工客户端测试/2026-11-17-界面挡住动作栏的提示.md)第二十三段）。

本方案修改[破石而出](破石而出.md)第 1 节"怪物挖掘"的规则；虫穴（第 2 节）不变。

## 背景

僵尸和骷髅只能挖 23 种天然方块（`MonsterDiggable.BLOCKS`），苦力怕的爆炸用的是 `Level.ExplosionInteraction.NONE`，不破坏方块。人类只要用树叶、木板、玻璃把自己围起来，怪物就毫无办法。

速通模式下，人类缩着就推进不了进度，所以龟缩本身只是临时躲避。本方案要打掉的是几秒钟就能糊好的廉价笼子。黑曜石笼这种代价高的龟缩继续保留。

分工：
- 僵尸和骷髅负责日常破笼：像人类空手一样挖任何方块；
- 苦力怕负责强拆：爆炸按原版破坏方块。

## 1. 怪物挖掘（替换《破石而出》第 1 节的"可挖方块""不可挖""时长""输入"四行）

### 规则

| 项目 | 规则 |
| --- | --- |
| 谁能挖 | 不变：僵尸和骷髅，含溺尸、流浪者等环境转化形态。苦力怕不能挖 |
| 可挖方块 | 除下表"不能挖"以外的所有方块 |
| 时长 | 原版空手时间：硬度 × 30 tick；需要工具才有掉落的方块（`requiresCorrectToolForDrops`）为硬度 × 100 tick；至少 1 tick。只有"天然方块"（即原来的 `MonsterDiggable.BLOCKS`）另外封顶 `monster.digMillis`，默认 7.5 秒。手持物品、效率、急迫、挖掘疲劳、水下、离地都不计入 |
| 输入 | 按住左键。**手里拿什么都能挖，拿什么都按空手计时**，镐子也不例外。拉弓、吃东西等正在使用物品时不能挖（不变） |
| 门 | 不按本规则挖，沿用敲门规则：僵尸、困难难度、12 秒、只限木门（含铜门，`DoorBlock.isWoodenDoor`）。铁门谁都挖不开 |
| 两格 | 沿用"挖哪两格"表。另一格也必须按本规则可挖，否则只挖主格；按两格中较慢的计时 |
| 掉落、距离、姿态、中途变化、裂纹、保护区、`mobGriefing` | 全部不变 |

### 不能挖

判定按下面的顺序进行，第一条命中的就是提示原因（见第 3 节）：

| 顺序 | 条件 | 判定方式 | 例子 |
| --- | --- | --- | --- |
| 1 | 门 | `block instanceof DoorBlock` | 木门、铜门、铁门 |
| 2 | 有方块实体 | `state.hasBlockEntity()` | 箱子、木桶、熔炉、床、潜影盒、告示牌、旗帜、头颅、信标、漏斗、营火、蜂巢、讲台、钟、刷怪笼、试炼刷怪笼、宝库、雕纹书架、合成器、装饰陶罐、潜声传感器 |
| 3 | 矿石 | 方块标签 `coal_ores`、`iron_ores`、`copper_ores`、`gold_ores`、`redstone_ores`、`lapis_ores`、`diamond_ores`、`emerald_ores`，另加 `NETHER_QUARTZ_ORE`、`ANCIENT_DEBRIS` 两个单独的方块 | 包括深板岩矿石、下界金矿 |
| 4 | 太硬 | 硬度为 -1（不可破坏），或原版空手时间超过 `monster.digMaxMillis`（新配置项，默认 30000 毫秒，即 600 tick） | 基岩、末地传送门框架、屏障、黑曜石、哭泣黑曜石、下界合金块、强化深板岩 |

- 矿石标签已在 26.3 数据里核实：8 个标签覆盖主世界、深板岩和下界金矿；下界石英矿不在任何一个标签里，所以单独列出。远古残骸本来就会被"太硬"拦下（30 × 100 = 3000 tick），列进矿石是为了让提示写"矿石挖不动"。
- 工作台没有方块实体，可以挖（2.5 × 30 = 75 tick）。
- 活板门和栅栏门不是 `DoorBlock`，按空手时间挖。

### 虫蚀方块

虫蚀方块按它伪装的方块处理：时长、是否属于天然方块都和宿主方块（`InfestedBlock.getHostBlock()`）一样，所以怪物不能靠挖得快慢分辨出虫蚀方块。

挖开虫蚀方块时不放出蠹虫，原因是：
- `Level.destroyBlock(pos, false, breaker)` 不调用 `dropResources`；
- 蠹虫是在 `dropResources` 里经 `spawnAfterBreak` 放出的。

现在用的就是这个调用（已核实 26.3 源码），实现时不要改。

## 2. 苦力怕爆炸破坏方块

| 项目 | 规则 |
| --- | --- |
| 爆炸方式 | `MonsterRoles.nativeCreeperBlast` 里的 `Level.ExplosionInteraction.NONE` 改为 `MOB`。原版语义（26.3 `ServerLevel.explode` 核实）：`mobGriefing` 关闭时不破坏方块；开启时按 `mobExplosionDropDecay` 决定掉落是否衰减 |
| 威力 | 不变：`creeper.explosionStrength`（默认 3），带电 × 2（默认 6），按原版的范围破坏方块 |
| 掉落 | 原版：方块按爆炸衰减概率掉落，容器被炸时里面的东西撒出来 |
| 哪些爆炸 | 自己引爆和被人类点燃的引信都破坏方块。被点燃后掉线仍然直接判死、不爆炸（`MonsterCreeper.disconnected`，不变） |
| 保护 | 大厅等保护维度已经由 `ProtectionExplosionMixin` 在 `explode` 开头整体拦截（不变）。另外在爆炸计算器里覆写 `shouldBlockExplode`：出生点保护内的方块（`server.isUnderSpawnProtection(level, pos, 苦力怕玩家)`）不破坏，和挖掘使用同一个判定 |
| 实体伤害 | 不变：计算器的 `shouldDamageEntity` 仍然只伤合法目标，掉落物（包括"遗落之地"的遗物）不会被炸掉 |
| 原版随从苦力怕 | 不变：它们本来就走原版 `Creeper.explodeCreeper`，会破坏方块 |

### 平衡说明（26.3 源码核实）

`ServerExplosion.explode` 先调用 `hurtEntities()`，后调用 `interactWithBlocks()`。暴露比例 `getSeenPercent` 用 `ClipContext.Block.COLLIDER` 做射线，树叶、玻璃这类有碰撞箱的方块都会挡住。所以：

- 苦力怕在树叶笼外自爆时，笼里的人基本不受伤，笼子被炸开，后续靠僵尸和骷髅冲进去。
- 虫穴里的苦力怕隔着墙自爆，只会把墙炸开，自己白死。所以虫穴提示改成建议它等人挖过来（见第 3 节），不再暗示"就地引爆"有用。

## 3. 提示与文案

### 挖不动的提示

只在怪物**挥手打到方块**时提示（复用 `MonsterMining.punch` 的路径），准星对着时不提示。同一名怪物 3 秒内只提示一次（复用 `HAND_HINTS` 的节流）。挥手打到的是生物时不提示，沿用 `diggableButHolding` 里的实体射线检查。

| 情况 | 提示 |
| --- | --- |
| 苦力怕打方块 | 苦力怕挖不动 · 引爆能炸开方块 |
| 非僵尸打木门 | 只有僵尸能敲开木门 |
| 僵尸在非困难难度下打木门 | 困难难度下僵尸才能敲开木门 |
| 打铁门 | 铁门敲不开 |
| 有方块实体 | 里面装着东西，挖不动 |
| 矿石 | 矿石挖不动 |
| 太硬 | 太硬了，挖不动 |
| 保护区、`mobGriefing` 关闭、不能行动 | 不提示 |

删除"空手才能挖"提示和 `diggableButHolding` 里"手上有东西"的分支。

### 其他文案

- 虫穴入穴提示（`LobbyRuntime.burrowed`）：
  - 非苦力怕：`你藏进了石头里 · 挖开前面的墙，破石而出`（去掉"空手"）；
  - 苦力怕：`你藏进了石头里 · 苦力怕挖不动，等人挖到你再引爆`。
- 规则书（`RuleBookText`）："挖掘与虫穴"一页拆成两页：
  - **挖掘**：僵尸和骷髅按住左键挖掘，一次挖开 1×2，跟人类空手挖一样快，拿着什么都一样；石头、泥土、下界岩这类天然方块最长 {digMillis} 秒。不掉落。门、装着东西的方块、矿石和黑曜石这类太硬的方块挖不动。苦力怕挖不动，但爆炸能炸开方块。
  - **破石而出**：沿用原来的第二段。
  - 一页放不下时可以调整措辞，但这几个要点不能丢。
- "角色"页：`困难难度下能空手敲开木门` 改为 `困难难度下能敲开木门`。

## 4. 实现要点

### `MonsterDiggable`

- 原来的 `BLOCKS` 改名为 `NATURAL`，`is(...)` 改名为 `natural(...)`。虫穴搜索 `SafeDeployment`（第 333、604 行）改调 `natural`，虫穴规则一字不改。
- 新增 `verdict(ServerLevel, BlockPos)` 或类似方法，返回一个枚举：`DIGGABLE`、`DOOR`、`CONTAINER`、`ORE`、`TOO_HARD`。按第 1 节表格的顺序判定。挖掘入口和提示共用这一个判定。
- 时长和"不能挖"都只按方块自身的属性和标签计算，不维护方块清单，所以以后新加的原版方块会自动适用。第 1 节的时间表只是例子和测试参照，不要写进代码。
- 不能直接调用原版的 `Player.getDestroySpeed`：它从手持物品的速度算起，而且我们为防止客户端预测，把 `BLOCK_BREAK_SPEED` 设成了 0。
- 按需求方裁决不计入环境因素（急迫、挖掘疲劳、水下、离地），时长在开挖时就定下。
- `ticks(state, capTicks)` 改为：
  1. 先把虫蚀方块换成宿主方块；
  2. 算出空手时间，硬度改读 `state.getDestroySpeed(level, pos)`，不再读 `getBlock().defaultDestroyTime()`；签名相应加上 `level` 和 `pos`；
  3. 只有 `natural` 的方块再和 `capTicks` 取较小值。
- 新增 `maxTicks(player)`，读 `monster.digMaxMillis`。

### 配置（core）

- `RulesConfig.SORTIE_DEFAULTS` 加上 `"monster.digMaxMillis", 30_000.0`（`Map.of` 最多 10 对，目前是 7 对）。
- `RoundEngine.digMaxMillis(rules)` 仿照 `digMillis` 写：规则里没有这个键时取常量默认值 30000，这样旧快照里的对局也能用。
- 更新 `RulesConfig` 那段 javadoc 里关于挖掘的描述。

### `MonsterMining`

- `available()` 去掉 `getMainHandItem().isEmpty()`。敲门也一样，拿着东西也能敲。
- `diggableAt` 改为 `verdict == DIGGABLE`；`aim()` 里门的判定（`upperDoor` / `doorAim`）保持在前面。
- **输入模式（关键风险）**：现在只要准星对着可挖方块，就把客户端切到生存输入模式，这样原版冒险模式客户端才会发出挖掘包。以前只在空手时切换，右键不受影响。现在拿着东西也能挖，如果仍然"对准就切"，生存模式下右键的含义会变：刷怪蛋会对方块使用，追迹罗盘、拘魂袋等物品的行为也可能不同。处理方式：
  - **空手**：保持现状，准星对着就切换。
  - **手里有东西**：准星对着时不切换。第一次挥手打到可挖方块时才切换（冒险客户端被限制挖掘时仍会发挥手包，`punch` 能收到）。之后按住左键，客户端 `continueDestroyBlock` 发现目标变了，会自己补发 `START_DESTROY_BLOCK`。停止挖掘、准星离开、换手持物时切回。这样只有正在按左键挖的时候右键含义才会变，这时玩家不可能同时去右键。
  - 实现时用 gametest 确认：切换后按住左键能连续开挖；用"手里有东西、只瞄准不挥手"断言客户端仍是冒险输入。
  - 如果确实做不到，在代码上方写 `TODO: [Refactor]` 说明原因，并向需求方报告，不要退回"必须空手"。
- 零挖掘速度不变：`BLOCK_BREAK_SPEED` 的 -1 总乘数作用在镐子速度、效率附魔之后，所以手持镐子时客户端预测的速度仍然是 0。硬度为 0 的方块在客户端算出来是 `0 / 0 = NaN`，`NaN >= 1` 为假，所以也不会预测瞬间破坏（26.3 `BlockBehaviour.getDestroyProgress`、`MultiPlayerGameMode.startDestroyBlock` 已核实）。这一点交给人工测试确认没有闪烁。
- `punch()`：`aim == null` 时，如果挥手打到的是方块而不是生物，就按第 3 节的表格提示原因。
- 被拒的右键照旧调用 `useBlock` 重新同步。

### 苦力怕爆炸

- `MonsterRoles.nativeCreeperBlast`：改为 `ExplosionInteraction.MOB`，计算器加上 `shouldBlockExplode` 覆写（出生点保护）。苦力怕玩家可以通过 `owner` 从 `level.getServer().getPlayerList().getPlayer(owner)` 取到，也可以改签名直接传进来。
- `MonsterCreeper` 不用改。

## 5. 交付

### core 单元测试

- `RoundEngine.digMaxMillis` 的默认值、自定义值，以及旧规则没有这个键时取默认值；
- 规则书新的"挖掘"页包含要点，`digMillis` 改了以后秒数跟着变（更新 `RuleBookTextTest`）。

### 无图形 GameTest（扩展 `MonsterDiggingGameTest`，新增苦力怕爆炸用例）

挖掘：
- 时长：树叶 6、木板 60、石砖 150、铁块 500 tick；圆石、深板岩被天然方块上限截断；虫蚀石头等于石头的时长。
- 不能挖：
  - 门、箱子（方块实体）、铁矿石、深板岩钻石矿石、下界石英矿、黑曜石、基岩各一例，`verdict` 给出对应的原因；
  - 把 `monster.digMaxMillis` 调到 400 毫秒以下时，铁块（500 tick）变成"太硬"。
- 手持镐子和弓都能挖，时长和空手相同；拉弓时不能挖。
- 两格：一格木板、一格石头，按较慢的计时；另一格是箱子时只挖主格。
- 树叶笼：人类被一圈树叶围住，骷髅能挖开。
- 挖开虫蚀方块不出现蠹虫。
- 提示：苦力怕、非僵尸打门、铁门、箱子、矿石、黑曜石各给出对应提示；挥手打生物不提示。
- 输入模式：手里有东西只瞄准时，客户端仍是冒险输入；挥手之后才切换。
- 原有用例：删掉"空手才能挖"相关断言，其余照旧通过。

苦力怕爆炸：
- `mobGriefing` 开启时破坏周围的木板和树叶；关闭时不破坏；
- 出生点保护内的方块不被炸：和挖掘共用 `MinecraftServer.isUnderSpawnProtection`。基类恒为 false，只有专用服务器覆写它，GameTest 测不到，改由人工测试第二十三段第 5 步看。
- 带电时破坏范围更大；
- 树叶笼外自爆，笼内人类受到的伤害远小于没有笼子时（验证"先算伤害后炸方块"）。

## 需求方裁决（2026-11-26）

1. 挖掘模型选"像人类空手一样挖，加排除表"，不选扩充白名单。
2. 排除表包括门、有方块实体的方块、矿石、太硬的方块；门槛 30 秒。
3. 带电苦力怕按原版威力 6 破坏方块，不限制范围。
4. 爆炸掉落按原版。
5. 苦力怕的出击门槛不变：40 怪物币，只追三星以上。一、二星人类的笼子交给僵尸和骷髅。
6. 挖不动时提示原因。
7. 手持任何物品都能挖，速度和能挖的方块一律按空手算，镐子也不例外；取消"必须空手"。
8. 不计入环境因素（急迫、挖掘疲劳、水下、离地），和《破石而出》一致。原版没有"不计工具的速度"可以直接调用，要计入就得复刻 `Player.getDestroySpeed` 里和工具无关的部分，还要改成每 tick 累加进度。这样带来的复杂度不值得。
9. （2026-11-26，评审后）
   - 容器（有方块实体的方块）保持挖不动，接受用木桶、熔炉围笼子的漏洞；
   - 贵重方块（铁块、金块、钻石块等）保持可挖，不掉落；
   - 苦力怕爆炸照原版炸掉下界传送门方块和床；
   - 爆炸撒出的物品，出击中的怪物也能捡。

## 实现记录

- 手持物品时，挥手打到木门也会把客户端切到生存输入，不只是可挖方块。冒险模式客户端只有在方块看起来能挖时，才会按住左键每 tick 送一次挥手；敲门要 12 秒，只靠挥出的那一下会在 4 tick 宽限后中断。挖掘和敲门因此共用“这一下确实开始了，才切换”。瞄着墙还没挥手时，右键仍是冒险模式。人在空中挥到可挖方块、挖掘还没开始（必须站在地上）时，这一下不切换。
- 拿着东西第一次挥手开挖后，服务端切到生存输入要一个来回才到客户端，之后客户端才开始每 tick 送挥手。所以这一次的等待宽限是 20 tick，后续挥手恢复为 4 tick，以免延迟超过约 200 ms 的玩家刚开挖就被中断。
- 矿石判定用 `BlockTags.ORES`，再加远古残骸。26.3 没有煤炭、钻石、红石、青金石、绿宝石各自的标签常量；`data/minecraft/tags/block/ores.json` 正好是本方案的 8 个矿石标签加上下界石英矿。远古残骸不在这个标签里，仍然单独算矿石，提示“矿石挖不动”。
- `natural()` 不拆虫蚀方块，虫穴选点和改前一样。计时、矿石和“太硬”才按宿主方块算。破坏仍是 `level.destroyBlock(cell, false, owner)`，不生成蠹虫。
- “`digMaxMillis` 低于 400 毫秒时铁块变太硬”的 GameTest 把换算后的 tick 上限直接传给 `verdict`（399 毫秒即 8 tick）。无头测试里给玩家套一局正式规则会让 `canAct` 失败。缺这个键时返回 30000 的行为在 `RoundEngine` 的单元测试里。
- 出生点保护没有 GameTest。`MinecraftServer.isUnderSpawnProtection` 在基类里恒为 false，只有 `DedicatedServer` 实现；GameTest 用的不是专用服务器。人工测试在测试服的出生点保护范围内引爆苦力怕。
- 持物挖掘时，弓的显示刷新（耐久条、说明）和追迹罗盘发光都会改掉客户端主手物品的组件。原版 `MultiPlayerGameMode.sameDestroyTarget` 用 `ItemStack.isSameItemSameComponents` 判断是不是同一次挖掘，组件一变，客户端就在同一批包里先发 `ABORT_DESTROY_BLOCK`、再发 `START_DESTROY_BLOCK`。所以 `MonsterMining` 收到 ABORT/STOP 时只记下“已松开”；同一批里又收到同一主格的 START、挖掘仍然有效，就清掉标记接着挖；到 `MonsterMining.tick` 时标记还在，才真正中断、切回冒险输入，并补发裂纹清除和方块重同步。这依赖服务端先处理排队的网络包、再跑这一 tick（26.3 `MinecraftServer.processPacketsAndTick`：先 `packetProcessor.processQueuedPackets()`，后 `tickServer`；`MonsterMining.tick` 挂在 `END_SERVER_TICK`）。
- 持物只点一下、不按住时，冒险模式客户端没进入挖掘状态，松手也不发 ABORT。所以持物挥出第一下创建的挖掘先是“未确认”：只等待，不计时，不发裂纹；收到下一次挥手或 START 才确认，从那时开始计时。20 tick 宽限内没有确认就中断并切回冒险输入。空手的挖掘一开始就是确认的。
- 门下面的方块也按门处理：`DoorBlock.canSurvive` 要求下半扇门站在方块上，挖掉它门就会掉，铁门也一样。所以 `verdict` 在上方是下半扇门时返回 `DOOR`，提示按那扇门本身给：木门说谁能敲开，铁门说“铁门敲不开”。困难难度的僵尸对着木门下的地板挥手，既不挖也不提示，也不会误触发敲门。
- “太硬”按封顶之后的时长判断：天然方块先和 `monster.digMillis` 取较小值，再和 `digMaxMillis` 比较。天然方块的上限本身也不超过 `digMaxMillis`，所以即使管理员把 `digMaxMillis` 调得比 `digMillis` 还小，石头等虫穴用的天然方块也始终挖得动，挖掘时长按较小的那个算。
- 空气不算可挖，`verdict` 返回空。两格挖掘的另一格是空气时只挖主格，之后有人往那一格放方块也不会让这次挖掘作废。
