# 追迹罗盘改版：随时可用、边走边引导、指针指向目标

2026-11-19 与需求方讨论定稿。状态：已实现（2026-11-19），待人工客户端验收（[2026-11-17 场次](../人工客户端测试/2026-11-17-界面挡住动作栏的提示.md)第六段）。实现中的偏差见文末“实现记录”。本文取代《[追猎出场与重新循迹](追猎出场与重新循迹.md)》第 3 节中的可用条件、冷却与引导规则；落点搜索（第 1 节，含 5 秒后兜底、海上规则）不变。

## 背景

旧规则：与目标直线 > 40 格持续 10 秒，或目标在其他维度，罗盘才亮；站立引导 5 秒；冷却 15 秒。问题：

1. 门槛拦不住任何事，只逼玩家绕路。主动归返默认无冷却（`monster.returnCooldownMillis` = 0）且保留身体与物资，远处的怪物可以归返 → 点目标模型 → 用同一套落点规则再出击。罗盘只比这条路少走一段营地。
2. 直线距离不等于路程距离。目标在脚下 20 格的矿洞里时直线不到 40 格，罗盘不亮，最需要它的时候用不了。
3. 追溯指针在原版里指向“自己上次死亡的位置”，对怪物而言指针没有意义。

## 1. 可用条件与冷却

| 项目 | 新规则 |
| --- | --- |
| 可用条件 | 不在冷却中，且罗盘指向有效目标（目标在线、存活、在挑战世界）。取消距离与持续时间门槛 |
| 光效 | 表示“现在按下就能用”。冷却中靠原版冷却遮罩，目标失效时不亮 |
| 冷却 | 10 秒，从落地起算；搜索失败或被打断不进冷却。新增配置 `monster.retrackCooldownMillis`，默认 10000 |
| 有效阶段 | 只在挑战、救场阶段，与现在相同 |

离目标很近时也允许使用。可能被传到更远处，由玩家自己判断。绕背由以下规则制约：引导中受击会打断、落点离任何人类 ≥ 8 格、16 格内落地播放物种原版叫声（苦力怕除外）、冷却。

## 2. 边走边引导

> 2026-11-23：归返营地也改为边走边引导，引导时长拆成归返 4 秒、循迹 5 秒（`monster.retrackChannelMillis`），见《[击败锁定与怪物平衡](击败锁定与怪物平衡.md)》第 3 节。下文“归返营地仍要求站立”已被取代。

只改循迹；归返营地仍要求站立（归返是逃生手段，边走边归返会让残血怪物边跑边撤）。

引导时长仍为 5 秒，读取 `monster.returnChannelMillis`，与归返共用。引导完成后的寻找落点阶段（最多约 10 秒）适用同一套打断规则。

| 打断循迹 | 不打断循迹 |
| --- | --- |
| 受到伤害 | 方向键移动、跳跃、潜行、转动视角 |
| 攻击实体，挖掘方块，破门 | 切换快捷栏，打开背包 |
| 施放技能（刷怪蛋、苦力怕点燃、骷髅连射等） | 被动位移（水流、推挤、无伤击退） |
| 拉弓、投掷三叉戟、使用拘魂袋等其他物品；右键方块或生物 | 手持罗盘再次右键（不重复、不重启） |
| 切换维度、身份或阶段变化 | |

讨论时曾把开门、按按钮、进食列为不打断，实现时核实：怪物玩家本来就不能操作方块、打开容器或进食（右键方块只会被拒绝，僵尸改为敲门），所以这些动作不存在，不需要白名单。规则仍是一句话：“引导时可以走，但不能动手。”

引导表现沿用幽匿主题（粒子、咔哒音、冷却遮罩当进度条），粒子跟随身体位置。

## 3. 指针指向目标

- 外观从追溯指针换成**普通罗盘**，名称仍为“追迹罗盘”。
- 指针始终指向绑定的追猎目标，冷却中也照常指，每秒更新一次。
- 目标在其他维度时指针原地乱转（原版罗盘在出生点维度不同时的表现）；目标阵亡、离线或失效时同样乱转。
- 实现方式（首选）：
  - 每秒只给这名怪物发送原版的世界出生点数据包，把目标位置当作出生点。原版普通罗盘指向世界出生点，物品本身不改，手持时不会每秒抖一下。
  - 怪物不再是出场状态（归返、阵亡、变回人类、离开）时，发回真实出生点。
  - 原版在登录、复生、切换维度时会重发出生点，下一次每秒更新会覆盖它。
- 备选方式：
  - 给物品写入磁石追踪数据（`tracked=false`）。
  - 只有首选方式经原版源码核实不可行时才采用，并且要先核实手持物品数据变化是否会触发换手动画。
- 副作用：怪物捡到的其他普通罗盘也会指向目标。可以接受，并写进规则说明。

## 实现记录

- 原版依据（26.3 客户端字节码）：普通罗盘的物品模型在没有 `lodestone_tracker` 组件时用 `CompassAngleState$CompassTarget.SPAWN`，读取 `ClientLevel.getRespawnData().globalPos()`；`isValidCompassTargetPos` 在目标维度与玩家所在维度不同时判为无效，指针随机旋转。`ClientboundSetDefaultSpawnPositionPacket` 只调用 `ClientLevel.setRespawnData`，客户端除罗盘外没有其他地方读取这个值。原版在 `PlayerList.sendLevelInfo` 和复生时发送 `ServerLevel.getRespawnData()`，归位时发送的就是这个值。
- 目标失效，或者目标和猎手不在同一维度时，发送一个不存在的维度 `hardrush:lost_quarry`（坐标为 0），让指针乱转。这样客户端收不到目标在其他维度的任何坐标，改装客户端也读不出来。猎手所在维度变化时立即重发，其余情况每 20 tick 更新一次。
- 发光和右键共用同一个就绪判断（`LobbyRuntime.retrackReady`）：目标在线、存活、不受保护、在挑战世界（任意维度），而且当前没有引导或落点搜索在进行。冷却由罗盘的原版冷却组记账，不依赖罗盘当时在哪一格，罗盘拿在背包光标上跨过落地时刻也会进入冷却。
- 营地出击和暂存恢复时，回响碎片与追迹罗盘都按当前规则重新发放，所以旧暂存里的追溯指针和过期描述不会被带回来。
- 循迹引导和搜索中切换维度，打断原因显示为“切换维度”（以前笼统写作“比赛状态变化”）；归返的打断原因同样改为“切换维度”。
