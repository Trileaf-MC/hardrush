## 人工场地与重现

服务端为 `.local/debug/server`，仅监听 `127.0.0.1:25586`。MCPFabric、spark 和开发夹具只装在服务端；两个客户端使用官方 26.3 的 81 个运行 JAR，启动时逐个复核官方文件，两个配置目录无模组和资源包。账号为与服务端 UUID 匹配的本地离线开发身份，不读取真实账号或启动器凭据。

```sh
python3 scripts/debug-tools.py start --side server
python3 scripts/p0-client.py launch-app HRProbeA --server 127.0.0.1:25586
python3 scripts/p0-client.py launch-app HRProbeB --server 127.0.0.1:25586
# 两个 launch 命令分别保持运行；连接后在另一个终端运行：
python3 scripts/p0-appearance.py prepare
python3 scripts/p0-appearance.py snapshot
```

启动器只允许本项目 `25585`／`25586` 两个回环地址。原生应用的游戏参数覆盖包内默认服务器，官方 JAR 逐个复核；本次两个客户端实际加入 `25586`，有日志及服务端状态。`prepare` 要求恰好两个指定测试账号在线，拒绝在其他玩家会话中改场地；白名单／OP 配置保留已有条目，并拒绝同名或同 UUID 冲突。

`prepare` 会重建主世界 `(47,147,47)`～`(81,158,81)` 场地、清空两个测试背包、装备剑／弓／箭／盾／钻石头盔胸甲，设置生存出生点并开启测试世界死亡保留物品。测试进行中不要重复准备，它会移动角色并重置场地。

| 窗口／场景 | 内容 |
| --- | --- |
| HardRushProbeA | 变身玩家，金块 `(64.5,150,64.5)`，本人普通模型／优先 Steve |
| HardRushProbeB | 观察者，绿宝石块 `(64.5,150,61.5)`，看 A 的怪物外观 |
| 门洞 | `(55,150,58)`，一格宽、两格高、已打开木门 |
| 台阶 | `(68,150,56)` 附近，半砖／楼梯／完整方块 |
| 水池 | `(72,149,72)` 附近，两格深、有上岸台阶 |

人工步骤：A 切 F5、向下看和操作；B 观察并用剑／弓攻击；在任一窗口分别执行 `/hardrushp0 disguise HRProbeA zombie`、`skeleton`、`creeper` 切换；A 走门洞、台阶和水池，最后执行 `/hardrushp0 clear HRProbeA`。死亡使用原版重生按钮。用户已完成这批操作；正式死亡转怪物大厅、技能及奖励复生仍属于 P2。

## 原版客户端连续生命周期

`scripts/p0-appearance-cycles.py --run` 专用于本地测试：会关闭两个指定原版应用、重载受管服务端，然后重复变身、死亡、重连和维度传送。它不合成鼠标键盘、不装客户端模组；死亡用原版 `immediate_respawn` 游戏规则触发客户端自身重生，重连重启官方应用。只终止二进制路径、用户名和回环地址完全匹配的测试进程，并在发信号前再次核对 PID 身份。

debugTools 的只读 `hardrushdebug snapshot <player>` 记录真实客户端加载确认、位置传送确认、真实 ServerPlayer 实例、身份、维度、属性、装备、权限、队伍、相机、隐身和世界内同 UUID 实体计数；这段代码不进入发布 JAR。每一步等待真实客户端完成加载及原版传送确认，再核对状态。最终结果与次数以证据清单为准。
