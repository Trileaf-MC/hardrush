# 崩溃后的自动续局与重连

日期：2026-10-23。范围：26.3 服务端实现。用户选择自动恢复到最近完整保存点，允许回退少量进度；资料不完整时留在大厅并说明原因。

## 自动续局

进行中的本轮完成原生入场后，系统在档案与数据库事务空闲时尝试建立第一个完整保存点，随后默认每 60 秒尝试一次。保存点包括本轮三维度与清单、玩家原生文件、档案 journal／悬停档案，以及独立 SQLite 镜像。鼠标拿着的物品、随身合成格和工作台输入另外封存在副本档案里，避免只复制原版玩家文件漏掉这些状态。

保存过程在服务端主线程形成短暂屏障：停止竞技操作，等待已受理档案 IO，提交计时快照，使用 `VACUUM INTO` 导出已提交的 SQLite 数据，原生保存并 flush 三维度和玩家，再复制并校验文件。不会把活动数据库的主文件直接当作包含 WAL 的备份。复制超过 10 秒预算或发生 IO 错误时不发布本次保存点，保留上次完整点；原生保存本身的耗时不包含在这 10 秒复制预算中。保存耗时不计入挑战与个人参赛时长。

保存点位于 `world/hardrush/full-checkpoints/`，以逐文件 SHA-256 清单和原子 `latest` 指针发布，只保留最近两个生成的保存点副本。尚未完成的副本不参与恢复。世界较大或存储较慢时保存会造成可感知停顿；保存失败或状态持续繁忙时，上次成功保存点可能早于 60 秒，不能承诺最多只回退一分钟。

服务端异常退出后，在打开比赛数据库、玩家档案服务和本轮动态世界之前，先核对当前数据库、轮次、规则、保存点完整性及文件路径。当前轮处于 `RUNNING`、没有已提交终局，且存在同轮的完整保存点时，自动恢复同一个轮次 UUID、种子及规则。世界、物品、身份、生命序号、复生资格和计时一起回到保存点；保存点之后的进度允许回退。玩家先在大厅核验，再自动回原维度、原位置。停服时间不计入挑战，恢复后的成绩保持待核验。

恢复会先把全部替代文件复制到独立目录，留下可重试的恢复标记，再替换各受管路径。崩溃现场被移动保存在 `full-checkpoints/restores/<尝试ID>/original/`，不会用新文件覆盖销毁原始现场。旧 SQLite WAL／SHM／journal 与旧主库一同移开，避免重放到恢复库。恢复过程中再次退出，下次启动按同一个不可变保存点重试。

以下情况继续留厅并向玩家显示具体原因：没有完整保存点、文件缺失／损坏、数据库不完整、保存点属于旧轮、规则不一致、路径包含链接，或异常退出时不处于可续玩的进行中阶段。已提交终局不会被旧保存点撤销；保存点之后尚未完成的身份转换，以及身份适配器提供的主动退赛／资格取消决策，也不能被旧保存点覆盖恢复参赛。正常保存退出沿用原有恢复逻辑，不自动回退。

`-Dhardrush.p1.fullCheckpointIntervalSeconds=60` 可调整尝试间隔，有效值为 1～3600；0 关闭完整保存点生成。关闭生成不会删除既有保存点。它不是损坏档案的强制解锁开关，也不能让此前从未生成过完整点的旧崩溃对局直接续玩。首发其他版本适配未由本次 26.3 验证替代。

## 管理员在线处理故障轮

OP4 执行 `/hardrush admin recovery`，按保存时间从新到旧核验当前轮的完整保存点。检查不依赖 `latest` 指针：最新副本损坏、清单或档案不完整时，会继续检查较早的副本。核对逐文件哈希、独立数据库、本轮身份／规则／种子、已提交终局与退赛／取消资格决定、世界所有权清单及玩家档案生命／位置。原数据库无法核验且不存在已知的中断恢复事务时，保留隔离并报告原因。

找到可用点后，在原版聊天栏显示保存时间、约多少秒／分钟／小时之前、轮号、回退进度与成绩待核验提示，以及可点击的 `[yes]` 和 `[no]`。只有申请的管理员可以在两分钟内使用该次确认；轮次／版本改变、重新申请、断线、降权或过期都会使旧提示失效。点击 no 不替换世界或数据库。控制台会显示对应的确认／取消命令。

点击 yes 后，先送玩家回大厅、排空并暂停档案写入，关闭比赛数据库，可信停止已安装的录像适配器，并等待本轮三个原生世界保存、注销和关闭。所有句柄释放后再次核验已确认的保存点，才统一替换世界、玩家档案与数据库。既有 session 与适配器绑定保留，在线实体重新绑定保存点中的档案；世界和档案核验、恢复审计及待核验标记持久化后，玩家无需重登或重新准备便可继续原局。

确认后保存点又损坏、复制失败或实际载入失败时，继续隔离并自动检查其他较早保存点。较早的回退范围需要重新点击 yes，防止管理员在不知情时接受更大回退。没有可用点时明确提示“无法自动恢复”。存储只读、满盘、录像未可信保存或世界句柄无法安全关闭时，需要先解决相应故障。

决定放弃原局时，执行 `/hardrush admin close-recovery`，可选地在后面填写原因。FAILED 状态会先自动重核原数据库；成功后持久化结束决策和审计。没有终局的原局记为中止，已有终局保持原结果。玩家回厅，档案、录像和旧世界安全释放后自动开始下一轮；原有世界和恢复现场保留。已中断的恢复标记会封存，避免重启后把新轮错误回退到故障轮。损坏的原数据库或无法安全释放的档案／世界仍会阻止轮换，并说明原因。

正常对局不能用 `recovery` 主动读档；两个入口均限制在故障处置中。完整点默认只保留最近两个副本，因此“尝试其他保存点”只覆盖当前实际保留且属于同轮的点，不会跨到上一轮。

## 退出重连到大厅

登录首先进入大厅核验是既有设计。同轮、仍存活的人类应在核验后自动恢复原来的游戏。修复了快速重连时数据库的在线标记已经更新、档案仍锁定，导致旧判断跳过恢复的分支；现按本轮人类身份及档案是否待恢复决定恢复，不再要求在线标记必须为离线。

恢复成功会提示“已恢复本轮人类身份，返回离线前的位置继续游戏”。跨轮时明确提示上一轮已结束、当前轮号及旧档案已封存。档案失败或服务器恢复隔离时保留具体错误提示。

用户报告的玩家一直留厅、随后能够通过准备区再次开局，说明当时不是关闭全部参赛入口的恢复隔离；也可能已进入下一轮或使用了不同参赛身份。本次未获得玩家名、发生时间或对应日志，不能把该次现象确定归因于已修复的快速重连分支。

## 自动与人工验证

`python3 scripts/p3-full-checkpoint.py` 使用独立随机目录、已有 EULA、仅回环监听的无图形 dedicated server。父进程核对测试 JVM PID 后发送 SIGKILL；新 JVM 自动回退实际三维度、容器、背包、末影箱、经验、原生进度、效果与坐标，再用嵌入连接验证快速重连。另一份相同崩溃现场故意破坏保存点，验证保留最新源数据库并留厅、拒绝参赛以及具体提示。测试代码只在 gametest 制品，不进入生产 JAR。

文件与会话自动测试另外覆盖完整点损坏／丢失、链接拒绝、恢复标记重试、旧轮与终局不可回退、正常退出不依赖旧保存点、两个副本保留、计时暂停和待核验标记先持久化再开放比赛。正常 RUNNING 保存退出／新 JVM 恢复另行回归。
