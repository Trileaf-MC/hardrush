# P1 第二批：实际世界、档案隔离与攻击因果

更新：2026-10-14。继续按用户指示提前推进 P1；P0／P0b／P1 的阶段验收均未放行。本批仅运行 JUnit、真实 SQLite 和无图形服务端 GameTest，没有运行真实客户端、浏览器或 computer use。

## 实现范围

- **P1-08**：独立 P1 三维度、持久世界所有权清单、异步原生区块请求、出生区与至少两条安全出口（2～4 条）。清单先于世界打开落盘；部分准备失败保留同轮 ID、种子与生成器，允许重试。已经就绪的世界重开只验证，不重建出生区或末地平台，不覆盖玩家建筑。损坏的安全点、缺失所有权清单、路径越界及符号链接均停止进入。
- **P1-09**：真实登录包发出之前隔离玩家；后台封存旧 NBT、背包／末影箱／光标／个人合成栏、进度及位置。档案转换按 PREPARED／APPLIED／VERIFIED 重放，新轮清除旧物资、效果、经验、出生绑定、位置与进度，同轮保留原状态；启动时维度尚未打开也保存原始登录坐标／朝向。生命序号区分死亡画面与已生成的新生命，重连只放行受控原版重生，并等新生命提交后开放操作。只有档案核验与参赛提交均成功才进入比赛；原版累计统计不被清零。
- **P1-04／05（普通模式接入）**：世界准备完成后进入 WAITING，`join → ready → 30 秒倒计时 → RUNNING`；取消最后就绪、下线、晚加入、普通死亡画面、床／锚重生和正常停服均接核心。上下线、死亡和重生在受理时捕获单调时间；即使 SQLite 回调延迟，也不把事件时刻改成写入完成时刻。
- **P1-06（攻击因果）**：人类近战、箭、床、锚、TNT 与水晶链保存创建时轮次／身份／生命序号、直接实体及父因果。实体 NBT 保存封存来源；未知来源、损坏标签及旧轮来源不猜测最近玩家。记录实际龙分部伤害、不可逆死亡候选和玩家致死事件；保留原版伤害类型。

战斗证据使用 SQLite schema 2 的独立 `evidence_events`，与轮次状态版本分别管理。事件 ID 与原快照／配置事件检查碰撞；相同内容可以重放，不同内容拒绝；查询有界且核验摘要。schema 1→2 在事务内升级，失败回滚并保留原数据。关键事件与证据队列都有上限，写入失败停止状态变更并隔离已管理的参赛玩家。

## 准备预算与恢复边界

主线程每 tick 最多启动两个未完成的 FULL 区块请求，检查 16 个候选、修改 64 个方块，并限制这些可分片工作的调度时间为 2 ms。原生区块生成继续使用 Minecraft 工作线程；不在主线程调用会 `managedBlock` 的 `getChunkFuture`，不在 IO 线程读写世界。

Fantasy 每 tick 最多打开一个维度。单次维度构造及原生请求内部不能被本实现抢占，2 ms 不是服务器整体 MSPT 保证。`metrics()` 分别记录总准备耗时、最慢区块、调度峰值、候选及改块数；最终合并夹具的首次准备为 7544 ms，最慢区块 1668 ms，调度峰值 10.685 ms；已就绪恢复 1376 ms、同轮清单重试 1022 ms，均为 0 改块；单维度失败后重试为 6501 ms。测试日志中的实测值仅代表当次本机夹具，不替代 P4 的负载验收。

大厅使用长期存在的原主世界；P1 世界使用 `hardrush:p1_<roundId>/<overworld|nether|end>`，不会借用 `hardrush:p0_…`。传送门语义、普通重生、原版进度判定、时钟与天气通过按轮次所有权的路由隔离。正常停服保留注册维度，由原版关闭区块 IO。开发夹具关闭通过 Fantasy 卸载并保存；自动轮换中的原生 Level 后置关闭、归档与完整引用释放仍属于 P1-10，尚未完成。没有递归删除或自动归档。

正常停服保存计时和阶段剩余量，同轮恢复等待世界与档案验证后才开放。崩溃标记仍进入 `RECOVERY_REQUIRED`，没有用重试世界命令清除计时不确定性；强制终止后的完整恢复仲裁属于 P3。

## 开发入口

P1 默认关闭。第一次在独立开发实例创建普通模式数据库时，可使用：

```bash
scripts/p0-gradle.sh :platforms:mc263:runServer -PhardrushP1=true -PhardrushP1InitialMode=normal --console=plain
```

独立服务器对应 JVM 参数是 `-Dhardrush.p1.enabled=true -Dhardrush.p1.initialMode=normal --enable-native-access=ALL-UNNAMED`。`initialMode` 只设置全新数据库的初始规则，已有轮次及下轮配置始终以数据库为准；不通过该参数改写正在进行的轮次。省略时仍按需求默认极限模式；极限模式可以准备世界与加入，但本批拒绝就绪开赛，因为正式死亡／怪物／复生闭环尚在 P2。

- `/hardrush status`：当前轮次、阶段、规则指纹、计时／暂停原因与世界准备状态；准备失败时显示原因。
- `/hardrush join`、`ready`、`unready`：普通模式的开发流程，成功回执在 SQLite 提交之后发送；档案未完成时拒绝参与。
- `/hardrush retry-world`：OP 重试失败的原轮世界准备；保留轮次和种子，不清除数据库／档案故障或崩溃标记。
- `/hardrush config next-mode normal|hardcore`：只设置下一轮模式，保持当前快照不变。

这是 P1 开发入口。**龙致死候选尚未接唯一终局提交、庆祝／自动轮换、排行榜、TAB 或历史书；当前不能作为完整比赛使用。** P2 的出生保护、极限赛制及正式怪物身份也未在此入口开放。P0 管理员探针仍独立存在，不作为 P1 参赛或成绩来源。
