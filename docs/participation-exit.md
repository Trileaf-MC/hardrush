# 取消资格、主动退出与观战

2026-10-23：两种退出都只作用于当前轮次；本轮不可恢复或重新参赛，下轮自动恢复资格。

## 玩家与管理员入口

| 入口 | 权限与用途 | 结果 |
| --- | --- | --- |
| 按住潜行，再按交换副手键（默认 Shift + F）；TAB 底部常驻提示当前键位 | 玩家仅操作自己；打开原版确认菜单，人类和大厅／外出怪物均可用 | 点击“确认”才提交，取消／关闭不改变身份 |
| 点击参赛／身份变化消息中的“退出本轮并观战”，或执行 `/hardrush spectate` | 同一确认菜单的备用入口 | 点击“确认”才提交，取消／关闭不改变身份 |
| `/hardrush admin disqualify <玩家名或UUID> <原因>` | OP 3；处罚或取消本轮资格，支持本轮离线参与者 | `DISQUALIFIED`，安全回大厅，默认不授予观战 |
| `/hardrush admin withdraw <玩家名或UUID> <原因>` | OP 3；代为办理非处罚退出 | `WITHDRAWN`，清理比赛身体后自动进入旁观模式 |
| `/gamemode spectator <玩家>` | OP 2；另行授予观战 | 已退出／取消资格的玩家也可以获准旁观，但不会恢复参赛资格 |
| `/gamemode adventure <玩家>` | OP 2；结束旁观 | 安全回大厅，退出／取消资格的身份仍保留 |

主动退出与处罚分别记录。玩家主动退出不会使整轮成绩变为“计时待核验”；处罚属于管理员／程序干预，会使本轮成绩待核验。主动退出后发现作弊，仍可追加处罚；处罚不能被主动退出命令覆盖。每项操作保留操作者／来源、原因、轮次、目标 UUID、前后身份与累计计时，可用现有 `/hardrush admin audit current` 查询。

TAB 提示为每位玩家单独生成，只在当前可以主动退出时显示；聊天刷屏不会影响入口。键位由原版客户端按其控制设置显示，改键后仍使用“潜行 + 交换副手”。不占用或发放背包物品，未潜行时的副手交换保留原版行为。打开确认菜单不会暂停比赛；需要关闭其他容器界面后再按快捷键，重复快捷键不替换已经打开的菜单。死亡重生处理、已退出、结算和故障恢复隔离期间不提供此入口。

普通玩家退出后可使用原版旁观菜单选择在赛玩家进行观察，不需要管理员再次 TP。旁观菜单的传送和视角操作只向已经获准的旁观身体开放，目的地仍受大厅／当前轮次边界限制；不会获得原版管理命令权限。

## 身份与物资

- `WITHDRAWN`、`DISQUALIFIED` 为持久化身份，不把已经参赛过的玩家伪装成从未参赛的 `LOBBY`。保留本轮参与时间、首次入场时间、生命序号、出场序号和已有进度记录。
- 提交受理后立即冻结目标输入与攻击；只有 SQLite 状态和审计共同提交成功后，才清理比赛身体并回厅。数据库失败不报告退出成功，也不先清空其物品。
- 当前比赛物资封存在 `hardrush/profiles/<UUID>/archives/exit-<轮次UUID>.bin`，同一轮第一次封存后不会被重连或追加处罚覆盖。封存只供诊断／人工取证，不提供本轮恢复物资入口。
- 观战身体清空随身装备、物品、经验和效果；旧末影珍珠失效。不会调用一次新的原生死亡，不产生额外掉落、击杀奖励或复生生命。
- 已退出者不再增加人类参与时间，不计在线存活人类或怪物，不可重新集结、中途入场、追猎、施放怪物技能或复生；复生余额与技能状态在退出时清除。
- 已发射箭、TNT 等的冻结攻击来源仍保留用于归因，但命中／生效时会检查其来源是否已退出或正在退出；失去资格的来源不能继续造成比赛伤害。
- 退出准备者会撤销其准备；最后一名准备者退出时取消倒计时。没有人类资格后，有其他有效怪物持有复生次数则按现有剩余期限救场，否则以“无有效参赛者”结束本轮。不会因为退出重新延长救场期限。
- 断线、正常重启和完整保存点恢复都保留本轮退出身份。如果完整保存点早于已提交的退出／处罚决定，拒绝自动回退，保留最新身份进入恢复隔离。主动退赛者重连后仍可观战；处罚者回到大厅，需要管理员另行授权旁观。普通玩家不会获得 OP 或 `/tp`、`/gamemode` 权限。
- 原生死亡界面中的玩家可由管理员取消资格，服务端会安全替换其身体并回厅，生命序号不增加。玩家自己的主动退出入口在重生处理期间暂不可用。
- 已结算、庆祝、换轮、恢复隔离或已过期的救场阶段，不接受这类新的身份操作；已结算记录沿用历史核验／修订功能，不追溯改写原终局。

## 自动规则接口

未来程序应在服务端主线程调用 `P1LobbySession.requestParticipationExit(...)`，指定当前轮次、目标 UUID、预期角色、生命／出场序号、退出类型、来源标识和原因。自动处罚使用 `ParticipantRole.DISQUALIFIED` 与可辨识的来源（如 `system:anti-cheat`）。此 Java API 是受信任服务端接口，命令权限检查在命令适配器中完成。

接口对过期轮次／身份、并行状态提交和重复退出返回失败；调用方须检查回执，必要时重新读取当前状态后重试。不要通过执行原版 `/kill`、改游戏模式或直接改玩家存档替代资格操作。

角色名随现有快照编码保存；旧快照无需重写。新增状态、审计与物资封存都是当前构建的运行数据，续服时应使用理解这些身份的版本。
