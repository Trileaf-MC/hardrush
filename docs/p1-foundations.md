## 状态与提交

游戏线程生成 `RoundTransition`，携带变更前后不可变快照和捕获的单调事件时刻。写入待完成期间拒绝冲突动作，对外只展示已提交状态。SQLite 事务成功后，回到游戏线程核对会话、轮次和版本再应用；写锁、状态过期或 IO 失败进入恢复／失败状态，不宣布就绪、加入或配置成功。

SQLite 以 `BEGIN IMMEDIATE → COMMIT／ROLLBACK` 串行写入，迁移 DDL 与 `user_version` 同事务。事件摘要同时覆盖轮次、版本、快照和操作：相同 ID、相同内容可重放；相同 ID、不同内容直接拒绝。操作仅允许 `PREPARED → APPLIED → VERIFIED`，独立版本检查防止重复应用或跳阶段。

当前 schema 保存轮次完整快照、事件摘要、幂等操作和规则审计。参与者等数据包含在快照中；用于历史查询、进度与战斗详情的索引／表将在对应 P1 任务增加。`latest()` 按轮次创建顺序选择，旧轮次的迟到写入不会改变恢复目标。

读取快照和下轮规则时核对已提交事件的 SHA-256、轮次／版本及审计链接；摘要不符或所属记录缺失时停止恢复，不用默认规则或更旧轮次掩盖损坏。该校验用于检测不一致，未提供防管理员重写所有记录的签名机制。

数据库路径检查所有父级、数据库文件及 WAL／SHM／journal 文件，拒绝符号链接和非普通文件。该检查约束本模块的文件操作，不提供跨世界、玩家文件与数据库的原子事务。

## 计时和恢复

累计值保存纳秒，展示成绩时取整数毫秒；不以 tick/20 或 UTC 时间相减计算比赛成绩。只有 `RUNNING` 且至少一名在线 `HUMAN_ACTIVE` 时推进比赛时间，个人时长只推进该玩家在线活人区间。普通死亡保留本轮资格，生命序号校验拒绝上一条生命的迟到死亡／重生事件。

正常停服等待已经受理的 SQLite 写入，保存最后累计值和阶段剩余量，然后关闭连接。启动读取同一 ID、种子及配置，在线会话重新核对；启动边界先持久化为未正常关闭，再开放基础入口。停服时间不补进成绩或开局／庆祝倒计时。异常退出只保留最近已落盘数值，并显示 `RECOVERY_REQUIRED`／计时待核验；本批没有清除恢复故障的管理员捷径。

这些规则在假时钟和真实临时 SQLite 中验证。活动比赛的世界／档案恢复、各阶段服务器集成和故障重试仍由 P1-08～11 完成；不能把核心恢复测试算成 W04 全部通过。

## 26.3 入口

默认不启用 P1 实验基础。开发服务端可显式运行：

```bash
scripts/p0-gradle.sh :platforms:mc263:runServer -PhardrushP1=true --console=plain
```

独立 Fabric 服务端在 `-jar` 前加 JVM 参数 `-Dhardrush.p1.enabled=true`；Java 25 的 SQLite 原生加载可同时加 `--enable-native-access=ALL-UNNAMED`。数据库位于当前服务器存档的 `hardrush/p1.sqlite`，独立于单轮维度和 P0 世界清单；不更换、删除或轮换 P0 世界。

- `/hardrush status`：显示启用／打开／失败状态、轮次 ID、阶段、当前与下轮模式、持久化版本和规则指纹。
- `/hardrush join`、`ready`、`unready`：本批明确拒绝参与，提示世界准备与玩家档案适配尚未接通，不能绕过 `PREPARING`。
- `/hardrush config next-mode normal|hardcore`：OP 管理权限，后台持久化后才发送成功消息；只改下一轮模式。本批的同步命令返回值不承诺异步成功，完整管理命令与审计在 P1-16。
- 原 `/hardrushp0` 探针继续独立使用，其变身或世界传送不会被计为正式 P1 参赛或成绩。

P1 默认的原版战斗属性数值来自已记录的 26.3 基线。更换版本标签不认证另一版本数值或兼容性，必须由相应适配器验证。本批配置快照尚未用于热改现有 P0 角色服务。
