# HardRush 大厅布局与全流程无指令交互设计

日期：2026-10-16。状态：核心交互已确认，26.3 玩家主流程已接通，稳定化及候选包结果见[交接状态](lobby-delivery-status.md)；布局尺寸、材质、首次默认角色、模型分页和提示文案为本版设计默认，可在实现评审与人工体验后调整。

玩家通过进入集结区准备开局，通过右键活人皮肤模型直接发起个人追猎。取消追猎投票、每 15 秒共同目标结算和玩家手动选择维度。入服、参赛、死亡、怪物追猎、返厅、复生、救场、庆祝、查战绩与下一轮均提供无需输入指令的入口。

本设计与[产品需求](requirements.md)、[产品决策](decisions.md)共同定义后续实现目标。已有命令、投票菜单和历史测试证据描述原有实现，不代表本设计已经落地。人工验收项目见[大厅无指令交互与定向追猎](人工客户端测试/大厅无指令交互与定向追猎.md)。

26.3 实施按[五轮交付计划](lobby-delivery-plan.md)由独立会话串行执行，进展见[交接状态](lobby-delivery-status.md)，每轮可复制的完整提示词见[启动词索引](lobby-delivery-prompts/README.md)。另外两版正式适配另排。

## 已确认核心与本版设计约定

明确确认的核心是集结区站入准备、离开取消，以及右键活人皮肤模型直接追猎并取消投票和手动选维度。下列中途门、祭坛、展台、分页和提示等细节是围绕核心整理的设计默认；倒计时、资格、身份与庆祝规则沿用最新产品需求。

| 项目 | 目标行为 |
| --- | --- |
| 开局准备 | 主动站入集结区即准备，离开即取消，无需分别操作加入和就绪 |
| 开局倒计时 | 首位有效准备者触发 30 秒；全部准备者离区或断线后取消，再次集结重新从 30 秒开始 |
| 中途参赛 | 通过独立入场门确认加入正在进行的本轮 |
| 怪物追猎 | 右键目标玩家的皮肤模型，直接发起本人的追猎请求 |
| 维度处理 | 系统按目标当前所在的本轮维度搜索落点，玩家不选维度 |
| 目标失效 | 明确取消本次请求并留厅，不随机替换成其他玩家 |
| 复生 | 回厅后在祭坛主动确认消费资格，出场冷却不阻止复生 |
| 客户端 | 使用原版客户端与原版资产，不要求资源包、客户端模组或额外按键绑定 |

选择谁只决定本次出场锚点。出场后仍可攻击其他在赛人类，击杀与召唤物发放复生资格继续按实际致死归属判断。多人可同时选择同一目标，不增加追猎独占、怪物人数、聚集人数或出场时长限制。

本设计编写阶段不实现代码、不改存档和数据库、不部署制品；随后五轮实施的授权与结果见交接。后续上线应在新轮次启用新规则，不追改旧轮成绩或静默重写活动轮的规则快照。

## 大厅布局

### 功能位置

大厅是长期存在的独立出征营地。首版核心区域建议约 64 × 48 格，主通道宽 4～5 格，按约 20 名同时在线玩家布置。尺寸是布局起点，不是参赛或追猎人数上限。

~~~text
                          人类出征台
                   ┌────────────────┐
                   │     集结区     │    中途入场门
                   │   站入即准备   │   挑战与救场时开放
                   └───────┬────────┘
                           │
       战绩书屋 ────── 中央广场 ────── 怪物营地
       规则讲台        出生与回厅点      三种角色展位
       历史与榜单      本轮状态牌              │
       管理讲台                         追猎庭院
                                  活人人偶  活人人偶
                                  活人人偶  活人人偶
                                             │
                                         复生祭坛
~~~

图示表达位置关系，不按格数比例绘制。怪物营地不再设置三座维度出征门、选择维度踏台或投票告示板。

| 区域 | 布置与入口 |
| --- | --- |
| 中央广场 | 首次入服及普通回厅落点，面朝集结区；出生点与集结边界至少相隔 6 格，不落在任何触发区域内 |
| 集结区 | 建议直径约 14 格，用连续地毯或羊毛标出边界；内部保持空旷，入口旗帜注明站入参加、离开取消 |
| 中途入场门 | 位于集结区侧面，采用需要主动走入的前厅，不占用日常通道；确认界面显示轮次、模式和当前挑战时间 |
| 怪物回厅点 | 靠近角色展位，面向追猎庭院；不会落在集结区、复生触发点或人偶交互范围内 |
| 角色展位 | 僵尸、骷髅、苦力怕并列展示，右键选择角色并查看简要技能说明 |
| 追猎庭院 | 人偶面朝中央，采用两排或马蹄形展台；建议展台中心间隔至少 3 格，留出通行和选取空间 |
| 复生祭坛 | 靠近怪物区，侧置于主要行走路线之外；使用不死图腾元素表达用途 |
| 战绩书屋 | 规则讲台、轮次档案、榜单、领书入口；阅读位置不阻挡参赛与追猎动线 |
| 管理讲台 | 放在书屋侧后方，按实际 OP 权限显示管理项目；普通玩家无法执行管理动作 |

营地使用木材、石砖、旗帜与原版装饰。大厅继续全区保护，设施和展示模型不可被破坏、推动、攻击或取走装备。大厅建筑只作用于大厅，不在正式挑战世界增加出生平台、保护圈或人工通道。

### 普通模式与极限模式

两种模式共享中央广场、集结区、入场门与书屋。普通模式的怪物区展示介绍并标明“极限模式开放”，不授予怪物身份。切换下一轮模式后同步更新入口文案；设置下轮模式不改变当前轮规则。

## 入服与开局集结

### 入服落点与引导

首次入服和跨轮返回在中央广场落地。状态牌显示轮次、模式、阶段，以及当前可进行的操作。第一次接近集结入口时显示“站入集结区参加，离开取消准备”，不强制打开长篇说明。

仍在本轮存活的人类重连后，经档案核验恢复原位置和状态；普通死亡者按原版重生规则处理。已外出的怪物重连进入怪物营地，按既有规则处理再次出场冷却。它们都不能通过重新登录获得一次新的人类参赛机会。

### 集结区启停

世界就绪后开放集结区，每名玩家还需独立通过档案核验才能准备；单个玩家档案未就绪不阻止其他合格玩家集结。准备世界、结算、庆祝、轮换和恢复隔离期间关闭入口，并显示原因。集结区停用时，将其中的大厅玩家放到圈外等候点；下次开放需要主动重新进入，正常停服恢复已确认准备的例外见下节。

| 玩家行为或事件 | 系统行为 |
| --- | --- |
| 首位符合资格的大厅玩家入圈 | 将报名与准备作为一次玩家意图受理，成功后开始 30 秒倒计时 |
| 其他玩家入圈 | 加入当前倒计时，保留已有剩余时间 |
| 已准备玩家离圈 | 立即撤销其有效准备，显示“已取消准备” |
| 已准备玩家普通断线 | 视同离圈；重连落圈外，需要重新集结 |
| 有效准备人数归零 | 取消倒计时；下次从完整 30 秒开始 |
| 倒计时归零 | 自动接入仍在线、在圈内且身份与档案就绪的准备者；圈外玩家留厅 |

一人即可开局，不要求全服玩家到齐。显示“已准备 3 人”，不采用容易被理解为全员门槛的分母。最后一秒仍允许离圈取消，不追加一次点击确认或强制锁定阶段。

准备状态按玩家处于集结区域的有效位置判断。正常跳跃、转头、打开背包、读书或查看 TAB 不取消；边界处理要容忍轻微同步抖动，同时保证明确越界即取消。圈内不设置读书、领奖或其他停留入口。

成功准备时播放短音效与局部粒子，行动栏显示“已准备 · 18 秒后出发 · 离开集结区可取消”。请求尚未确认时显示“正在登记准备”，不能提前表现为已成功。玩家在登记期间离圈，迟到的结果也不能重新准备或把他送入挑战世界。快速进出和重复交互不能重复报名。

### 正常停服恢复

正常停服保存倒计时余量和原准备者身份。重启先显示“正在恢复上次集结”，原世界就绪且至少一名停服前已准备的 UUID 完成本人档案核验、上线并恢复圈内站位后，即可续计，不要求所有原准备者回齐；无关玩家上线不能替代原准备者放行倒计时。

完成核验后，恢复原准备者到安全的圈内位置，显示“恢复上次准备 · 剩余 X 秒 · 离区取消”，再继续保存的剩余时间。只有已上线、核验且在圈内的有效准备者参与本次开局。停服时长不扣倒计时，也不重新给满 30 秒。普通断线仍按离圈处理，与正常停服暂停区分。

若原集结区域被改动，无法安全恢复准备站位，则将受影响玩家放到圈外并明确提示取消准备；按剩余有效准备人数决定继续或取消。脏退出或身份不确定进入恢复隔离，不能套用正常恢复自动开局。

## 中途加入与普通重生

挑战或救场期间关闭开局集结功能，开放独立中途入场门。进入前厅后显示：

> 第 24 轮 · 极限模式
>
> 有效挑战时间 12:36
>
> 加入后空装进入主世界自然出生点，无出生保护。
>
> 操作：加入本轮／返回大厅。

只有本轮尚未参赛、身份与档案就绪的大厅玩家可以确认加入。极限死者会收到怪物庭院指引，有复生资格时同时指引祭坛；集结区与入场门都不能恢复死者的人类资格。存活人类重连恢复原档案，不走空装首次加入。

确认成功后才应用入场结果和参与记录；世界、阶段或档案改变时留厅说明原因。确认前关闭界面等同于放弃此次加入；已受理后显示“正在加入”，此时关闭界面不撤销已受理的转换，也不能重开后重复入场。不建立未受理的自动入场队列。

普通模式保留原版死亡画面和重生按钮，优先有效床或重生锚，失效时回本轮主世界自然出生点。普通死亡不进入怪物营地，不触发极限救场或团灭。

## 怪物选角与追猎庭院

### 回厅与选角

极限死亡先完成原版掉落，再转换怪物身份并进入怪物营地。首次成为怪物、被击败和成功主动返厅沿用 30 秒出场冷却。冷却和技能的跨重连、正常停服处理沿用本轮规则，本设计不重新定义计时方式。

右键角色展位选择僵尸、骷髅或苦力怕，展示技能说明和当前勾选状态。本轮保留上次所选角色；首次使用默认僵尸。角色选择成功后才更新显示。只有大厅怪物能更改角色，切换角色不重置技能或出场冷却。

### 活人模型与状态

每名本轮仍拥有人类参赛资格的玩家对应一个展台。在线、存活且当前允许追猎时，人偶显示本人皮肤、游戏名与“右键追猎”。原版皮肤不可用时使用默认皮肤并保留准确游戏名，不阻止选择合法目标。

| 玩家状态 | 展台表现与操作 |
| --- | --- |
| 在线且存活的人类 | 显示皮肤、名字和“右键追猎” |
| 已离线但仍存活的人类 | 保留模型和名字，标注“暂离，无法追猎”；不显示为已死亡 |
| 死亡处理完成 | 暂时显示“已死亡”，然后保留空展位；该位置不立即换成另一人 |
| 同一玩家复生 | 恢复其原展位，待人类身份与档案转换完成后才可追猎 |
| 大厅访客或本轮怪物 | 不列为活人追猎目标 |
| 轮次已经冻结或结束 | 停用全部追猎交互，显示阶段状态 |

展位按本轮 UUID 稳定绑定，不因其他人离线、死亡而把后一个模型移到原位置。首版庭院可预留约 20 个展示位；本轮累计存活人数包含离线者，超过展示容量时通过原版翻页牌查看后续模型。翻页只影响操作玩家自己的陈列，显示页码和总人数；模型映射更新期间暂不受理点击，防止一次点击选择到新换入的人。展示容量不限制参赛、追猎人数或已有离线资格。

模型只复制外观与受控状态，不同步真实装备、背包、血量、坐标、距离、方向或行动。名字和皮肤用于识别，服务端实际按展台绑定的 UUID 验证目标，重名或改名不会把追猎转给其他人。

### 右键直接追猎

完整动线为“回到怪物营地 → 选择角色 → 右键目标皮肤模型 → 搜索安全落点 → 出场”。没有投票步骤、维度菜单、共同目标结算或第二道出场门。

准星指向合法模型时，行动栏显示“目标：小明 · 当前角色：骷髅 · 右键追猎”。交互处理如下：

1. 冷却未结束时显示剩余时间，保持大厅，不登记自动出场。
2. 可出场时，右键直接受理以该人为锚点的本次请求，显示“正在寻找小明附近的安全落点”。
3. 系统读取目标当前所在的本轮维度和位置，完成有界搜索、身份提交及传送前复核。
4. 成功后应用怪物角色并出场；失败给出原因，保留出场机会。

冷却归零只给一次轻提示，仍需主动右键。一次只处理一个出场请求，连续点击同一人或快速点击不同人不能产生并行出场、重复传送或重复消耗。本人搜索反馈不会把其他怪物的目标改成同一人。

### 目标与安全落点变化

| 情况 | 处理 |
| --- | --- |
| 目标在本轮换维度 | 跟随同一目标身份，在当前维度重新校验和搜索，无需玩家手动选择 |
| 搜索时目标移动 | 传送前再次验证距离、位置和地形；条件不成立则继续在原预算内搜索或失败 |
| 目标死亡、离线、变怪物或生命已更换 | 本次请求失效，留厅说明原因；不改追其他人，也不追同 UUID 的下一条生命 |
| 无安全点或预算耗尽 | 留厅，保留出场机会；发起玩家等待 3 秒后可重试，换目标也不能绕过等待 |
| 出场后目标换维度 | 怪物留在当前世界，自行通过原版传送门行动；不再自动跟随传送 |
| 请求期间轮次结算或恢复隔离 | 取消出场，保持安全大厅，展示新阶段 |

安全落点继续要求距目标水平 32～64 格、距同维度所有在赛人类至少 24 格；避开虚空、岩浆、窒息、传送门、下界顶部、危险边缘与末地小型到达平台。使用现有已加载地形，不为追猎新造平台或强制生成落点区块。优先同片可到达地形。

每次请求最多搜索 2 秒或评估 64 个候选点；目标换维度与重新验证共享原预算，不能反复重置预算拖住服务器。传送前再次验证同一目标的生命、身份、维度与所有人类安全距离。安全条件失败的内部取消恢复本次出场机会；搜索失败后的 3 秒重试间隔按发起怪物 UUID 生效，期间换目标也不能重新搜索。世界、档案或存储出现真正故障则进入相应隔离，不以普通重试掩盖错误。

## 技能与主动返回

出场怪物通过原版快捷栏物品施放角色技能。技能物品提供名字、简短说明和剩余冷却，保持既有角色攻击操作与原版输入，不依赖额外按键。

快捷栏另设固定的归返物品，建议使用回响碎片。右键开始 5 秒引导，行动栏显示“正在返回营地 · 还需 X 秒”。移动、攻击、使用物品或技能、受伤均取消，并显示具体中断原因；已开始引爆的苦力怕不能借归返中断自爆。正常停服、断线或轮次改变取消未完成引导。

成功返厅后重新等待 30 秒，可重新选角或在有资格时直接复生。败退通过原生死亡与重生返回，不能清掉真实死亡、复制掉落或恢复成上一条生命。

技能与归返物品是受控操作入口，不可丢弃、转赠或变成生存物资，不能借它们自由换装、打开外部容器或绕过怪物能力限制。复生与跨轮转换移除这些入口物品，不占用人类正常生存背包。

## 复生与救场

### 主动消费资格

祭坛根据当前玩家资格显示“尚无复生资格 · 击杀在赛人类后获得”，或“已有复生资格 · 右键恢复人类”。获得资格只通知本人，不自动返厅、复生或改变已选择的角色。

右键祭坛打开简短确认：

> 消耗一份复生资格，空装恢复为人类。
>
> 返回本轮主世界自然出生点，无出生保护。保留本轮进度与战绩，旧掉落物不会自动找回。
>
> 操作：确认复生／继续作为怪物。

出场冷却期间也能确认。受理后显示“正在复生”，只在资格与身份提交、目标档案应用和安全传送完成后显示成功。重复点击或关闭界面不能重复消费；资格、阶段或出生安全条件改变时给出明确结果。失败与恢复按原有持久化转换处理，不根据空背包猜测资格状态。

### 无可追猎目标时

| 已处理完死亡批次后的状态 | 展示与入口 |
| --- | --- |
| 有在线存活人类 | 挑战继续，模型正常开放 |
| 只剩离线人类 | 显示“人类暂离，挑战计时暂停”，保留其模型及资格；不启动救场 |
| 无人类且有复生资格 | 启动 60 秒救场，突出祭坛及中途入场门；资格持有者可立即复生 |
| 无人类且无资格 | 团灭结算，停用追猎、入场与复生入口 |
| 救场到期仍无人类 | 团灭结算，剩余资格随本轮失效 |

资格可能由仍存活的召唤物在主人回厅或离线后获得。庭院模型更新不能取代死亡批次裁决：先认定致死和发放资格，再处理苦力怕回厅，最后判断人类与资格，避免短暂模型空缺错误触发团灭。

救场期间成功复生或新玩家加入后恢复挑战，倒计时取消。再次获得资格不延长本次截止时间。正常停服保存救场余量；到期与已受理复生的先后仍按既有服务端顺序仲裁。

## 战绩书屋与状态反馈

### 规则 历史与领书

规则讲台直接提供模式、集结、追猎、技能、复生和胜负规则。书屋通过原版界面提供“选择轮次 → 查看结果、参赛名单或榜单 → 领取主册或分卷”，轮次列表支持翻页，不要求输入 UUID 或命令。普通与极限成绩继续分榜，异常成绩保留核验标识，未结算轮不公开种子。

下一轮主册按既有规则自动发放，手动补领经书屋完成。背包满时保留待领并提示，不覆盖物品或把书丢在地上。已发出的书仍是历史快照，成绩修订后可领取新版。

### 提示分工

| 展示位置 | 内容 |
| --- | --- |
| 场景标识 | 设施用途、入口启停原因、当前可进行的动作 |
| 顶部状态条 | 当前阶段的主要倒计时，例如开局、救场、庆祝 |
| 行动栏 | 个人准备、模型瞄准、搜索、技能或返厅进度；接近设施提示不得覆盖正在执行的操作 |
| TAB | 轮次、模式、挑战时间、暂停原因、在线与离线人类、怪物、末地人数和结果 |
| 聊天记录 | 加入、死亡、获资格、复生、通关等关键事件；不承担必须输入指令的流程 |

确认、取消与失败采用不同短音效，重要状态同时提供文字。颜色和粒子作为辅助，不单独承担可用性或倒计时含义。个人选择反馈不更改共享设施的含义，旁人不会误以为自己也已准备或选中目标。

原版容器界面用于名单、历史分页和确认。大厅可以补充右键营地指南打开的状态总览，但总览不绕过集结区的位置约束，也不提供投票或手动维度选择。暂停菜单对话框可作为后续辅助入口评估，不能成为首版完成流程的前提。

## 庆祝与下一轮

采用 2026-10-16 最新庆祝规则：通关最多庆祝 180 秒，当前在线玩家全员完成回厅后可提前结束。

通关结果首次持久化时，在末地在线的人类和怪物进入固定庆祝名单，原物资先封存，自动穿戴临时不可损坏鞘翅并获得 16 色、每色 16 发烟花。怪物使用正常玩家身体庆祝，不继续追猎、召唤或赚取资格。其他维度玩家直接回独立大厅；后来首次上线者留大厅，不补领庆祝物资。

庆祝玩家跳入龙池出口即可直接回独立大厅，结束个人庆祝；不回旧轮主世界、床或重生锚。返回时移除临时物资并保存已返回状态，重连不回末地或重新发满物资。尚在庆祝的原名单玩家重连保留位置、烟花余量和阶段余量。

在线全员回厅或最多 180 秒到期后执行安全轮换，离线者不阻塞。仍有档案核验或返回未完成时不提前释放世界；录制保存和旧世界关闭成功后才开放下一轮。正常停服保留庆祝余量，不用停服墙钟扣时间。相关人工项目见[无指令交互清单的书屋庆祝与轮换章节](人工客户端测试/大厅无指令交互与定向追猎.md#书屋-庆祝与轮换)。

团灭回厅展示失败结果 30 秒再轮换；管理员中止即时回厅并显示原因。轮换和世界准备时关闭集结区，将玩家安置在圈外；下一轮世界与档案就绪后重新开放，所有玩家重新主动集结。原轮物资封存，下一轮空装，庆祝与控制物品不能泄漏到新轮。

## 异常与管理边界

| 状态 | 玩家反馈与行为 |
| --- | --- |
| 世界准备中 | 显示准备阶段，留厅，可读规则与已有历史 |
| 世界准备失败或磁盘不足 | 显示暂停原因及需要管理员处理，不开放半完成世界，不静默删除资料 |
| 玩家档案尚未就绪 | 显示个人核验状态，暂不允许准备、入场、追猎或复生 |
| 存储故障或恢复隔离 | 明确显示恢复状态，停止竞技身份转换；不能显示成普通等人开局 |
| 回放保存或世界释放失败 | 留厅等待处理，不用关闭界面、重新进圈或跨轮绕过保存门槛 |

只在身份和服务状态允许时开放规则与历史等只读功能；历史依赖不可用时说明暂不可查询，不伪造空记录。重核存储成功也不等于恢复比赛，当前无法继续的原活动轮仍按既有恢复处置执行。

玩家日常全链路必须无指令可达。房主日常管理可通过管理讲台提供按权限开放的状态、下轮模式、世界准备重试与中止等入口，中止时明确显示轮次、影响和原因并确认。该管理界面属于后续扩展，不作为玩家全链路验收前提；故障修复、成绩修订和归档删除继续遵守既有权限、确认及审计规则。

## 后续实现与验收约束

交互入口只表达玩家意图。集结位置、角色展位、人偶、容器和物品触发的请求，都必须重新验证当前玩家对象、轮次、身份、生命、出场序号、距离和服务状态。客户端物品名字、皮肤、展示文字与实体 ID 不能授予资格。人偶属于大厅展示，不计为参赛者、在线人类或末地人数，不影响团灭与救场判断。

定向追猎迁移时停用旧投票与手动维度入口，包括旧菜单、命令、定时结算和失效目标随机替换。历史快照字段如需保留，只用于兼容读取，不得重新启动投票。新规则如何写入快照与兼容旧轮次由后续实现评审确定，保留旧轮规则与历史证据。

Mannequin 人偶可作为首选展示候选。原版 Java 1.21.9 已提供可加载玩家 profile 的人偶实体，详见[Minecraft 官方说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-9)。26.1.2、26.2、26.3 的显示、皮肤加载、固定站位和右键处理需分别验证，不能用通用功能说明替代目标版本验收。皮肤资料应取原玩家资料，避免把怪物本人使用的 Steve 显示覆盖当成原皮肤。

后续自动验证重点包括集结进出竞态、正常停服恢复、定向目标及跨维度变化、同一生命校验、有界安全搜索、重复请求、资格消费与故障隔离。布局、皮肤、选取手感、物品操作和完整原版游玩由人类按[人工清单](人工客户端测试/大厅无指令交互与定向追猎.md)验收。旧投票与命令测试通过不代表上述能力通过，不因此勾选既有阶段门槛。
